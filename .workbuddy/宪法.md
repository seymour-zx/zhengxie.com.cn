1. **单一权威**：本目录内只保留一份权威文档（本宪法 + 后续每环节一份契约），决策编号从 **DEC-001 重新登记**，永不出现"两处说法不同"。

4. **提纯取代**：新世界的每一份内容（定位、数据、页面、构建、校验）都从旧项目**提炼精华**而来——先看旧世界有什么值得留，再决定搬什么、改什么、扔什么；最终新世界**完全取代**旧项目（旧项目退役冻结，不再修补）。
5. **旧项目冻结**：自 2026-08-29 起，对 `zhengxie.com.cn/` **不再做任何改进**；旧世界只作"素材库"读取，不作修改。

## 七、世界架构 · 公开分层模型（第一判据 = URL 可访问性）

> 依据：用户 2026-08-29 指正——判断公开与否，最基本的是**通过网址能否访问**，而非文件看起来像什么。旧世界"README 归说明层、.gitignore 归发现层"判据不自洽，新世界废弃该分法。

| 大层 | 判据 | 包含 | 层内细分 | 例子 |
|---|---|---|---|---|
| **公开层** | URL 可访问（Pages 发布） | 一切可从 `https://<域名>/` 访问的固定路径 | ① 人读内容（README.md、*.html）② 机器指令（robots.txt、sitemap.xml、ads.txt）③ 静态资产（css/js/图片/favicon/CNAME） | `README.md`、`index.html`、`robots.txt`、`style.css`、`logo.svg` |
| **隐藏层** | URL 返回 404（点文件） | 以 `.` 开头的文件 | 版本控制等 | `.gitignore` |
| **私有层** | URL 返回 404（点目录） | 治理/记忆/备份/构建 | 宪法、日志、backup、脚本 | `.workbuddy/` 全部 |

**铁律**：
1. 能通过 URL 访问 = 公开；**名字与位置固定、无法修改的路径（README.md、robots.txt、sitemap.xml、CNAME、ads.txt、favicon）永远只放公开内容**。
2. 内部治理（宪法/日志/备份/构建配方）一律进私有层 `.workbuddy/`（进 Git 跨设备同步，但 Pages 不发布点目录 → URL 404）。
3. 公开层内再细分（人读/机器/资产），层层控制信息防泄漏——**先分大层，再层内细分**，不跨层。
4. 将来上线时：README.md 直接使用公开占位版；若需调整，只改公开内容，绝不把内部内容写回 README.md。

## 十、世界坐标保护（防泄漏第一优先）

> 依据：用户 2026-08-29 —— 新世界取代旧世界后将发布 GitHub Pages，`.workbuddy/` 会在公开仓库中，但这**不是担心的暴露**（别人必须随机输入 URL 才能到达，属"偶然闯入"，可承受）；**要完全禁止的，是在 html、README.md 等公开文件中泄露 GitHub 用户名（世界坐标）**——坐标一旦出现在公开可达的网页，别人可从网址读到，然后在 GitHub 直接输入坐标精确到达。

### 10.1 暴露分级（按"到达方式"分级，而非内容敏感度）

| 级别 | 到达方式 | 处置 |
|---|---|---|
| **坐标泄露（完全禁止）** | 公开文件（URL 可访问）中出现 GitHub 用户名/仓库名 → 他人从网页读到坐标，在 GitHub 精确输入直达 | 公开层任何文件**一律不得出现**：`github.com/<用户名>/`、`git@github.com:`、`<用户名>@users.noreply.github.com`、`<用户名>.github.io/<仓库>` 等坐标形式 |
| 随机闯入（可承受） | `.workbuddy/` 等点目录在公开仓库中，需精确输入 URL 才能查看（Pages 不发布点目录，URL 404） | 允许，不设防；属"造物主随机输入坐标偶然来访" |
| 服务名提及（允许） | 公开文案提及托管服务名 | 允许写"GitHub Pages"作为服务名；**不得写仓库地址/推送地址/用户名** |

### 10.2 铁律

1. **公开层（§七）任何文件禁止出现世界坐标**：GitHub 用户名、仓库名、`github.com/<user>/<repo>`、`git@github.com:` 等。
2. "GitHub Pages" 仅作**服务名**可提及；部署教程一律用占位符（`<你的用户名>/<仓库名>`），不写真值。
3. **坐标扫描**：上线前与每次改公开层后，执行 `grep` 坐标模式扫描（`github\.com/[a-zA-Z0-9_-]+/`、`git@github\.com`、`users\.noreply`、`github\.io/`），**零命中才允许发布**。
4. 旧世界核验（2026-08-29）：公开层 github 字样均为服务名或收录站（引擎频道收录 github.com 搜索入口），**零坐标泄露**——新世界维持并制度化此标准。

### 10.3 世界坐标清单（仅私有层可记录）

- GitHub 用户名 / 仓库名 / 推送地址：仅存在于 `.workbuddy/` 私有层（如部署笔记），**永不写入公开层**。
- 若公开内容确需提及部署来源，一律用占位符或仅写域名（`zhengxie.com.cn`）。
