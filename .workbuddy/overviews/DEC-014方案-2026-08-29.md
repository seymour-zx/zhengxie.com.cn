## A. sitemap lastmod 自动生成

### 现状（2026-08-29 实测）

- `sitemap.xml`：**手写** 13 URL，含 `changefreq`/`priority`，**零 `lastmod`**，缩进不统一。
- 每次新增页面靠手工补录（旧 CONVENTIONS §5.5 要求"手动补 sitemap"，但从未自动化）。
- SEO 缺陷：搜索引擎无法判断页面更新时间，抓取优先级低。

### 方案 A1（推荐）：新建 `assets/.build/gen_sitemap.py`

| 项 | 设计 |
|---|---|
| 输入 | 仓库根全部 html（复用 verify_site.py 的页面发现逻辑） |
| 机制 | 每页内容 sha256 → 缓存 `.sitemap_lastmod.json`（页面→{hash, lastmod}）→ hash 变化才刷新 lastmod=当天 → 写回缓存 |
| 产出 | `sitemap.xml`：13 URL + `<lastmod>`（W3C 格式 `YYYY-MM-DD`）+ 保留现有 changefreq/priority 映射 |
| 接入 | `build.py` 步骤表追加第 3 步 `gen_sitemap.py`（失败即中断） |
| 幂等 | 内容不变 → hash 不变 → lastmod 不变（不会每天戳新） |
| 产物 | sitemap.xml 进 Git（方案甲，随仓库同步） |

**影响面**：新脚本 1 个 + `build.py` 加 1 步 + sitemap.xml 被替换（格式规范化，URL 集合不变）。
**验证**：生成后 XML 可解析、13 URL 齐全、lastmod 格式合规；`verify_site.py` 不受影响。

### 备选

- **A2**：不改脚本，仅手工为现有 13 URL 补静态 lastmod。成本最低，但每次改页仍要手工维护——回到老问题。
- **A3**：不做。维持零 lastmod（现状，SEO 短板保留）。

## B. GA4 / AdSense 去留

### 现状（2026-08-29 实测）

- 统计脚本分布在 **5 个文件**：`index.html`、`404.html`、`directory/engine/`、`directory/gov/`、`pages/overview/`。
- 组成：GA4（`G-B880S4NQVK`）+ AdSense + 百度统计×2（com.cn 主站 + 备用各一份）。
- 已知问题（旧 13-SEO审计 P0）：**GA4/AdSense 为境外服务，被 GFW 屏蔽**——国内访客加载时脚本请求超时/被拒，拖慢首屏；且 GA 面板收不到国内流量，数据价值≈0。

### 方案 B1（推荐）：删除 GA4 + AdSense，仅留百度统计

| 项 | 内容 |
|---|---|
| 动作 | 5 个 html 的 head 删除 `gtag`（GA4）与 `adsbygoogle`（AdSense）代码段，**保留百度统计** |
| 执行路径 | 手写页（404、overview）直接改；build 产物页（index、engine、gov）改 `build_homeplus.py` 模板后重跑 build |
| 收益 | 国内首屏去掉被墙脚本阻塞；统计口径单一真实（百度统计） |
| 代价 | GA/AdSense 数据归零（GA 本收不到国内数据，实际损失≈0；**AdSense 若有真实展示收益需你确认**，有收益则此方案不适用） |
| 验证 | `verify_site.py` 全绿 + grep 确认 `gtag`/`adsbygoogle` 零残留 + 百度统计代码保留 |

### 备选

- **B2**：全部保留（现状，首屏继续被墙脚本拖累）。
- **B3**：只删 GA4 留 AdSense（半吊子——AdSense 同样被墙，删不删无差别，不推荐）。
