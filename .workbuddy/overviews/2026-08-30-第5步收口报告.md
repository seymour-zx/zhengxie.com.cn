## 一、分层校验 L1-L5

| 层 | 内容 | 时机 |
|---|---|---|
| L1 静态 | verify_site 八项 → xlsx 报告 | 每次部署前 |
| L2 构建 | build.py 失败即中断 | 每次改数据 |
| L3 死链 | check_links | 收录前后 + 每月全量 |
| L4 手工 | 上线清单 12 项（功能/视觉/无障碍/禁用 JS 降级/三端实测） | 每次部署前 |
| L5 监控 | 统计后台 + 反馈收集 | 持续 |

## 二、展示方案

1. 控制台一句话摘要：`页面 N | 问题 X | 🔴红线 A | 🟡严重 B | ⚪一般 C` + 红线明细
2. xlsx 分级别 sheet：汇总 / 红线(红底) / 严重(黄底) / 一般(灰底)
3. 每行：页面/检查项/级别/问题/建议/造物主决定（下拉：上线/修复/豁免）

## 三、闭环机制（xlsx = 报告 + 决策单一体）

- 造物主标 xlsx → 下次 verify_site.py 读决定列：豁免→标"已豁免(日期)"、修复→未修继续提示、上线→确认
- agent 部署前读决定列：修复项先修、未标记提醒、全部放行才部署

## 四、门槛分级

🔴 红线（断链/noopener/构建失败/禁用 JS 失效）→ 建议修复，最终造物主拍板
🟡 严重 → 登记限期修复；⚪ 一般 → 带病上线进整改
豁免机制：登记原因+期限 → 留痕季度复核

## 五、上线流程

改 xlsx → build（L2）→ verify xlsx 报告（L1）→ 造物主逐条标决定 → 死链抽查（L3）→ 手工清单（L4 含三端实测）→ 造物主 git 推送 → 复测
