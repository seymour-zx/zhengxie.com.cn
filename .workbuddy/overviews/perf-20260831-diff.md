## 三、P0 —— 首屏卡死与输入卡顿（主战场）

### P0-1 预计算全量化 → 惰性按需测量
- **根因**：`precomputeLines`/`precomputeTitleLines` 在初始化时逐卡写 3 个内联样式→读 `scrollHeight`→写回，写读交替迫使浏览器对 1000+ 节点文档**同步重排 674 次**才允许交互。
- **改动**：删除这两个函数；改为点击展开时**只测被点那一行 3~4 张卡**（`toggleDescExpand`/`toggleTitleExpand` 调 `measureRow`），并用 `getDesc/getTitle` 缓存结果避免重复 `querySelector`。
- **效果**：初始化强制重排从 674 次 → **0 次**。

### P0-2 `refreshScrollable` 全量 → 视口感知增量
- **根因**：原 `refreshScrollable` 遍历 678 个元素读 `clientWidth`/`scrollWidth`，被 `applyFilter`、`renderTags`、`load`、`resize` 四处调用 → 每敲一字/每点一星都全量跑。
- **改动**：拆为 `refreshScrollableFor(list)`（严格「先批量写后批量读」）+ `queueRowCheck`：视口内立即测，视口外交 `IntersectionObserver`（`rootMargin:300px`）进入时补测，标记常驻。**整页滚动并集 328 == 优化前 328，零漏测。**
- **效果**：交互期几何读取从 1356 次/次 → 仅当前显隐变化的卡。

### P0-3 `highlightCard` 无脑重写 → 脏检查
- **根因**：每次按键对 674 张卡的 title+desc 执行 `el.innerHTML = ...`，销毁重建 DOM 子树；且切换分类/收藏时关键词未变也照样全量重写。
- **改动**：加关键词签名（`__hlSig`）脏检查——关键词未变则跳过；变化才重写该卡。
- **效果**：无谓 DOM 子树重建消除。

### P0-4 `applyFilter` 写读交替 → 四阶段批处理
- **根因**：原实现逐卡 `card.hidden = ...` 后立刻调 `refreshScrollable` 读几何，又是写读交替。
- **改动**：重写为 ① 预计算静态可搜索文本（消除每次 337 次 `querySelector`+`toLowerCase`）② `aliasSet` 结果缓存 ③ 批量写 `hidden` → ④ 末段统一 `queueRowCheck`。同步 `__shown` 状态供随机漫步复用。

## 四、P1 —— 滚动掉帧与监听器膨胀

### P1-1 `wheel` 全量 `closest` → pointerover 缓存
- **根因**：document 级 `wheel` 用 `{passive:false}`，每次滚动都 `e.target.closest(SCROLL_ROW_SEL)`，浏览器无法把滚动交给合成线程。
- **改动**：滚轮目标用 `pointerover` 预缓存 `hoverRow`，移动端零成本；仍保留边界交还页面逻辑（横向到头交还竖向滚动）。

### P1-2 3386 个逐元素监听器 → 事件委托
- **根因**：`touchstart`/`touchend`/`touchcancel`/`pointerdown`/`keydown` 实际还是逐元素挂（约 3386 个），常驻内存且初始化耗时。
- **改动**：全部改为 `document` 级事件委托（按 `data-*`/class 分发），监听器从 **~3386 → ~10**。键盘可达性（Enter/Space 展开）改委托后覆盖所有卡片。

### P1-3 `transition: all` → 明确属性名
- **根因**：9 处 `transition: all` 订阅所有属性（含布局属性），批量交互时额外样式计算。
- **改动**：收敛为 `transform, box-shadow, border-color, background, color` 等具体属性。

### P1-4 `.card:hover` 无脑生效 → `@media (hover:hover)`
- **根因**：移动端触摸后 hover 态**粘住**，337 张卡同时挂 `transform:translateY(-3px)`+大阴影。
- **改动**：`.card:hover`/`.card__fav:hover` 包进 `@media (hover: hover) and (pointer: fine)`，触屏不再触发。

## 五、CSS 纯收益项（你问的重点）

| 项 | before | after |
|---|---|---|
| `backdrop-filter: blur(6px)`（吸顶栏） | 每帧全宽模糊重算 | 去掉，改 `var(--bg)` 不透明 |
| `content-visibility` | 0 处 | `.card` 启用 `auto` + `contain-intrinsic-size: auto 300px` |
| `transition: all` | 9 处 | 0 处 |
| `.card:hover` 触屏粘滞 | 触发 | `@media (hover:hover)` 限定 |

> `content-visibility:auto` 是最大白送：视口外卡片跳过样式计算/布局/绘制，337 张中可能只渲染首屏十余张。

## 七、风险与未做项
1. **万张卡片**：`content-visibility` 可撑到数千张；真正万张需虚拟滚动/分页（架构级改动），建议用本次实测数据再决定是否上。
2. **滚动条轻微跳动**：`contain-intrinsic-size:auto 300px` 下，视口外卡片用 300px 预留高度，真实高度回灌时滚动条长度可能轻微抖动（可观测，不影响功能）。
3. **公开层坐标**：本次改动未触及任何 URL/用户名，`qa` 前后公开层一致，上线前照常跑坐标扫描即可。
