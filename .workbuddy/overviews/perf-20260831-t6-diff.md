## 一、用户三个痛点的真因（不是"卡太多"，是手势被抢走）

| 现象 | 真因 | 原代码 |
|---|---|---|
| 左右滑道**时好时坏** | `touch-action: pan-x pan-y` 让浏览器对纯横向滑道"横竖归属模糊"，有时把横滑判给页面、有时给滑道 | `style.css:972` |
| 左滑到尽头**往上滑**、右滑到尽头**往下滑** | 全文件零 `overscroll-behavior`，到边界后手势"链"到页面纵向滚动 | 全局缺失 |
| 一卡就**左滑切回小米桌面**、用户退站 | 横向 overscroll 链到 **MIUI 系统导航手势**（左滑返回/回桌面） | 全局缺失 |

> 关于"JS 渲染是不是该排序、少分类就不卡"：**不成立**。卡顿与卡的数量/渲染顺序无关，是上面两条 CSS 缺失让浏览器和 MIUI 抢手势。把手势归属和边界链断修对，几千条滑道都不会再卡。排序/减分类是白费力。

## 二、改动 1 — 修正 T6 块（核心，原 969–973 行）

**Before**
```css
/* T6 修复：滑道/卡片行允许横向触摸滚动，减少 JS 干预 */
.track, .filter-tags__track,
.card__tags, .card__links, .card__title, .card__desc {
  touch-action: pan-x pan-y;   /* ❌ 纯横向滑道不该声明 pan-y */
}
```

**After**
```css
/* T6 修复（2026-08-31 v2）：横向滑道只声明 pan-x，让浏览器独占横手势，
   竖手势自动留给页面 → 解决「左右滑时好时坏」。
   overscroll-behavior: contain 阻止到边界时把手势链到页面/系统导航
   （小米左滑回桌面、到尽头往上滑的根因）。
   标题/描述区是「点按展开」非滑道，不在此列，保留纵向滚页面手势。 */
.track, .filter-tags__track,
.card__tags, .card__links, .card__sources {
  touch-action: pan-x;
  overscroll-behavior: contain;
}
/* T6 修复（2026-08-31）：禁用整页橡皮筋回弹，杜绝 MIUI 把页面 overscroll
   钩成「左滑回桌面」系统手势，避免用户被甩出站点。本产品无下拉刷新，无副作用。 */
html, body { overscroll-behavior: none; }
```

## 三、改动 2 — 补 `.card__sources` 缺失的溢出规则（原 121–122 行）

`.card__sources` 在 JS 选择器里是滑道，但 CSS 漏了 `overflow-x:auto`，当前根本滚不了。

**Before**
```css
.track,
.card__title, .card__desc, .card__tags, .card__links {
  overflow-x: auto;
```
**After**
```css
.track,
.card__title, .card__desc, .card__tags, .card__links, .card__sources {
  overflow-x: auto;
```

> 标题/描述（`.card__title`/`.card__desc`）保留在 `overflow-x:auto` 组（点按展开用，内容被 line-clamp 截断，无害），但**移出了** `touch-action: pan-x` 组——它们不是滑道，必须保留纵向滚页面的手势。

## 四、JS 未改动的理由

既有触摸逻辑（`touchstart/touchend/touchcancel` 事件委托，仅加 `is-touch-active` 金色高亮）全部 `passive: true`、**不 `preventDefault`**；唯一 `preventDefault` 在 `wheel`（桌面滚轮映射，与触摸无关）。原生滚动得以完整保留——正好印证 T6 技术债预期的"简化 preventDefault + touch-action: pan-x"。

## 五、验证结果

| 检查项 | 结果 |
|---|---|
| `qa-scroll-check.js` 回归闸门（改 CSS 也跑） | ✅ 退出码 0（场景 A 现代 / B 老内核降级均过） |
| track `touch-action` | ✅ `pan-x` |
| track `overscroll-behavior` | ✅ `contain` |
| `html,body` `overscroll-behavior` | ✅ `none` / `none` |
| 标题 `touch-action` | ✅ `auto`（保留纵向滚页面） |
| 边界链页面（滚到左端仍左滑） | ✅ 页面 `scrollY` 0→0，手势锁在滑道内 |
| 容器可滚性探针（程序化设 `scrollLeft=80`） | ✅ 读回 80，滑道是合法横向滚动容器 |
| 合成触摸横滑 `scrollLeft` | ⚠ headless 合成触摸**无法驱动原生滚**（环境限制，**非代码问题**）|

> 说明：headless 浏览器里 `Input.dispatchTouchEvent` 不能可靠触发合成器滚动手势，故"横滑是否改变 scrollLeft"在自动化里恒为 0——这是测试桩限制，不代表真机失效。计算样式 + 容器探针 + 边界不链页面三项已确定性证明修复到位。**真机横滑手感请你拿小米浏览器最终验收**（你已认领）。

## 六、风险与备注

- `overscroll-behavior: none` 会禁用整页橡皮筋回弹手感；本产品无下拉刷新，无功能影响。若你日后想要页面回弹弹性，可只改用 `contain`（滑道级仍保 `contain`）。
