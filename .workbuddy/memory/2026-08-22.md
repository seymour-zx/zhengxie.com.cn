## 正协导航 — 第十七轮：media 列支持图片底色 + 纯色/字符占位

用户痛点：收藏站点的矢量图(透明 PNG/SVG)无底色，直接铺在红容器上看不清/不搭；且无图时只有首字符占位不够灵活。
方案（用户拍板）：media 列用**英文逗号**分隔（用户指出空格易误填肉眼难发现），支持：
- `URL` → 纯图(旧行为)
- `URL,颜色` → 图+底色衬底(给矢量图衬底,不改容器红底)
- `颜色值`(#rgb/rgb()/rgba()/hsl()/transparent) → 纯色块占位(无图模式,任何 CSS 合法色)
- `字符,颜色` → 文字占位+自定义底色
- 空/其它 → 首字符+红渐变底(兜底)
关键实现点：先按第一个逗号 partition 再判 is_url（避免 `url,color` 被 urlparse 误判整串 URL）；颜色正则 `_COLOR_RE` 匹配 #/rgb/hsl/transparent；颜色值内逗号保留在 tail 不受影响。
改动文件：build.py(build_media 重写+_COLOR_RE+is_color helper+顶部 media 文档)、style.css(.card__media--color 去红底渐变回退)、README 数据表 media 行更新。
校验：build_media 单元测 10 例全过(含 url,color / 纯色 / 字符,色 / rgba 带逗号 / 短hex#fff)；完整 build 成功；现有 xlsx 62 纯URL+66 空,无新语法,向后兼容。
结论：media 列语法已升级,换设备编辑 xlsx 时照 README 数据表 media 行写即可。

## 正协导航 — 第十九轮：media 颜色非法语句稳健降级修复

用户问"所有情况下颜色语句非法怎么处理"。实测发现 build_media 有3个bug：① `url,非法色` 丢图变文字兜底；② `合法色,尾巴`(#FFF,多余) 走文字兜底而非纯色块；③ `rgb(1,2)`等参数非法被正则放行进 style。
按用户同意的降级原则修复：
- is_color 强化：加 _is_valid_rgblike/_is_valid_hsllike 参数范围校验 + _NAMED_COLORS 颜色名兜底(red/green等)；非法参数(rgb(1,2)/rgba(...,5)/hsl(1,2))判为非法。
- build_media 判定顺序改为：纯URL→URL+合法色(图+底)→URL+任何tail(退化为纯图,不丢图)→head合法色(纯色块,忽略尾巴)→字符+合法色(文字)→兜底首字符+红底。
- 验证14组用例全符合：url+非法色=纯图、#FFF多余=纯色块、rgb(1,2)=文字兜底、red=纯色块。
- 同步更新 README media 行补"降级原则"说明。
结论：media 列任何脏数据都安全降级，不崩站不丢图不进无效 style。
