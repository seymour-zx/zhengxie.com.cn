## 造物主意志全录（00:00，C-1 定位根本澄清——旧世界被弃根因）

3. **卡片本质（陈列馆/百科索引）**：每张卡片 = 一个词条（政协/机构/人名/书名/电影/学校……无任何限制）。**卡片不一定有链接**——XX 政协网站已停维护/合并，卡片也必须存在；"我知道有 XX 政协，但没挂网址，因为它的网址不存在或我还没找到"——这个信息本身就要展示给用户（用户能理解，网络发展必然淘汰低流量网站）。旧世界 agent 反复要求"删无链接卡片" = 没理解产品本质。

## Bug 记录（04:28，造物主实测反馈）——小米浏览器滑动卡死

**现象**：小米手机自带浏览器访问时，**标签行和链接行的滑动有时会卡死**；微信内置浏览器、谷歌浏览器操作正常。

**影响**：旧世界 main.js「统一滑动行为」（滑道/卡片行内容溢出时接管滚轮为左右滑，触屏触摸同样激活）在 MIUI 浏览器有兼容 bug；**新世界继承 main.js（D-09）→ 必须在新世界构建时修复，否则带病上线**

**可能原因（供第 4 步修复参考）**：
1. JS `touchmove` + `preventDefault` 与 MIUI 浏览器横向手势（边缘返回等）冲突 → 死锁
2. 滚动事件反复触发 + preventDefault 状态锁死
3. `overflow-x:auto` 容器缺 `touch-action` CSS（如 `touch-action: pan-x`）→ 浏览器默认手势与 JS 冲突
4. MIUI 浏览器内核（老 Chromium 定制）兼容差异；触屏时 wheel 事件行为异常

**修复方向（第 4 步构建时落地）**：
- CSS `touch-action: pan-x` 声明，减少 JS 干预
- 简化 JS 接管：原生 scrollLeft 平滑滚动，避免过度 preventDefault；加异常兜底（超时释放）
- 实测覆盖：小米浏览器 + 微信 + Chrome 三端验证

**已登记技术债 T6**（overviews 汇总文档）
