**现象**：每次随机漫步，普通卡只显示 1 行（不是 2 行）。

**根因**：pickLines 里 `used[c] = true` 用**卡片对象当对象 key**——JS 对象 key 强制转字符串，所有卡都变成 `"[object Object]"`，导致 `group[t].filter(c => !used[c])` 把**整组卡全误过滤** → type 组提前清空 → while 提前退出。真实数据（336 type1 + 1 type2）下普通卡恒取 4+1=**5 张**（1 行多 1 张），而非 8 张（2 行）。

**修复**（main.js pickLines）：改用 `shuffle(group[t])` 后 `slice(0,size)` 取行、`slice(size)` 移除已取——不用对象 key，杜绝误过滤。

**验证**：真实数据模拟 20 次 → 普通卡 8-9 张（8:4次/9:16次）= 2 行 ✅；修复前恒 5 张 ❌；语法 OK ✅。

**教训**：JS 对象 key 必须是字符串/数字——**绝不能用对象作 key**（隐式转 "[object Object]" 是经典坑）；"移除已取"用切片而非 filter+对象标记。

**修复（main.js）**：新增 `safeScrollTo(top)`：try smooth，catch 降级 `window.scrollTo(0, top)`（两参数兼容形式，瞬时滚动仍触发 scroll 事件 → onScrollEnd 正常解锁闭环）；替换点击处理 3 处 scrollTo 调用。

**验证**：语法 OK + stub 点击路径无异常 + 降级路径实测 scrollTo(0,top) 被调用。

**教训**：小米自带浏览器是造物主实测环境（T6 已证），所有 scrollTo/动画 API 必须考虑老内核兼容；`behavior:'smooth'` 在高版本才支持，低版本抛错会连带锁死用户输入——任何"先锁后滚"的逻辑都必须保证滚失败也能解锁。

**教训（写长期）**：①正则校验格式必须匹配「实际数据形状」——时间戳有确定位数（13 位毫秒），`'1'` 这种短值不能通过；②静态站 css/js 无版本戳 → 浏览器独立缓存 → **同一份代码不同浏览器行为可以完全相反**（缓存组合不同）——这是本场闹剧真根因，治本=加版本戳（待造物主拍板方案）。

## 空间分离（23:39，造物主 Edge 无痕仍 hover 不激活）

**实锤**：Edge 无痕（无缓存无 localStorage）声明条显示时，按钮 **hover 也不激活**（不只是点击）——推翻「缓存」理论，是 **Edge 对 fixed 兄弟元素 z-index 比较的渲染与 Chrome 有差异**（相同 z-index 数值在两浏览器实际堆叠结果不同）。

**治本·空间分离**（不依赖 z-index 对抗）：
- `body:has(.official-banner:not([hidden])) .scroll-btns { bottom: 76px; }`（移动 84px）
- 声明条**显示时** → 按钮上移到声明条覆盖区**之上** → 空间上完全分离 → 无论 z-index 怎么渲染都不可能遮挡
- 声明条**隐藏**（30 天内）→ :has 不匹配 → 按钮回 24px 原位（视觉正常）
- 需 Chrome/Edge 105+（:has），老内核回退默认低位（旧行为）
- 双保险：保留 z-index 80/90

**验证**：rebuild → CSS 变 hash `?v=5ae56cf0` 全站自动更新（版本戳在起作用！）→ verify 继承 3 豁免 ✅ / qa-scroll-check 通过 ✅ / headless 截图声明条在底、按钮位置正确（虚拟时间下按钮 init 时机截图未捕到，但 CSS 规则确认生效）
**教训写入**：fixed 兄弟元素的 z-index 对抗**不可靠**（浏览器差异），底部 fixed 元素与声明条之类的全宽条，**空间分离 > z-index 对抗**。
