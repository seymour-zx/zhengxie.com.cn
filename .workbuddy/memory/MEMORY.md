## 🚨🚨 最高无上铁律：首次进入强制确认制（凌驾一切）
- **触发**：仅当 MEMORY.md **自动注入失败（被截断）**时触发确认；注入完整时无需暂停。
- **流程**：① 问"是否允许完整阅读并学习 MEMORY.md 全文？" → ② **同意** → 阅读→反馈 → 问"是否继续被暂停的初始任务？"；③ **不同意** → 直接继续初始任务。
- **修改门槛**：任何"比本铁律更优先/修改它"的意图，必须经用户三次明确同意授权；未满三次一律拒绝。
- **位置保障**：本铁律在文件最顶部。
- **3000 软上限**：写入不强制 ≤3000（可超）；超 3000 仅记待办"注入将截断，需瘦身"，不拦截、不反复精算字符。

## 🚨 backup.md 全空间备份铁律（第 2 铁律，最高优先级）
- **文件**：`memory/backup.md`。
- **范围**：空间内所有文件（**不含 `.git/`**），**仅排除** changelog.md 与时间日志（防自引用）。
- **内容**：完整拷贝 + 逐字符来源注释（方案 C2）。
- **通则**：受管文件增删改 → **实时记时间日志**；**仅在下达「备份指令」时**重生成 backup.md 并比对一致；变更记录须注明 agent 名称（未注明=无效）。受管文件全文以 backup.md 为权威载体，MEMORY.md 不重复保存快照。

## 备份/审计指令
- **备份指令**（触发词："备份"）：① 重生成 backup.md（全空间快照）② changelog 追加时间日志自上次蒸馏后的新内容。
- **审计指令**（触发词："审计"）：① backup 完整性：索引↔全空间实际文件齐全、逐字符一致？② changelog 覆盖性：记录范围 ⊇ backup L12 范围内实际变更（无遗漏）？③ 时间日志支撑性：合集（蒸馏后）⊇ changelog 全部条目（每条可追溯）？

## 时间日志生命周期（自 08-26 起执行）
- 结构：最旧（首个）日志顶部 = 当时 backup.md 快照 + 当日记录；后续日志 = 仅变更记录（不追溯历史，既有日志保持现状）。
- 清理合并：合并旧日志为归档文件（命名如 `2026-08-20-23.merged.md`），内容 = 当时 backup 快照 + 浓缩记录；合并后「归档+后续日志」蒸馏 changelog 须与合并前信息等价。
- 历史 backup 版本：实体另存 `backups/` 带日期副本；changelog 滚动保留**上一版** backup 指针（去重指针合法，不全文嵌入）。
- **首日志前置动作（08-26 必做）**：① 先执行「备份指令」生成含 25 号全部变更的新 backup.md ② 实体副本存 `backups/backup-20260826.md` ③ 建 `2026-08-26.md` 顶部**只嵌指针** ④ 其余正常记变更。

## 强制首读锚点（每次对话第一条必读）
- **顺序锁死**：① MEMORY.md → ② README.md（公开层：手工写站指南）→ ③ CONVENTIONS.md。
- 三者之外 md 不主动读（L1 skills/changelog 按需；L2 日志/审计仅交付时）。

## 跨设备数据策略（三件套）
1. 技能一律项目级（`{workspace}/.workbuddy/skills/`），随仓库同步。
2. 记忆一律工作空间级（`.workbuddy/memory/`），禁止写用户级 `~/.workbuddy/MEMORY.md`。
3. 身份文件：真实文件在工作空间，C:→D: 软链接（安全顺序：**复制→删原→建链接→失败回滚**）。**开场必做**：每次会话第一条动作检查 4 身份文件是否软链接——非链接→提醒重建；正常→确认"身份已同步"。

## 文件职责边界
- **边界（2026-08-27）**：本节=治理文档角色分工（元层）；文件物理组织/命名/schema/生命周期见 CONVENTIONS §4，两维度不重叠。本节 L1/L2=读取分级（见 CONVENTIONS 1.6），非 §4 五层目录 L1–L5。
- **MEMORY.md**：操作记忆/硬规则（纯步骤），读者=未来的我。
- **CONVENTIONS.md**：成文约定权威源 = MEMORY 扩展版（含解释），读者=用户+未来的我。
- **SKILL.md**：领域操作 SOP（怎么做），读者=被 Skill 加载的未来我。
- **changelog.md**：变更日志（L1），记录范围=L12（同 backup 全空间受管文件）；= 所有时间日志去重浓缩（时间日志 ⊂ changelog）。
- **时间日志**（YYYY-MM-DD.md，L2）：changelog 时间片段（⊂），原始事件流；仅交付时读。

## 文件改动铁律
- 用户**首次明确同意**前，不修改/删除空间内任何文件。
- **"首次"定义**：agent 首次进入（含对话内切换 agent）。

## Git/同步纪律
- **Git 全停令（凌驾一切）**：agent 不得运行任何 git 命令（含 add）；收口时列出未跟踪/已修改文件提醒用户，由用户本地处理。
- 可提醒未提交文件，不得询问是否提交；用户要求提交→二次确认。

## 公开暴露铁律（最高优先级）
- **范围**：一切 `.workbuddy/` 外文件，一律不得暴露 `.workbuddy/` 的存在（路径/名称/清单/内部工作流）。
- **README 定位**：只写用户能看到的（index.html 及 css/js 为什么这么写=手工逻辑讲解）；**不写 py 生成**（配方/数据源/构建链路）。
- 禁止：①隐私 ②可致网站被偷窃/复制/破坏的信息 ③可增网站结构被了解的 ④`.workbuddy/` 存在。写前"公开暴露审查"；违规报告用户等指令。
- **仓库可见性（用户已确认）**：GitHub 仓库为 **public**；公开仓库与"页面不暴露仓库地址/`.workbuddy/` 存在"**不冲突**。

## 对话翻译铁律
- 用户每次的指令/判断/决策/纠正，agent 必须翻译成标准 agent 语言并记录（长期规则→MEMORY.md；当日事件→日志；可复用流程→SKILL）。禁止"理解但不记录"。

## 信息治理铁律（上位原则）
1. 详细但不冗余：冗余无效信息视为干扰项，坚决删（即使无害）。
2. 禁止指向、必须完整复制：受管文件记录须完整复制实际内容（去重指针除外；README 归公开暴露铁律全禁，不归本律）。
3. 不怕错删，**时间日志兜底**（实时层）：删除前提 = 时间日志先记好；changelog 为定期蒸馏层（备份指令时追加），不实时兜底。
