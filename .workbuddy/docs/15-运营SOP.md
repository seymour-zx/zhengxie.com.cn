| 角色 | 职责 | 对应 WorkBuddy 专家 |

| **运营决策（用户本人）** | 拍板方向、审内容、做最终发布决定 | — |

## 2. 指标定义（唯一口径）

> ⚠️ **纪律**：无 30 天有效分母前，不基于下述指标拍板任何方向性决策（CONVENTIONS 圆桌 #26）。

| 指标 | 定义 | 数据源 | 现状 |
|---|---|---|---|
| **成功找站**（北极星） | 点击卡片外链后**未立刻返回**（停留 > 10 s 或无 pvs 回退） | C7 打点 + 百度统计 | 无（C7 未建） |
| **扑空率 zero_result** | 站内搜索结果为 0 的 query 数 / 总 query 数 | C7 打点 | 无 |
| **收藏率 save-rate** | 发生收藏行为的会话 / 总会话 | C7 打点 + localStorage | 无 |
| **复访找站率 re-find** | 同一访客多次访问并点击外链的比例 | 百度统计 | 无 |
| **收录量** | 百度索引的本站 URL 数 | 百度站长平台 | 未接入（F2） |
| **死链率** | 死链数 / 总外链数（当前 219） | `check_links.py` | 待全量 |
| **OG 覆盖率** | 有 OG 全套的页面 / 总页面 | 扫描脚本 | 3/14 ❌ |

### 2.1 指标口径纪律

- 换算法前必须记录变更点，否则趋势断裂。
- 季度复盘时统一回顾口径是否仍合理。
- **禁止**用未接入的数据源（如 GA4）的残缺数据下结论——国内大概率采集不全。

## 3. 报表模板

### 3.1 周报（每周，四数 + query）

```markdown
## 周报 · YYYY-WW（MM-DD ~ MM-DD）

**四数**
| 指标 | 本周 | 上周 | 环比 |
|---|---|---|---|
| 成功找站 | | | |
| zero_result | | | |
| save-rate | | | |
| re-find | | | |

**站内 query**
- 高频 Top10：<词 / 次数>
- 扑空 Top10：<词 / 次数> → 收录候选：<列出>

**本周动作**
- 新增收录：N 条（<清单>）
- 修复：<清单>
- 待办：<清单>

**风险**：<无 / 描述>
```

> C7 未建成前，周报只出「本周动作 + 风险」，四数标"无数据"。

### 3.2 月报（每月）

在周报基础上加：

- 死链全量结果（根页 + 频道）
- 台账对账结果（card / link / html）
- 收录质量抽检结果（本月新增卡抽查 N 条，通过 N 条）
- 内容产出统计（办事指南 N 篇、导语 N 个）
- OG / JSON-LD 等覆盖率变化

### 3.3 季度报

加：外链全量核验结果、域名/备案/DNS 状态、认证标记回访、文档体系一致性抽查（`.workbuddy/docs/` 与站点现状漂移数）。

### 3.4 半年/年度报

加：架构复盘、SEO 大盘（收录量/排名/流量来源/扑空率趋势）、专家评审轮结论、命名与治理规范遵守复盘。

## 4. 异常响应（出事怎么办）

| 异常 | 判定 | 立即动作 | 后续 |
|---|---|---|---|
| **站点打不开** | HTTP 非 200 / 超时 | ① 查 GitHub Pages 状态页 ② 查 DNS 解析 ③ 查 CNAME 配置 | 记录事件，复盘是否为部署导致 |
| **页面样式丢失** | 页面裸奔 | 查相对资源路径（`assets/` 深度）——**本项目已发生过**（05-开发规范 §8） | 跑断链扫描，全站排查 |
| **外链大面积失效** | 死链率突增 | 判定是对方站点变更还是本站数据问题；先标记待核验，**不批量删除** | 逐条人工确认 |
| **收到投诉/举报** | 内容或收录被指不当 | **立即降级或下架**涉事内容（存疑即下架） | 转合规流程（12-合规 §7） |
| **发现山寨/钓鱼收录** | 核验不通过 | 立即下架 + 全站排查同类 | 更新收录核验标准（16-内容更新规范 §2） |
| **第三方脚本拖慢** | LCP 明显恶化 | 临时注释该脚本；报告用户 | D-4 决策 |
| **数据被误改** | 卡片内容异常 | 从 `.workbuddy/backups/` 回档（19-备份策略 §5） | 补时间日志 |

## 5. 内容节奏（产出要求）

| 类型 | 频率 | 要求 | 依据 |
|---|---|---|---|
| 本周上新 | 每周 | 精选 3–5 条新增/更新卡片 + "更新了什么"，复用 changelog 数据源 | C3 |
| 频道页导语 | 每月推进一批 | 300–500 字**独特内容** + FAQPage JSON-LD | D1 |
| 办事指南文章 | 每月 2–4 篇 | "XX 事项网上办理入口汇总"，内链到频道页，配 FAQPage | D3 |
| changelog 更新 | 每次收录/改动 | 同步 `pages/changelog/` | §5.3.3 第 6 步 |

---

## 6. 运营纪律（红线复述）

1. 内容发布前过**公文审稿闸门**（措辞/角标/来源留痕）。
2. 收录前 100% 过官方源核实（12-合规 §3）。
3. 不发布 AI 自动生成的政务/民生资讯。
4. 任何指标决策需有 30 天有效分母。
5. 每次运营动作（含内容更新）都要过 02-迭代规则 四阶段 + 记时间日志。
