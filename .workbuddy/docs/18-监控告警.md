# 正协导航 · 监控告警（18-监控告警）

> 读者：故障处理、建设数据能力时必读。
> 版本：v1.0 ｜ 2026-08-29 ｜ **现状：监控能力基本空白，本文为建设方案 + 现有最小可行监控**

---

## 1. 监控现状（诚实基线）

| 层 | 现状 | 问题 |
|---|---|---|
| **可用性** | 无主动监控 | 站点挂了只能靠人工发现 |
| **性能** | 无 RUM；LCP/CLS 未测 | 不知道真实用户体验 |
| **统计** | 百度统计（3 处）+ GA4（11 处）+ AdSense（6 处） | **GA4/AdSense 域名被 GFW 屏蔽**，数据大量缺失 |
| **站内行为** | 无打点（C7 未建） | 无搜索词、无扑空率、无收藏率 |
| **收录** | 未接入百度站长平台（F2 待做） | 不知道索引量与抓取异常 |
| **安全** | 无 CSP、无入侵检测 | 静态站攻击面小，风险可接受 |

**核心矛盾**：数据能力建在**国内不可达**的 GA4/AdSense 上，导致"有监控但看不到"。

## 2. 监控分层设计

### 2.1 L1 可用性（最优先，可立即落地）

| 项 | 阈值 | 频率 | 工具 | 现状 |
|---|---|---|---|---|
| 首页 HTTP 200 | 非 200 即告警 | 每 5 分钟 | 免费拨测（如 UptimeRobot / 阿里云云监控 / 腾讯云拨测） | ⬜ 未建 |
| 首页关键词存在性 | 页面含站点名 | 同上 | 同上 | ⬜ |
| 频道页 200 | 非 200 即告警 | 每 30 分钟 | 同上 | ⬜ |
| DNS 解析正常 | 解析到 GitHub Pages | 每天 | `nslookup` / 在线工具 | ⬜ |
| HTTPS 证书有效期 | 剩余 < 14 天告警 | 每天 | 浏览器 / 在线检测 | ⬜ |

> **最小可行方案**：注册一个免费拨测服务，加 3 条 URL（首页 + 2 个频道页），异常发邮件。成本低、收益高。

### 2.2 L2 性能（RUM）

| 项 | 阈值 | 频率 | 工具 |
|---|---|---|---|
| LCP | > 2.5 s 告警 | 持续（RUM）或每周抽样 | Web Vitals / Lighthouse |
| CLS | > 0.1 告警 | 同上 | 同上 |
| TTFB | > 800 ms（国内）告警 | 同上 | 同上 |
| 第三方脚本超时 | 单域 > 3 s 未响应 | 每次部署后 | DevTools Network |

> ⚠️ **注意**：境外节点测不出 GFW 导致的超时。**性能测量必须在国内网络下进行**，否则结论无效（14-性能基线 §7.4）。

### 2.3 L3 收录与 SEO

| 项 | 阈值 | 频率 | 工具 |
|---|---|---|---|
| 百度索引量 | 周环比下降 > 10% 告警 | 每周 | 百度站长平台（F2 待接入） |
| 抓取异常 | 出现 404/5xx 抓取即查 | 每周 | 同上 |
| sitemap 提交状态 | 提交失败告警 | 每次新增页面后 | 同上 |
| 死链率 | > 2% 告警 | 每月 | `check_links.py` |

### 2.4 L4 站内行为（依赖 C7）

| 项 | 定义 | 用途 |
|---|---|---|
| 站内搜索 query | 用户输入的搜索词 | 收录候选、导语选题 |
| 扑空 query | 结果为 0 的搜索词 | 最直接的"缺什么"信号 |
| 卡片外链点击 | 点哪个卡、跳哪个站 | 找站成功率、热门入口 |
| 收藏行为 | 收藏了哪些卡 | 收藏率 save-rate |
| 主题切换 | 亮/暗使用占比 | 暗色价值评估 |

> C7 打点方案见 §4，当前 ⬜ 未建。

### 2.5 L5 安全

| 项 | 阈值 | 频率 |
|---|---|---|
| 第三方脚本变更 | 与 11-安全审计 §2.3 清单不符即查 | 每月 |
| 仓库公开内容扫描 | 出现密钥/口令即告警 | 每次提交前（人工） |
| 域名到期 | 剩余 < 30 天告警 | 每月 |

## 3. 告警响应流程

```
告警触发
  → ① 确认是否为误报（换网络/换设备复验）
  → ② 判定级别（🔴 站点不可用 / 🟠 功能受损 / 🟡 指标劣化）
  → ③ 🔴 立即处置（回滚 / 下架 / 修配置），不等完整根因分析
  → ④ 记录事件到当日时间日志
  → ⑤ 复盘根因 → 更新本文或相关规范的检查项
```

| 级别 | 响应时限 | 处置 |
|---|---|---|
| 🔴 站点不可用 / 合规风险 | **立即**（发现即处理） | 先恢复服务，再查根因；存疑内容先下架 |
| 🟠 功能受损 / 死链率超阈值 | 24 小时内 | 定位并修复，记录 |
| 🟡 指标劣化 / 体验下降 | 本周内 | 进整改清单，按排期 |

## 4. C7 站内搜索打点方案（待建）

> 目标：用最小成本拿到"用户到底在找什么"的真实数据（周报 query 报表依赖它）。

### 4.1 采集事件（4 个，够用即可）

| 事件 | 触发 | 字段 |
|---|---|---|
| `search` | 站内搜索回车 | `query`、`result_count` |
| `zero_result` | 结果为 0 | `query` |
| `card_click` | 点击卡片外链 | `card_key`、`target_domain`、`cat` |
| `fav_toggle` | 点收藏星 | `card_key`、`to_state` |

### 4.2 实现约束（静态站前提下）

- **不引入第三方 SDK**：直接用百度统计的**自定义事件**（`_hmt.push(['_trackEvent', ...])`）上报，无需新依赖、国内可达。
- 事件写入 `assets/js/main.js`，不单独引脚本。
- **隐私**：只采集行为事件，**不采集可识别个人信息**；隐私政策须披露"采集匿名使用行为用于改进服务"。

### 4.3 落地步骤

1. 在 `main.js` 的搜索/点击/收藏处理处埋 4 个事件（用百度统计事件接口）。
2. 更新 `pages/privacy/` 披露埋点（**合规前置**，见 12-合规 §2.1）。
3. 部署后观察 30 天建立基线 → 才有资格用四数拍板。
4. 周报增加 query 报表（15-运营SOP §3.1）。

## 5. 统计方案待决（D-4）

| 方案 | 优点 | 缺点 |
|---|---|---|
| **仅留百度统计**（Backlog P0 建议） | 国内可达、首屏最快、数据聚焦主战场 | 失去 AdSense 变现 |
| 保留三套 | 覆盖海外 + 变现 | 首屏被拖（2 域被墙）、数据仍缺失、隐私披露复杂 |
| 百度统计 + 自建轻量打点 | 行为数据自主 | 需后端，违背静态站定位（**否决**） |

**拍板后必须同步**：11-安全审计 §2.3、14-性能基线 §4、12-合规 §2.1、01-PRD §9 Q2。

## 6. 监控建设路线图

| 阶段 | 动作 | 成本 | 收益 |
|---|---|---|---|
| **M0（1 周内可做）** | 注册免费拨测，加 3 条 URL 可用性监控 + 邮件告警 | 极低 | 从"完全不知道挂了"到"5 分钟内知道" |
| **M1（依赖 D-4）** | 拍板统计方案；删除或异步化 GA4/AdSense | 低 | 消除首屏最大风险 |
| **M2（依赖 F2）** | 接入百度站长平台，监控索引量与抓取异常 | 低 | 收录生命线可视化 |
| **M3（C7）** | 落 4 个站内行为事件 + 隐私披露 | 中 | 周报四数与 query 报表有了数据源 |

---

## 7. 纪律

- **不得**基于 GA4 数据下国内业务结论（采集不全，样本偏差）。
- **不得**在无 30 天有效分母时用指标拍板方向。
- 任何新增打点/统计脚本 → 先过 11-安全审计 §5 引入前检查清单 + 更新隐私政策。
