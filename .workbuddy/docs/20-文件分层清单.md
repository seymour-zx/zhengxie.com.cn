## 1. 五层模型（按"谁需要它"分层，不按文件类型）

```
┌─ T0 运行层 ──── 浏览器 / 访客 / 搜索引擎爬虫 ──── 每个字节都公开
├─ T1 发现层 ──── 爬虫 / 托管平台 / 广告平台 ────── 机器可读格式
├─ T2 说明层 ──── 外部读者 / 想自建同类站的人 ──── 受公开暴露铁律全禁
├─ T3 数据构建层 ─ 运营者（改 xlsx）/ 开发者（改 py）
└─ T4 治理知识层 ─ Agent（每次会话）/ 未来的你 / 接手者
```

**分层第一原则**：内容越"内部"，越往下沉。**决不允许下层内容泄漏到上层**——尤其 T4 → T0/T2。

### 1.1 你的理解对照（已确认与修正）

| 你的判断 | 结论 | 说明 |
|---|---|---|
| 访客只要 html / css / js | ✅ 对 | 还需加 `assets/images/`、`favicon.ico` |
| README 是"放 GitHub 才需要" | ⚠️ 半对 | 它是**面向人的项目说明书**，GitHub 只是恰好渲染它。因对外可见，受公开暴露铁律全禁 |
| 更新数据才要 py + xlsx | ✅ 对 | 即 T3 层 |
| 完整了解项目才要 md | ✅ 对 | 但 md 分属两阵营：T2（README，公开）/ T4（`.workbuddy/docs/`，内部） |
| Agent 才要 `.workbuddy/` + 所有 md | ⚠️ 半对 | `.workbuddy/` 内部还分三类（§5），后两类 Agent 不主动读 |

## 2. T0 运行层 —— 给浏览器与访客

**受众**：网址访问者、搜索引擎爬虫。
**铁律**：**这一层的每个字节都视为公开内容。**

| 路径 | 允许内容 | 禁止内容 | 谁维护 |
|---|---|---|---|
| `index.html` | 导航产品页完整结构（S1 骨架） | ❌ 任何 `.workbuddy/` 路径或提及 ❌ 内部草稿 ❌ 未核实内容 | build 生成（**禁手改**） |
| `404.html` | 品牌风格错误页 + 可读内容 + 延迟跳转 | ❌ 广告位 ❌ 内部路径 | 手写 |
| `pages/*/index.html`（9 个） | 说明/合规/功能页（S3–S5 骨架） | 同上 | 手写 |
| `directory/*/index.html` | 频道页（S1/S2 骨架） | 同上 | build 生成（**禁手改**） |
| `assets/css/style.css` | 全站样式 + design token（03-设计规范 §2） | ❌ 硬编码色值（token 定义处除外） | 手写 |
| `assets/js/main.js` | 交互增强 + 埋点（18-监控告警 §4） | ❌ `eval` ❌ `innerHTML` 拼接用户输入 ❌ 新增内联事件 ❌ 密钥 | 手写 |
| `assets/images/*` | WebP（**保留透明通道**）+ `logo.svg` | ❌ 非 WebP 位图 ❌ 超大图 | 手工 |
| `favicon.ico` | 站点图标 | — | 手工 |

**T0 硬约束**：
1. 所有卡片/链接/分类按钮**静态渲染**，禁用 JS 仍可读可点（SEO 生命线）。
2. 相对资源路径按**实际目录深度**取（`../` vs `../../`，不可照抄——ADR-005，本项目已在此翻车两次）。
3. 每个 `<img>` 必带 `alt`；每个 `_blank` 必带 `noopener`。
4. head 齐备：`canonical` / `description` / `keywords` / OG 全套 / `twitter:card` / `theme-color` / `viewport` / `apple-touch-icon`。

## 4. T2 说明层 —— 给外部人

**受众**：GitHub 访客、想自建同类导航站的人。
**铁律**：**公开暴露铁律全禁**（CONVENTIONS §1.11）。

| 路径 | 允许内容 | 禁止内容 |
|---|---|---|
| `README.md` | 项目是什么、设计语言、站点结构、**手工写站教程**、部署方式、FAQ | ❌ 提及 `.workbuddy/`（路径/名称/清单）❌ 写 py 生成链路 ❌ 暴露内部工作流 ❌ 真实统计 ID ❌ 任何可致站点被复制/破坏的信息 |

**T2 写作纪律**：写每一段前问一句——"这段话让陌生人知道了内部结构吗？"是则不写。
**README 的定位**：只写"用户能看到的"（index.html 与 css/js 为什么这么写 = 手工逻辑讲解）。py 生成链路属 T4，**不得进 README**。

## 7. 新建文件准入规则（放哪、叫什么、要什么）

### 7.1 判定流程（不确定放哪时按序问）

```
Q1. 访客或爬虫会直接或间接用到它吗？
    → 是 → 进 T0（页面/样式/脚本/图片）或 T1（机器配置文件）
    → 否 → Q2

Q2. 它是数据或生成数据的程序吗？
    → 是 → 进 T3（xlsx 真值源 / .build 脚本）
    → 否 → Q3

Q3. 它是对外的项目说明吗（陌生人可读）？
    → 是 → 进 T2（且必须过公开暴露审查）
    → 否 → 进 T4

Q4（T4 内部）. 是规范（每次要读）/ 历史（追溯时读）/ 评审（专家调阅）？
    → 分别进 docs / memory+backups / agent-review-survey
```

### 7.2 命名规则（CONVENTIONS §4.2）

| 对象 | 规则 | 实例 |
|---|---|---|
| 页面/URL 目录 | 小写英文单词 | `pages/about/`、`directory/gov/` |
| Python | 小写 snake_case；`build_*` 生成器、`check_*`/`collect_*`/`sync_*` 工具、`_临时名` 一次性 | `build_homeplus.py` |
| 文档 md | `NN-<主题>.md`（编号体系）或 `<主题>-<日期>.md`（交付物） | `20-文件分层清单.md` |
| 数据列 | 英文 snake_case | `card_title` |
| 时间戳 | 一律 `YYYY-MM-DD` | `2026-08-29` |
| 备份目录 | `.workbuddy/backups/YYYY-MM-DD-<用途>/` | — |

### 7.3 新建文件的标准骨架（"限制于标准框架内"）

#### 新增 HTML 页面

1. **先判骨架**：S1–S6 属哪一类（README §三）？无法覆盖且对长远有利才新增 S7+。
2. **套该骨架模板**，head 必含（缺一即不合格）：
   `title` / `description` / `keywords` / `canonical` / `og:title` / `og:description` / `og:image` / `og:site_name` / `og:url` / `twitter:card` / `theme-color` / `viewport` / `apple-touch-icon` / JSON-LD（按 CONVENTIONS §3.1 选 `@type`）/ FOUC 防护内联脚本。
3. **组件只能复用** 04-组件库规则 §2 已登记的 class，新增组件须先登记。
4. **相对路径按实际目录深度**取，不照抄。
5. 建完跑 09-用例模板 UC-P01 ~ UC-P10。

#### 新增 Python 脚本

```python

"""

"""

import os

HERE = os.path.dirname(os.path.abspath(__file__))   # 不依赖 cwd
ROOT = os.path.dirname(os.path.dirname(HERE))

    pass

    sys.exit(main())     # 失败即非零退出码
```

约束：仅标准库 + `openpyxl`（唯一第三方依赖，06 §1）；失败即非零退出码；不静默吞异常。

#### 新增 md 文档

1. 先问："能融合进现有权威源吗？"能 → 融合，不新建。
2. 不能 → 登记编号进 `00-索引.md` → 再落文件。
3. 未登记的 md = 废 md。
