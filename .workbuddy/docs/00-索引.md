## 一、体系定位（这份体系解决什么）

现有资产已能跑，缺的是**可传承的工程约束**：规范散在 README（手工写站）、CONVENTIONS（治理+运营）、两个 SKILL（子页 SOP / SEO 标准）里，没有产品定义、设计 token、组件契约、测试与质量标准、安全/性能/合规基线、部署与监控闭环。

本体系补齐这 19 项，使「任何人换设备接手 → 读 00 → 按编号取用 → 产出与现有一致」。

**边界（不越界）**：

- 本体系**不重复** CONVENTIONS 的治理铁律（Git 全停令、文件改动铁律、backup 铁律、公开暴露铁律）——那些仍是最高优先级，本体系与之冲突时以 CONVENTIONS 为准。
- 本体系**不重复** README 的手工写站教程——README 面向"自建同类站的人"（公开层），本体系面向"维护本项目的执行者"（内部层）。
- 本体系**不替代**两个 SKILL 的操作步骤——SKILL 是"怎么做"的 SOP，本体系是"必须满足什么"的标准与基线。

## 三、新接手 5 分钟路径

```
00-索引（本文件）
  └→ 01-PRD          搞清楚这站是什么、为谁、不做什么
      └→ 03-设计规范 + 04-组件库规则   动视觉与结构前
          └→ 05-开发规范 + 06-技术选型  动手写之前
              └→ 02-迭代规则           按流程跑一次改动
                  └→ 17-部署流程 + 10-质量标准   发布前过闸门
```

只需改一个卡片文案 → 走 `16-内容更新规范` + `02-迭代规则`（轻量版）即可。

## 四、文档维护规则

1. **真值源唯一**：同一规定只在本体系出现一次；CONVENTIONS / README / SKILL 已有的，本体系只写指针不复制（防漂移）。
2. **变更留痕**：任何编号文档增删改 → 记当日 `.workbuddy/memory/YYYY-MM-DD.md` 时间日志（backup 铁律），并同步本索引的"修订记录"。
3. **禁止裸放**：新建 md 必须先在本索引登记编号，否则视为废 md（CONVENTIONS §1.13 文档生命周期）。
4. **周期性复核**：每季度（见 15-运营 SOP）抽查本体系与站点现状一致性，漂移项进整改清单。
