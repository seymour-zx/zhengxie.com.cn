## 1. 产品定位

### 1.1 一句话（暂用，待拍板）

> **正协导航 —— 让每一次寻找，都不止于找到。**
> 独立第三方导航站，汇集人民政协与民主党派的官方入口。

⚠️ 此句为 README 既有 slogan，尚未经「定位一句话定案」（CONVENTIONS §5.4 A2 / §5.7 待拍板）。**拍板前不得写进 JSON-LD、OG、对外文案**。

### 1.2 产品性质（三条硬边界）

| 维度 | 定义 | 反例（禁止） |
|---|---|---|
| **独立第三方** | 与任何政府机构无隶属关系，不获官方背书 | 暗示官方身份、使用政协官方标识/视觉 |
| **聚合而非生成** | 只做入口的收录、核实、组织 | AI 自动写/自动发政务或民生资讯 |
| **导航而非门户** | 核心价值是把人快速送到正确官网 | 把内容搬到站内做成"内容站"稀释导航价值 |

### 1.3 差异化（凭什么被用）

1. **可信**：每条收录经官方源核实（备案/域名归属/诈骗预警），政务卡带认证标记与核验时间（C4/C5，待建）。
2. **垂直**：政协 + 民主党派 + 政务办事入口的密度，通用导航站做不到。
3. **轻量**：纯静态，无后端、无追踪墙，国内可访问性优先于功能丰富度。

## 2. 目标用户与场景

| Persona | 场景 | 核心诉求 | 关键路径 |
|---|---|---|---|
| **A 办事群众** | 要找"某市政协官网""社保网上办理入口" | 快、准、是官网不是山寨 | 根页 → 搜索/分类 → 卡片 → 外链 |
| **B 研究者/从业者** | 查民主党派中央、地方政协、部委清单 | 全、可核对、能批量看 | 频道页 → 分类筛选 → 逐条核 |
| **C 站内运营者（用户本人）** | 新增收录、核验外链、看数据 | 录入不踩坑、改动可回档 | xlsx → build → 校验 → 部署 |

> 说明：A/B 的 persona 与旅程文档属 CONVENTIONS §5.4 E3（⬜ 待做）。本表为最小可用版本，供需求优先级排序用，不等 E3 产出。

## 3. 范围边界

### 3.1 本期范围内（In Scope）

站点现有能力 + 已排期待建项：

- 根页导航产品（337 卡）、频道页（engine 67 / gov 59）、9 个说明功能子页、404。
- 三维度筛选（分类 × 关键词 × 本地收藏）、集合搜索、滑道交互。
- xlsx 单一真值源 → Python build 生成页面。
- 治理层（CONVENTIONS、本体系、2 个项目技能）。

### 3.2 明确不做（Out of Scope）

| 不做 | 原因 |
|---|---|
| 后端 / 用户账号 / 云同步收藏 | 静态站定位，成本与合规代价远超收益 |
| 站内资讯自动生成与发布 | 红线（CONVENTIONS §5.5 🔴-1） |
| 广告策略优化（布局/单价） | 属平台策略，转专家（CONVENTIONS §二） |
| 移动端原生 App | 无需求、无资源 |
| 收录范围扩张到非政务通用领域 | LOCKED：垂类为主、通用为辅（§5.5 🔴-9） |

## 5. 非功能需求（NFR）

| 类别 | 要求 | 权威文档 |
|---|---|---|
| **性能** | 首屏关键路径 ≤ 预算值；**首屏第三方域 ≤ 1**（当前 3，其中 2 域被墙） | [14-性能基线](./14-性能基线.md) |
| **SEO** | 所有卡片静态渲染，禁 JS 仍可读可点；canonical/description/JSON-LD 齐备 | [13-SEO审计](./13-SEO审计.md) |
| **安全** | 无 CSP 前不得引入新第三方脚本；所有 `_blank` 必带 `noopener` | [11-安全审计](./11-安全审计.md) |
| **无障碍** | 文本对比度 ≥ WCAG AA；焦点可见；图标有 aria-label | [03-设计规范](./03-设计规范.md) §5 |
| **合规** | 非官方声明、隐私披露、广告隔离、内容红线 | [12-合规检查清单](./12-合规检查清单.md) |
| **可维护性** | 单一真值源；改动必备份 + MANIFEST；临时脚本用后即删 | [05-开发规范](./05-开发规范.md) / [19-备份策略](./19-备份策略.md) |
| **可移植** | 全部约束落在随仓库同步的 md 或代码内，换设备可读 | CONVENTIONS §1.7 |

## 8. 验收口径（什么叫"做完"）

任何功能/改动交付，必须同时满足：

1. **功能验收**：按 [09-用例模板](./09-用例模板.md) 写的用例 100% 通过。
2. **质量门槛**：过 [10-质量标准](./10-质量标准.md) 的红线项（红线任一不过 = 不许上线）。
3. **流程合规**：走完 [02-迭代规则](./02-迭代规则.md) 四阶段，有备份锚点与时间日志。
4. **文档同步**：引出新规则 → 落进权威源，不裸放 md。
