**结论：本站目前没有"全流程控制表"，相关规定是碎片化的**，分散在 5 处，本次草案把它们收拢为一张可执行的总表：

| 现有规定 | 位置 | 覆盖范围 | 缺口 |
|---|---|---|---|
| 迭代四阶段（Plan/Build/Sync/Close） | CONVENTIONS §5.1 | 单次开发迭代 | 无周期（日/周/月）与节点（部署/收录）控制 |
| 文件命名与存放规范（五层目录） | CONVENTIONS §6 | 文件治理 | 无运营流程 |
| 上线检查清单 | README §10.4 | 首轮上线 | 无持续运营检查 |
| SEO 标准手册（LOCKED/Backlog） | skills/zhengxie-seo-standard | SEO 事项 | 无时间周期编排 |
| 卡片录入规范 SOP | 圆桌 §4.2 产物 | 收录动作 | 无前置/后置流程衔接 |

**已确认的背景事实（截至 08-27）**：
- 站点结构：根页 65 卡 + 频道 hub + `gov/`（政务导航 59 卡）+ `engine/`（引擎导航 18 卡）；sitemap 13 条 URL。
- 数据源：`assets/xlsx/self_links.xlsx`（根页，英文 75 列）为唯一真源；频道页 `directory/{gov,engine}/assets/xlsx/self_links.xlsx` 同 schema（英文 75 列）；`build_homeplus.py` 仅接受英文表头。
- 生成器：`build_homeplus.py` 每次运行**删除所有 `directory/*/index.html` 再重生成** → 新频道必须走生成器正路（带 xlsx），手写频道页会被清。
- 台账：`card`/`link`/`html` 三份 `*_verification_log.xlsx` 已建（0 行，未接入渲染）。
- 治理三层：时间日志（实时）⊂ changelog（备份指令时蒸馏）⊂ backup.md（备份指令时全空间快照）；受管文件增删改 → 实时记时间日志。
- Git：**agent 全停令**——agent 不执行任何 git 命令，仅收口时提醒未提交文件。

## 1. 全流程六大阶段总览

```
设计 ──→ 开发 ──→ 部署 ──→ 收录 ──→ 运营 ──→ 维护
 │        │        │        │        │        │
 骨架判定   数据源    发布闸门   官方核验   日/周/月  死链/复核
 视觉语言   build     上线清单   字段录入   内容节奏   备份/审计
 架构决策   校验      sitemap   台账登记   数据打点   归档清理
```

每阶段都跑「迭代四阶段」（Plan → Build → Sync → Close），单文件微调也至少走 Plan 清单 + Build 备份 + Close 查跟踪。

## 4. 必做 / 建议做 / 不建议做 / 禁止做（红绿灯总表）

> 规则来源均为已拍板决策或圆桌红线，**不是新提法**；执行中若与 LOCKED 决策冲突，以"用户最新指令 > CONVENTIONS > 技能手册"裁决。

### 🔴 禁止做（红线，任何阶段）
1. **AI 自动写 / 自动发站内政务或民生资讯**——聚合≠生成，发布前必须人工守门（圆桌 #30/#33）。
2. **冒充官方**：暗示与政府机构隶属关系、使用政协官方标识/视觉风格、自称官方。
3. **收录未核验链接**（无备案/域名归属/诈骗预警核查）。
4. **agent 执行任何 git 命令**（含 add）——Git 全停令。
5. **新 md 裸放 `docs/` 当永久文件**——必须融合进权威源或降级 L2。
6. **不传谣发布纪律**：待核实（pending）零主动触达；证伪即降级挂红标；误报 >5% 熔断（#31 建成后适用）。
7. **政务/机构/办事频道页放广告**；**屏蔽代办/贷款/下载器类广告**（F5）。
8. **优化负面词**：代办/代开/加急/包过/贷款/下载器（D4）。

### 🟢 建议做（性价比高，未定优先级）
