## 二、片段化拼装引擎（build_homeplus 核心改造，D-16）

**页面 = 骨架 + 片段拼装，全部由 xlsx 驱动，py 无页面特判**：

| 片段 | 控制字段 | 规则 |
|---|---|---|
| head 元信息（title/description/keywords/OG/Twitter/JSON-LD/canonical） | title/description/keywords + dir_path | 自动生成（引用同源，一处改全联动） |
| GA4 统计 | stat_ga4 | True=注入 gtag 脚本 + preconnect；空=零残留 |
| 百度统计 | stat_baidu | True=注入 hm 脚本 + preconnect；空=零残留 |
| 广告位 | ad_slots | `1,3` 式 → 注入对应广告位代码 + adsbygoogle + preconnect；空=零广告代码（meta 零 AdSense） |
| 集合搜索框 | search_box | True=注入 hero 搜索框模块；空=无 |
| 导语 | channel_intro_enabled + channel_intro | 开关 True 且有内容才显示 |
| 卡片区 | dir_path | 该页对应分类的全部卡片 |
| footer / 声明条 | 固定 | 全站统一 |

**py 无页面特判原则**：代码里不出现"首页该有 X、搜索专题页该有 Y"的硬编码；一切由 xlsx 行的字段值决定。

## 三、xlsx 读取健壮性（build 规格，造物主拍板）

1. 读**第一个 tab**
2. **自动识别表头行**（扫描含关键列名——如 row_seq/dir_path 的行，作为表头；不硬编码行号）
3. **列乱序不影响**（表头 → 列名映射，按名取值）
4. **额外列安全**（只取已知列名，忽略造物主自加备注列）

## 四、随机漫步改造（做-5）

- **行为**：点【随机漫步】→ 随机展示一行/一页卡片（**不跳转**）→ 用户自选点击
- **UI**：随机漫步条与分类标签**同处 sticky 分类容器**；随机模式隐藏分类标签（display:none）、显示随机漫步条（含「换一批」「退出」+ 广告提示）
- **广告双策略**：随机池 = 普通池 + 广告池（is_ad=True）；**首次必出 1 张广告卡 + 每批固定比例**（参数放 build 配置常量）
- 广告卡带「广告」标识（card--ad + 标签）

## 五、小米滑动修复（T6，必做）

- CSS：滑道/卡片行容器加 `touch-action: pan-x`
- JS：简化接管逻辑（原生 scrollLeft 平滑滚动）、避免过度 preventDefault、异常超时兜底释放
- 实测：小米浏览器 + 微信 + Chrome 三端验证

## 六、verify_site → xlsx 报告（D-10）

- 八项校验（断链/head/noopener/链接合法性/图片/标题层级/JSON-LD/面包屑）照旧执行
- **输出 xlsx 问题报告**：
  - sheet1 问题清单：页面 / 检查项 / 级别（红线·严重）/ 问题 / 建议 / **造物主决定**（上线/修复/豁免）
  - sheet2 汇总：每页问题数 / 红线数 / 严重数
- **上线决策权归造物主**（人治闸门）：审阅 xlsx → 逐条标决定 → 决定是否上线
- **闭环（契约 04）**：重跑时读旧报告「造物主决定」列 → 豁免/上线/修复继承（`load_prev_decisions`），拍板不因重跑丢失
- 适配：JSON-LD 契约映射更新（/topics/ 专题导航 CollectionPage、专题页 WebPage）；豁免清单重审

## 六·补、资源版本戳（2026-08-30 造物主拍板方案 A，治缓存不同步）

- build_homeplus.py 顶部 `asset_ver()` 算 css/js 内容 **md5 前 8 位** → `CSS_VER/JS_VER` 拼进生成页 `<link>/<script>` 的 `?v=`（文件变 → URL 变 → 浏览器必重发）
- 手写页（pages/*）css 引用由 build main() 末尾**幂等注入**同一版本戳（仅替换无 ?v= 的 href，不碰正文）
- verify_site.py check_1 资源存在性检查**剥离 query**（`?v=` 不当路径）；报告继承豁免见上
- 背景：CSS/JS 独立缓存不同步曾致「两浏览器行为完全相反」（谷歌↔微软反转，2026-08-30）

## 七、广告位编号体系（2026-08-30 确认）

**旧世界已有编号**：① 顶部（ad--top，data-ad-slot `5952548493`）、② 底部（ad--bottom，data-ad-slot `4856101005`）——注释标 ①②，AdSense 后台可分位统计收益。

**新世界 `ad_slots` 编号 = py 广告位片段库索引**：
- `AD_SLOT_1` = 顶部广告位（slot 5952548493，沿用旧 ①）
- `AD_SLOT_2` = 底部广告位（slot 4856101005，沿用旧 ②）
- `AD_SLOT_3`+ = 中部/自定义位（扩展；**新增需先在 AdSense 后台建广告单元拿 slot ID** → py 加片段 → xlsx 引用，不动页面代码）

**编号注意点**：
1. 每个编号 = py 里一段**完整广告位片段**（aside + ins + push + 各自 data-ad-slot）
2. **loader（adsbygoogle.js）只注入一次**（有任意广告位才注入；零广告位零注入）
3. preconnect 随广告开关
