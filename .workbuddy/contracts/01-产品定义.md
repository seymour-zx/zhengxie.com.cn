## 0. 旧世界被抛弃的根因（永远记住，不可再犯）

> **旧世界 agent 团队一直用「传统导航网站」定义本项目**——形式借鉴了传统导航的外观，但产品本质不是导航。传统导航网站已被时代淘汰多年，何况本架构是纯静态 html+css+js。旧世界的每一轮圆桌、每一份执行方案，都建立在"这是个导航站"的错误前提上 → 一切结论天然违背造物主本意。

**执行铁律**：本项目**不是导航站**（虽然长得像）。任何"导航网站惯例"（如"卡片必须有链接、无链接卡片应删除"）**不适用于本项目**，除非造物主明确认可。

## 1. 产品本质（一句话）

> **一个主题卡片陈列馆 / 百科索引**：每张卡片是一个词条（机构、人、书、电影、学校……无任何限制），像展览展示架、陈列馆一样陈列"世界上存在过/存在着的事物"，并给出与它相关的链接（若有）。

- 造物主初衷：实现一个想法，兴趣 / 爱好，把网站当玩具。有情怀才做，不图利。
- 形式（卡片、分类、筛选、收藏、暗色、集合搜索）= 承载方式；本质 = 陈列馆。

## 2. 定位（展开）

- **综合全品类导航**，绝非纯粹垂直导航。
- **政协 + 民主党派 = 首页的一个频道专题**——作用：吃 `zhengxie.com.cn` 域名的政协自然流量。
- 域名与名称带来的政协流量是入口，但站本身是综合陈列馆。
- 必须时刻**切割**：避免违规、避免被误认/假冒官方。

## 3. 卡片模型（陈列馆 / 百科索引）

1. **卡片 ≠ 必须有链接**。卡片表示"我知道有 XX 政协 / XX 事物"。它没有网址，可能因为：
   - 官网已停维护 / 已被合并；
   - 造物主尚未找到网址。
   → **卡片必须存在**，并明确展示"此条无网址"（用户能理解，这是网络发展的必然——低流量网站没有维护价值，网站作为历史产品正在被淘汰）。
2. 卡片可以是一本书名、一个人名、一部电影名、一所学校名……**没有任何限制**，都可能出现 → 这就是百科形态。
3. 卡片是**索引不是内容**：不做百科内内容；相关链接挂给对应的百科页面（外部），内容在外部。
4. 旧世界 agent 反复要求"删除无链接卡片" = 违背本意，**否决**。

## 4. 链接模型（链接行，不限制数量）

1. 卡片链接 = **链接行**（不是传统导航的"一卡一链"）。
2. **不限制链接数量**：只要与卡片相关，都可以挂——官网 / 微博 / 微信公众号 / 百科页 / 相关站点……
3. 例：XX 政协的官网没了，可以挂它的**微博链接、微信公众号链接**——这是产品发展方向。
4. xlsx 当前限 10 个链接位（link_1~link_10）= **预留位，为造物主人工收录维护方便**；后期将改造为不限制。

## 5. 名称与 slogan（永不改）

- 名称：**正协导航**
- slogan：**「让每一次寻找，都不止于找到」**（title / hero / footer 全站副标题）
- 造物主一直不同意改名的原因：`zhengxie.com.cn` 可吃政协自然流量；slogan 与定位契合。两者**永不改**。

## 6. 信息架构（D-02 / D-03 已拍板 + 待决项）

**已拍板（2026-08-30）**：
1. **首页 `/` = 政协 + 民主党派专题（唯一首页内容）**：民主党派**合并归集进政协专题**；卡片数千张（继续放其他内容影响页面访问；首页只有一个位置）。
2. **其他专题全部为子频道（子页面）**：gov 政务 / search 搜索工具 / 百家姓…后续扩展；**不进首页**。综合全品类 = 通过不断扩展子频道专题实现。
3. **gov 专题 = 政府/政务**：人大**初期合并进 gov**；后期是否开独立人大专题**待定**（目录名 npc/renda/其他 待决）。
4. **聚合搜索框 = 自用工具**：**不放首页**；**放搜索专题页**——方便造物主自己随意设备访问（域名自己的、网址好背）。
5. **命名标准**：废弃旧世界"差异化竞争避开热门关键词"；新标准 = **用词准确，对用户、机器无理解障碍和歧义**。

**待决**：
- 人大专题**开设时间**（目录 renda 已定，是否独立待后期评估）
- 百家姓专题**立项时机**（下一个新专题计划已定）
- 其他专题扩展方向（博物馆/学校/老字号等）——建议已罗列，待造物主圈定

**做**：
- 卡片陈列（有链接 / 无链接都展示；无链接明确标注"无网址/未找到"）✅（D-04）
- 链接行多链接（官网 / 微博 / 公众号 / 百科页……）✅（D-05）
- 综合全品类 + 政协专题吃流量 ✅（D-01/02/03）
- 整站级可信信号：非官方声明 + Organization 机器可读 + 链接露真域名 ✅（做-4；页面/卡片/链接维度暂不做，后期升级）
- 站内搜索 / 分类 / 收藏（本地）/ 暗色模式 / 随机漫步 ✅（做-5；**随机漫步新玩法**：随机展示一行/一页卡片，不跳转，用户自选是否访问；**UI = 随机漫步与分类标签同处 sticky 分类容器，随机模式隐藏分类标签、显示随机漫步条（换一批/退出）**；**类型选择 = 数量加权随机类型 → 取 2 行（行内同 type）；纯加权无排除（排除会拔高少数类型概率，C 规则已否决）；广告卡与普通卡同池自然参与，不分普通/广告（广告池/首次必出/比例策略已取消），广告卡带"广告"标识**）
- 反馈渠道明确，不静默假装成功 ✅（做-6；**与不做-5 同一逻辑：明确无后端，不设计假提交页面；反馈 = 邮件或共享表格登记；共享表格用「收集表/表单」模式，填写人仅见自己填写的内容（反馈表 + 收录表都适用）；平台 = 多家主流并列（腾讯文档/金山文档/石墨…），用户自选填写哪家**）

**不做**：
- 代办、代开、加急、包过、贷款、下载器类内容与收录（永久屏蔽）✅（不做-1；**语义澄清：屏蔽"以代办/代开/加急/包过/贷款中介/协助贷款公司/下载器为核心服务的灰色网站"收录；判断标准 = 网站性质（是否提供灰色服务），非"是否出现词"——银行/政务/正规机构页面出现"贷款"等词完全正常，正常收录**）
- 冒充官方 / 使用官方标识 / 自称官方（切割是第一优先）✅（造物主多次强调）
- 站内生成政务 / 民生资讯（聚合 ≠ 生成，发布前人工守门）✅（不做-3；**只挂聚合索引——用户点击链接跳转外部看内容；本站不写/不转/不承载政务民生内容，只收录官方入口、挂官方链接；内容永远在外部**）
- 逐卡认证徽章 / 逐卡核验日期（可信 = 整站级）✅（做-4 顺带确认）
- 无后端却假装"提交成功" ✅（不做-5；**修正为：收录申请 = 在线共享表格**（第三方在线表格工具，字段格式对齐 cards.unified.xlsx），申请者填表 → 造物主核验 → 复制粘贴入 xlsx → build 上线；**收录 = 复制粘贴，零转换；真实提交渠道，不做假提交**）
- **不做百科内内容**（只做索引，内容挂外部）✅（造物主明确）

### 7.1 命名通则（合规 · 造物主拍板入契）

1. **凡涉及官方/政务内容的专题，中文名必须带第三方属性词**（导航 / 索引 / 入口）——原因：裸"政务"会让用户误认官方政务平台，违背切割铁律；"导航"等词明示第三方，一劳永逸防合规风险。
2. **纯工具/文化类专题不受此限**（如"搜索工具""百家姓"）——原因：不涉及官方，无误导风险。
3. **命名标准（全站）**：用词准确，对用户、机器无理解障碍和歧义；废弃旧世界"差异化竞争避开热门关键词"思路——原因：差异化思路以牺牲准确性为代价，违背造物主本意（准确 > 避关键词）。
