## 三、门槛与分级（旧世界红绿灯提纯，最终决策归造物主）

| 级别 | 含义 | 处置 |
|---|---|---|
| 🔴 红线 | L1 断链 / 外链 noopener / L2 构建失败 / 禁用 JS 降级失效 | **强烈建议修复后上线**（xlsx 报告标红，造物主最终拍板） |
| 🟡 严重 | L1 其余项 / L3 死链 / 性能超预算 | 登记限期修复（可上线，xlsx 标注） |
| ⚪ 一般 | 无障碍非致命 / 文案细节 | 带病上线进整改 |

**豁免机制**：豁免项登记原因 + 期限 → 进豁免清单（xlsx 报告「造物主决定=豁免」列）→ 下次校验仍显示但标注豁免。

## 五、上线流程（每次部署）

1. 改 xlsx / 模板 → 记日志
2. `python build.py`（L2：失败即中断）
3. `verify_site.py` → xlsx 报告（L1）→ **造物主审阅拍板**（逐条标上线/修复/豁免）
4. `check_links.py` 抽查（L3，收录变更时）
5. L4 浏览器手工清单（含三端实测）
6. 造物主 git 推送（agent 不执行 git）
7. 发布后复测：根页/专题页/404 可达，统计可见

## 六、展示方案 + 闭环机制（2026-08-30 确认）

**展示**：
1. 控制台一句话摘要：`页面 N | 问题 X | 🔴 红线 A | 🟡 严重 B | ⚪ 一般 C` + 红线明细
2. xlsx 分级别 sheet：「汇总」（全站一览）/「红线」（红底）/「严重」（黄底）/「一般」（灰底）
3. 每行：页面 / 检查项 / 级别 / 问题 / 建议 / **造物主决定**（下拉：上线/修复/豁免）

**闭环（xlsx = 报告 + 决策单一体）**：
1. 造物主打开 xlsx → 逐条标 上线/修复/豁免 → 保存
2. **下次 verify_site.py 读上次报告决定列**：
   - 豁免 → 该问题本次标注「已豁免(上次日期)」→ 不再当新问题打扰（留痕季度复核）
   - 修复 → 问题还在 → 继续提示；已修复 → 自然消失
   - 上线 → 确认记录
3. **agent 部署前读决定列**：修复项先修（代码类）→ 重新 build → 新报告复看；未标记项提醒；全部放行才部署
