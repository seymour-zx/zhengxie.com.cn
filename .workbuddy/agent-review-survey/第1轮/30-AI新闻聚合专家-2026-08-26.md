## 二、圆桌总结（综合之前所有答卷 + 自己的思考）

我通读了第 1–29 位。圆桌把"可信/非官方/合规/定位/增长/战略/顺序/用户侧沉淀/测量/内容/时效/相关性"说到极深，但**整张圆桌漏了最致命的一环：前面所有"内容/时效/相关性"方案，都默认"有人工/有内容供给"，却没人回答"燃料从哪来、怎么持续、且不编造"**。我实地核验了站点，结论比想象更硬：

### ① 核心核验结论（实地，AI 新闻聚合视角的铁证）

我查了 `.github/workflows/`、`package.json`/构建配置、`index.html` 全站 grep、`README.md`、目录结构：

- **纯静态手写、零聚合管道**：无 `.github/workflows/`、无 `package.json`/`vite`/`gulp`/`Makefile` 任何构建配置；`README.md` 第 7 行明示"**不需要任何构建工具或数据源文件，所有内容直接手写进 HTML**"——**128 张卡全靠人工手写维护，没有任何采集/监控/聚合机制**。这是 #21 SOP 空转、#22 维护可见性告警的**物理根因**：人工精选不可持续，入口一变就失真。
- **零 AI 聚合 / 零 RSS / 零 feed**：`index.html` grep `聚合/爬虫/rss/feed/采集/数据源/抓取` **零命中**（命中的"AI"仅筛选标签示例、"百度"仅搜索引擎集成）——站点不聚合任何资讯，用户无"情报流"可订阅。
- **内容区空转 + 字段缺可信（与 #27/#28 互证）**：`blog/news/journal` 目录物理不存在（#27）；卡片字段（README 第五节）仅 `站序/分类/type/title/desc/media/tags/links`，**缺 #21 per-card 可信四要素**；`sitemap.xml` 无 `<lastmod>`（#28）；`self_meta.json` 仅 `title/description/keywords`（#28）。
- **"AI 智能"是一级导航分类却只挂人工链接**：`README.md` 第 5 行把"AI 智能"列为收录分类之一，但仅人工整理的链接列表，**无任何 AI 行业资讯/动态聚合**——本站自己就是"AI 导航分类"，却对 AI 动态零聚合， irony 拉满，也证明"聚合能力"在本站完全空白。

### ② 我认同的（接住前位）

- **#21 per-card 可信档案（来源/核验/失效）**：这是"可信"的数据底座；我补：**"核验"必须可自动化供给**——人工逐卡核不可持续，需聚合流水线定期回灌 `last_verified`/`status`（接 #28 `freshness.json`）。
- **#27 journal/ 内容区天然载体**：我补：**journal/ 最该由"聚合流水线"自动生成"官方入口变更情报"**，而非人工写一篇篇 blog（人工写 blog 是 #23 说的 premature scaling，聚合情报才是高频、可续的燃料）。
- **#28 时效流 + 零后端失效提醒**：我补：**流的内容来自哪？** 就是本棒的聚合流水线输出的 `freshness.json` + `journal/`——否则 #28 的"本周更新"是空壳。
- **#29 个性化相关性 + 可行动性**：我补：**"为你"排序需要信号**——本棒的热度评分（heat_score）× 相关性（relevance）就是 #29 流的排序燃料，避免 #28"全量流噪声劝退"。
- **#26 测量优先**：我补：**聚合本身也要被测量**——聚合命中率、误报率、人工守门通过率，否则"自动供给"会变成"自动编数据"（#19 伪数据舆情）。

### ③ 我补充的（AI 新闻聚合专属，别人没说的——本棒核心）

1. **"聚合 ≠ 生成"是本站生命线**：圆桌把"可信"当成静态属性（#21）与人工 SOP（#21 D5），却没人钉死**AI 参与的最危险动作是"编造/自动发布"**。AI 新闻聚合方法论的铁律就是：AI 只做**采集（多源拉取）/排序（热度评估）/去重（合并同事件）/摘要（压缩不增事实）**，**绝不生成事实、绝不自动发布**。每条聚合结果必须挂**可控源 + 多源印证数 + 过 #21 D5 复核闸门 + #24 公文审稿**，**人工守门才发布**。这是把"AI 新闻聚合专家"的"交叉验证"专业铁律，落成 #21 可信的流水线化硬约束——否则就是 #19 伪数据/伪官方舆情炸弹。
2. **构建期聚合，不破纯静态架构（绕过 #3 天花板）**：#3 网站开发专家说纯静态有天花板。但聚合**不必在运行期**——用 **GitHub Actions 定时（cron）跑脚本**：拉官方源 + 监测收录卡 URL 存活 + 抓公告 → 结构化 → 输出 `freshness.json`（接 #28）+ 生成 `journal/` 情报页（接 #27）→ 部署到 Pages。**聚合在构建期、运行期仍是纯静态**，零后端、零服务器成本，完美契合本站架构，也绕开 #17 PIPL（不涉个人信息）。
3. **六维分层监测 = #28 流的燃料工厂**：把"官方入口变更"拆成六源监测——① 官网公告/RSS；② 政府公报；③ 12345/热线知识库；④ 权威媒体转载；⑤ 网友标记失效（接 #28 `expiry_flag` / #26 真实聚合反伪数据）；⑥ 失效举报入口。每源至少一次扫描，多源印证才晋级"可信变更"，直接 operationalize #21 可信 + 喂饱 #28 流。
4. **热度评分 × 相关性 = #29 流的排序信号**：给每条情报打 1–5 星热度（多源报道/社区传播/权威性/影响面/争议/时效），再 × 用户画像相关性（#29），输出"为你排好的本周热门变更"——解 #28 噪声劝退、#29 无排序。
5. **聚合形态守合规红线（#6/#15/#18/#19）**：① 带 AdSense 的"资讯/情报"页须与政务内容**视觉与文案区隔**（#6/#15 广告不混政务）；② 每条注明"来源：XX 官网，非本站发布，请以官方为准"（#15/#18 不冒充、#21 指路不代办）；③ 爬官方源守 `robots.txt`（README 有 robots.txt）；④ 聚合的是**公开官方信息（非个人信息）**，PIPL 风险低，但发布页若用 #26 行为埋点仍须境内管道（#17）。

### ④ 我反对的

- **反对"让 AI 自动写/自动发站内资讯"（最危险误解）**：任何"AI 生成政务/民生内容直接上线"的设想都踩 #19 伪数据 + #21 可信塌房 + #15/#18 冒充官方三重雷。本棒钉死：AI 只采集排序去重摘要，**发布前必人工守门**。
- **反对"人工精选 128 卡就够"（轻反对 #21/#22 现状依赖）**：人工维护在入口规模化后必然失真滞后（#28 时效失真），必须上构建期聚合流水线回灌 `status`/`last_verified`，否则"可信"是会说谎的快照。
- **反对"聚合=堆更多链接"**：无来源、无去重、无热度的聚合 = 噪声（#29 噪声劝退）。聚合价值在"多源印证 + 排序 + 可溯源"，不在"量大"。

### ⑤ 往哪推一步

把"AI 新闻聚合方法论"落成一条**构建期 CI 流水线 + 守门红线**，织进前位四棒：**① 建 `scripts/aggregate`（cron 跑，六源采集 + 存活监测 + 热度排序 + 去重）→ 输出 `freshness.json`（#28）+ `journal/` 情报页（#27）**；**② 钉死"聚合≠生成"：每条挂源 + 多源印证数 + 过 #21 D5 + #24 公文审稿，人工守门才发布**；**③ 热度 × 相关性排序喂 #29 "为你"流**；**④ 扩展 #26 埋点加 `feed_view`/`expiry_alert_click`/`rec_from_feed` + 聚合质量指标（命中率/误报率/守门通过率）**。这是把 #21 可信、#25 沉淀、#26 测量、#27 内容、#28 时效、#29 相关性**六棒在"可自动供给、可溯源、守门才发"的维度一次性织成"替你盯着信息"的民生导航**——且全程纯静态、零后端、零 PIPL 个人信息风险。

## 三、专业深挖：我的 3 个问题及答案

> 注：这 3 个问题已同步追加到主问卷第 6 节「历届追加问题池」。

- **Q1. 站点 128 卡全靠人工手写"精选"（README 明示无数据源文件），在 #21 SOP 空转、#22 维护可见性告警下不可持续——AI 新闻聚合方法论（多源采集 + 交叉验证 + 热度排序 + 去重）怎么落地成"构建期 CI 流水线"，既给 #27 journal/ + #28 新鲜度流供"燃料"，又不破纯静态架构、不越合规红线？**
  - A1. 落地为**构建期聚合（不破静态）**：① 在仓库加 `scripts/aggregate.mjs`（或 py）+ `.github/workflows/aggregate.yml`（cron 每日/每周跑）；② 脚本做三件事——**a. 存活监测**：对收录卡 `links` 批量 HEAD/GET 探活，记录 200/301/404/域名变更 → 写 `status`；**b. 六源采集**：拉官方公告/RSS、政府公报、12345 知识库、媒体转载、网友 `expiry_flag`（#26 真实聚合）、失效举报，结构化提取"入口 X 于 2026-08 变更/疑似失效"；**c. 热度排序 + 去重**：每条打 1–5 星热度（多源/权威/影响/时效），同事件合并；③ 输出 `directory/<cat>/assets/json/freshness.json`（接 #28）+ 生成 `journal/index.html` 情报列表（接 #27 S6 骨架）；④ 部署到 Pages，**运行期仍纯静态**（绕过 #3 天花板）。合规：聚合公开官方信息、不涉个人信息（#17 低风险）；爬取守 `robots.txt`；输出页标"来源：XX 官网，非本站发布"（#15/#18/#21）。

- **Q2. "可信"是本站生命线（#21/#19），但 AI 聚合最危险的正是"生成/编造"——怎么把"聚合 ≠ 生成"钉成硬约束？AI 只做采集/排序/去重/摘要，每条必须挂可控源 + 过 #21 D5 复核闸门 + #24 公文审稿，人工守门才发布？怎么用 #26 测量"聚合准确率/误报率/守门通过率"防伪数据舆情？**
  - A2. 三道闸钉死"聚合≠生成"：① **产出形态约束**：脚本只输出"结构化事实行"（来源 URL + 变更类型 + 时间戳 + 多源印证数），**禁止大模型自由生成正文**；如需摘要，用"抽取式摘要"（摘官方原文句），不增事实；② **发布前守门**：`journal/` 与卡 `status` 变更**不直接上线**——PR 触发 #21 D5《内容可信核验规范》复核清单（来源类型/核验渠道/核验日期/失效周期四要素齐？多源印证≥2？）+ #24 公文审稿（无绝对化词/无官方暗示/责任边界清），**人工 approve 才 merge**；③ **测量防伪**：扩展 #26 指标——`agg_recall`（监测命中真实变更率）、`agg_false_alarm`（误报率）、`gate_pass_rate`（守门通过率）、`post_publish_flag`（发布后被网友标记失效数），看板预警"误报率 > 5% 即暂停自动流、转纯人工"（呼应 #26"无分母不拍板"+ #19 舆情熔断）。这样"自动供给"永远在安全栏内。

- **Q3. 聚合产出怎么既喂饱 #28 新鲜度流 + #29 "为你"相关性排序（heat_score × relevance 排序信号）、又用 #26 埋点（feed_view/expiry_alert_click/rec_from_feed）验证"聚合真驱动回访"，且发布形态守 #6/#15 广告与政务内容隔离、不冒充官方（#15/#18/#19）？**
  - A3. 体验侧：`freshness.json` + `journal/` feed 进 #28 首页"本周更新"流；每条带 `heat_score`（热度）× 用户画像 `relevance`（#29）排序，输出"为你排好的热门变更"，解 #28 噪声 + #29 无排序。验证侧：扩展 #26 事件 schema 加 `feed_view`（看了情报流）/ `expiry_alert_click`（点了失效提醒）/ `rec_from_feed`（从情报流点了推荐入口），看板监控"情报流 → 回访率""失效提醒 → re-find 率"，无 30 天分母不判成败（#26 治理红线）。合规侧：① 情报页与 AdSense **区块隔离 + 文案标注"以下为广告/以下为官方来源情报"**（#6/#15 广告不混政务）；② 每条"来源：XX 官网 · 非本站发布 · 请以官方为准"（#15/#18 不冒充、#21 指路不代办）；③ 爬取守 robots、聚合公开信息（#17 低风险）。这样"聚合"既喂时效/相关性、又闭环测量、还不越界。

## 四、点评 / 修改方案 / 发展方向

### 4.1 点评（现状：好在哪、问题在哪）

**做得好（AI 新闻聚合视角）**：
- 已有"红金白可信"品牌底座 + 分类筛选骨架——聚合情报可挂其上，不用重写；
- 圆桌已备齐"可信溯源（#21）+ 用户沉淀（#25）+ 指标（#26）+ 内容骨架（#27）+ 时效流（#28）+ 相关性（#29）"六块拼图，只差"**可自动供给、可溯源、守门才发**"的燃料工厂。

**有问题（AI 新闻聚合视角）**：
- 🔴 **零聚合管道**：无 CI/构建/采集，128 卡纯人工，不可持续（#21 SOP 空转物理因）；
- 🔴 **零来源标注**：卡与情报均无"来源 + 多源印证"，不可信不可溯（#21 可信塌房风险）；
- 🔴 **聚合=生成 风险未设防**：若未来上 AI 写稿，无守门闸 = #19 伪数据炸弹；
- 🟡 **#28/#29 流是空壳**：无燃料（freshness.json/journal/ 未生成），"本周更新/为你"无内容；
- 🟡 **无热度/相关性排序信号**：即便有流也噪声劝退（#28/#29 共病）；
- 🟡 **"AI 智能"分类零聚合**：自身 AI 分类却对 AI 动态零聚合（irony，证明聚合能力全空白）。

### 4.2 修改方案（改哪里 → 改成什么样 → 为什么，标优先级）

- **[高] 建构建期聚合流水线 `scripts/aggregate` + `.github/workflows/aggregate.yml`（cron）**：六源采集 + 存活监测 + 热度排序 + 去重 → 输出 `freshness.json` + `journal/`。为什么：解"人工不可持续"（本棒核心），喂饱 #27/#28/#29，且不破纯静态（绕过 #3 天花板）。
- **[高] 钉死"聚合 ≠ 生成"三道闸（产出形态 + 发布守门 + 测量熔断）**：脚本只出结构化事实行、禁自由生成；PR 过 #21 D5 + #24 公文审稿才 merge；误报率 > 5% 自动暂停。为什么：守 #21 可信生命线、防 #19 伪数据舆情，是本棒最锋利贡献。
- **[高] 每条聚合/卡补"来源 + 多源印证数"字段（接 #21/#27 字段表）**：卡与 journal 条目标"来源：XX 官网 · N 源印证 · 核验 2026-08"。为什么：把 #21 可信从口号变可溯证据（交叉验证落地）。
- **[中] 热度 × 相关性排序喂 #29 "为你"流**：`heat_score × relevance` 排"本周热门变更"。为什么：解 #28 噪声 + #29 无排序。
- **[中] 扩展 #26 埋点加 `feed_view`/`expiry_alert_click`/`rec_from_feed` + 聚合质量指标**：接 #26 看板，验证"聚合真驱动回访"且监控误报。为什么：本棒价值 + 安全可量化。
- **[中] 情报页与 AdSense 区块隔离 + "来源/非官方"标注**：接 #6/#15/#18。为什么：广告不混政务、不冒充官方。
- **[低] "AI 智能"分类补 AI 行业动态聚合（自证能力）**：用同流水线聚合 AI 周报/论文/政策。为什么：自身分类零聚合是讽刺，补上即示范。

### 4.3 发展方向（中短期 1–3 个月 / 长期半年以上）

- **中短期**：聚合流水线上线 → `freshness.json` + `journal/` 自动生成（人工守门后发布）→ #28 流 + #29 "为你"跑通 → #26 埋点 `feed_view`/`expiry_alert_click` 上线 + 聚合质量看板。目标：30 日内收录卡 `status` 自动回灌覆盖率 ≥ 80%、人工守门通过率 ≥ 95%、误报率 < 5%、情报流浏览率 ≥ 活跃用户 15%（待 #26 30 天分母校准）。
- **长期**："聚合 ≠ 生成 + 人工守门"成站点可信护城河（"每条都标来源、多源印证、变了有人告诉你"），把 #21 可信 + #25 沉淀 + #26 数据 + #27 内容 + #28 时效 + #29 相关性在"可自动供给、可溯源、守门才发"维度织成"替你盯着信息"的民生导航；构建期聚合成可复用 SOP（政务类导航通用），全程纯静态、零后端、零 PIPL 个人信息风险；误报熔断机制让"自动供给"永远在安全栏内，#19 伪数据舆情从设计上被排除。
