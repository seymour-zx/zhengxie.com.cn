## 一、通用问卷作答（题目格式对应主问卷第 3 节）

> 用户画像设定：一位 **区政务服务中心信息员（兼"怕存到旧版/怕发错材料"的办事群众双视角）**——日常用金山文档维护公示与官方入口库，最怕链接失效、最怕把内部材料误发外网。

### A. 你的用户画像
- A1. 28 岁，区政务服务中心信息员（女），日常维护公示栏 + 给群众指官方办事入口；也是普通网民。
- A2. 电脑为主（WPS / 金山文档写材料、管知识库），手机为辅（微信 + 用导航站查入口）。
- A3. 找东西：群众问"XX 证明在哪办" → 先翻自己的收藏夹 / 金山文档知识库找官方入口；自己用站则分类 + 搜索。

### B. 场景与现状
- B1. 上次找"异地就医备案"官方入口：先百度（前三条是广告 + 仿冒站），再问同事要了上次存的链接——结果那版已过期。约 8 分钟，全程最怕"存的是旧版"。
- B2. 我用金山文档自建了"办事入口库"，按事项打标签、设"有效期"、到期提醒；但站点的收录卡没有这概念，全靠人脑记，换设备或同事离职就断。
- B3. 最烦三点：① 文档 / 链接"不知道是不是最新版"；② 找得到却怕发错（内部材料误发外网）；③ 入口散在微信 / 收藏 / 文档，换设备即断。

### C. 第一印象与理解
- C1. 打开 zhengxie.com.cn：红金白、克制、有"官方感"的导航——比 hao123 干净、不像仿冒站。
- C2. 只看首页：一个"帮人找政协 / 政务官方入口"的精选导航，给办事群众用。
- C3. 最吸引："精选 / 官方入口"的承诺感；最想关：看不到"这条何时核验、来源哪、会不会过期"——和我最怕的"旧版 / 失效"直接撞。

### D. 体验与意愿
- D1. 用站找"省人社厅官网"：命中快、无广告干扰，好。卡点：卡片不显示核验日期 / 来源，我不敢 100% 信它长期有效（怕是旧版、怕已改版）。
- D2. 设首页意愿 **4/5**：能找站、无广告，但"可信"看不到证据 → 扣 1 分。
- D3. 广告可接受（政务入口旁别放竞品中介就行）；为"确保每条都最新 + 可溯源"，愿付一点（年费级）。
- D4. 向朋友介绍："一个专找政协 / 政务官方入口的站，每条都标了从哪来、啥时核验——比百度干净、比你自己存的链接靠谱。"

## 二、圆桌总结（综合之前所有答卷 + 自己的思考）

**认同什么**
- #38 把"可信"落成**表契约**（主键 + 可信列 + 总表 + `SCHEMA.md` + `validate.py`），并已在 `directory/_master/site_data.xlsx` 实跑成 32 列——这是地基，方向完全对。结构化真值源就该是机器读的一张表。
- #36 世界圣经"单一真值源"、#37 减法优先"先把已想清楚的压成 v1"、#22/#23 定位 / 客户关口——都同意。

**补充什么（我的核心增量）**
- **圆桌最大的盲区：只设计"系统"，不设计"系统产物的文档生命周期"。** #34 知识管理说"raw 文件散落、缺索引（本棒证主问卷第 7 节漏登 #32）、矛盾标注"——这正是文档管家天天处理的"文件没收拾"症状。圆桌 38 份答卷 md 命名靠 `{N}-{name}-{date}` 勉强统一，但**版本、检索、权限、归档、跨设备 / 多人协作全空**。
- **结构化真值与叙述性规范，要分两个仓库，别混。** #38 把"可信"编码进 xlsx（对，机器读）；但 #21 内容可信核验规范 / #24 公文审稿 / #36 世界圣经 / #16 改造清单 是**叙述性治理文档**——它们需要版本化、审阅留痕、权限分享、可检索，塞不进 xlsx 字段，也不该塞。正确分层（详见 4.2）：
  1. **结构化真值** = `site_data.xlsx`（机器读，#38 已建）；
  2. **叙述性规范** = 在线协作文档（人读 + 审阅 + 权限，single source of truth）；
  3. **过程留痕** = 答卷 md 归档（只读沉淀，检索索引）。
- **"可信"要可被外部验证，但后端逻辑不能泄露。** 文档管家给的解法：治理规范进**带权限的在线协作文档**——外部只看"已发布 / 可验证"视图，后端 schema / 校验脚本 / 白名单不对外分享（直消 #15/#17/#19 红线）。

**反对什么**
- 反对把 SOP / 世界圣经 / 改造清单也塞进 xlsx 或堆成无版本 md：重蹈 #34 说的"raw 文件散落、矛盾无人标"。规范是**文档**，该有文档系统的生命周期。
- 反对"规范写给人看、靠 PR 对齐"：#21/#24/#36 的规范应从"人记的 md"升级成"文档系统管的真值源"，构建期 CI 直接**读取文档**校验，而非人工事后比对。

**往哪个方向再推一步**
- 推一步 = **定义"站点治理文档生命周期 SOP"**：三类文档各自命名 / 版本 / 检索 / 权限 / 归档规则；叙事性规范进在线协作（single source of truth + 权限边界）；CI 从文档读规范跑校验。让"可信"从"表里可追溯(#38)"再进一层到"规范可审计、可被外部验证、且后端不泄露"。

## 三、专业深挖：我的 3 个问题及答案

> 已同步追加到主问卷第 6 节「历届追加问题池」。

- **Q1. 圆桌 1–38 棒已产出 38+ 份答卷 md + 改造清单 + 问卷本体 + 站点 README + 已落地的 32 列 `site_data.xlsx`/`SCHEMA.md`/`validate.py`——这批"决策与治理文档"用什么生命周期管（命名 / 版本 / 检索 / 权限 / 归档），才不会变成又一个没人翻的文件夹？给出一份可执行的文档管理 SOP。**
  - **A1.** 立"站点治理文档三层生命周期"：
    ① **命名规范**——`{类型}-{主题}-{YYYYMMDD}`（如 `survey-答卷-39`、`sop-可信核验-v1.2`、`schema-收录数据-v0`）；版本用 `vN.N` 语义化，不靠日期伪装版本。
    ② **检索 / 索引**——`agent-review-survey/INDEX.md` 做全量索引（补 #34 证漏登的 #32），每份文档一行：类型 / 主题 / 版本 / 责任人 / 状态（草稿 / 生效 / 归档）/ 链接；构建或人工发布前更新。
    ③ **归档**——生效文档留 `active/`，过期版本移 `archive/`（保留可回溯，不删），解决"改了旧版找不到"的痛点（我的 B1 场景）。
    ④ **整理**——文档管家"批量整理"纪律：发布前 `列出受影响清单 → 确认 → 移动`，避免误删 / 误覆盖（呼应治理铁律"首次修改需确认"）。
- **Q2. #21 内容可信核验规范 / #24 公文审稿 / #36 世界圣经 本质都是"叙述性治理文档"——它们该存在哪、谁写、怎么被构建期 CI 读取校验（single source of truth）、怎么版本化 + 审阅留痕？即把规范从"人记的 md"升级成"文档系统管的真值源"，与 #38 的结构化 xlsx 互补不分家。**
  - **A2.** 三份规范进**在线协作文档**（金山文档类），而非仓库裸 md：
    ① **single source of truth**——`世界圣经`/`可信核验规范`/`公文审稿模板`各一份在线文档，唯一可写入口；仓库里的 md 只放"导出快照 / 链接"，不反向改。
    ② **版本化**——在线文档自带版本历史；重大修订走"提议 → 审阅（#24 公文审稿模型）→ 发布"三步，发布即升 `vN.N`，旧版自动归档（治 B1"旧版"恐惧）。
    ③ **CI 读取校验**——构建期脚本拉取在线文档的"生效版"结构化段落（如"收口白名单""绝对化禁用词"），与 `site_data.xlsx` 的 `source_type` / 域名白名单对照；文档改了 → 下次构建自动生效，不靠人工 PR。
    ④ **与 #38 互补**——xlsx 管"每条数据长什么样"（结构化），在线文档管"规则与叙事"（人读 + 审阅）；两者通过 `SCHEMA.md` 指针互链，不分家、不互漂。
- **Q3. 这些治理文档（含由 xlsx 派生的 per-card 可信档案视图）要不要进在线协作文档做"多人可审 / 可评论 / 带权限分享 / 留痕"，还是锁在仓库？分享与权限边界怎么设，才既不泄露后端逻辑（#15/#17/#19 红线）又能让"可信"可被外部验证？**
  - **A3.** 分"对内 / 对外"双视图，权限分层：
    ① **对内视图（可审 / 可评论 / 留痕）**——运营者 + 审阅人（#24/#33 守门）可编辑、可评论、可看版本与责任人；这是"可信"的**内部守门工作台**。
    ② **对外视图（只读 / 可验证）**——只发布"已核验卡片的来源 / 核验日期 / 状态"为公开页（如 `/trust` 或 per-card 溯源弹层），**不含** 后端 schema、白名单脚本、校验逻辑（直消 #15/#17/#19"泄露后端 / 冒充"雷）。
    ③ **权限边界**——在线文档分享用"指定人 + 有效期 + 水印"，绝不" Anyone 永久链接"；对外可信页由构建期从 xlsx 派生（只读快照），与可写源隔离。
    ④ **留痕**——每条规范的"谁改、何时、为何"自动记录（在线文档版本 + 评论），外部验证时用户能看见"这条规范最后核实于 X 月"，闭环 #21"可信可被溯源"。

## 四、点评 / 修改方案 / 发展方向

### 4.1 点评（现状：好在哪、问题在哪）
- **好**：#38 已把结构化真值源落地（32 列 xlsx + `SCHEMA.md` + `validate.py`），"可信"在表层可追溯；答卷 md 命名基本统一。
- **问题（文档管家视角，按优先级）**：
  1. **治理文档无生命周期**——38 份 md 无版本 / 无索引 / 无归档（#34 证 #32 漏登），新人接不住；
  2. **叙述性规范与结构化数据混放**——SOP / 世界圣经 / 改造清单堆成裸 md，无版本、无审阅留痕、不可检索；
  3. **规范靠 PR 对齐**——#21/#24/#36 改了，构建不自动感知，靠人记；
  4. **权限 / 分享缺位**——"可信"想被外部验证，但后端逻辑与对外视图未隔离，碰 #15/#17/#19 红线。

### 4.2 修改方案（改哪里 → 改成什么样 → 为什么，标优先级）
- **【高·Phase 0·零后端·可逆】治理文档三层分型 + 命名 / 版本规范**：把文档分成「结构化真值(xlsx) / 叙述性规范(在线协作) / 过程留痕(答卷 md 归档)」；命名 `{类型}-{主题}-{YYYYMMDD}` + 语义化 `vN.N`。**为什么**：根除"raw 文件散落"（#34 症状），让新人 10 分钟接住（#36 连续性台账前提）。
- **【高·Phase 0】建 `agent-review-survey/INDEX.md` 全量索引**：每份文档一行（类型 / 主题 / 版本 / 责任人 / 状态 / 链接），发布前必更。**为什么**：补 #34 证漏登的 #32，检索从"挨个开"变"一表查"。
- **【高·Phase 1】叙述性规范进在线协作文档（single source of truth + 权限分层）**：`世界圣经`/`可信核验规范`/`公文审稿模板` 迁在线文档，对外只发"已核验卡片来源 / 日期 / 状态"只读视图，后端不分享。**为什么**：规范可版本化 + 审阅留痕 + 可被外部验证，且不踩 #15/#17/#19；与 #38 xlsx 互补不分家。
- **【中·Phase 1】CI 从文档读规范校验**：构建期脚本拉在线文档"生效版"结构化段落（收口白名单 / 绝对化禁用词），与 xlsx 对照。**为什么**：规范改了自动生效，不靠人工 PR（治 4.1 问题 3）。
- **【中·Phase 1】答卷 md 归档纪律**：生效留 `active/`、过期移 `archive/`（保留回溯）；发布前"列清单 → 确认 → 移动"（文档管家整理纪律 + 治理铁律）。**为什么**：治"旧版找不到"（B1）、防误删。
- **【低·Phase 2】跨设备 / 多人协作**：在线文档分享用"指定人 + 有效期 + 水印"，运营 / 审阅可评论留痕；per-card 可信档案对外视图由构建从 xlsx 派生（只读隔离）。**为什么**：把 #25/#35"跨设备可溯源"与 #21"可信可被外部验证"在文档层闭环。

### 4.3 发展方向（中短期 1–3 个月 / 长期半年以上）
- **中短期**：Phase 0（三层分型 + 命名版本 + INDEX 索引）Day 0–2 → Phase 1（规范迁在线协作 + 权限分层 + CI 读文档校验）Week 1–2。先让"治理文档自己被管好"，再谈上层 UI 徽章。
- **长期**：在线协作文档成"规范真值源"，与 #38 xlsx 互链成站点双底座（结构化 + 叙事）；配合 #26 埋点测"带来源 / 版本的卡 + 可验证规范页"是否真提升设首页意愿（D2），不符则回滚上层、保文档契约。
