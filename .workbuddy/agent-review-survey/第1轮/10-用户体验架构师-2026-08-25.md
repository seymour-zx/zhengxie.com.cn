## 二、圆桌总结（综合之前所有答卷 + 自己的思考）

我通读了全部 9 份答卷，作为**建议顺序的最后一位**，我的职责不是再添新视角，而是**收口**——把 9 份答卷收敛成信息架构层面可执行的方案，并给出整体改造路线图。三位前辈（用户调研专家、产品管理专家、用户体验研究员）已经反复确认了方向，我确认并落地：

**① 信息架构诊断：现在的 IA 是"分类中心"，用户是"任务型"——这是结构的根问题。**
我从架构角度看这个站：**用户 80% 是"我知道我要找什么"（任务型：找 XX 官网/找入口），20% 是"随便看看"（浏览型）**。而现有 IA 是纯"分类中心"（10 个分类 + 16 个频道页 + 卡片），任务型用户被迫先猜分类再找。我以县政协工作人员人设作答时，路径是"找'政协'分类 → 找 XX 省政协"——能用但绕。**架构层面的解法（低成本、高回报）：首页加"任务入口"双模式**——在保留分类（浏览模式）的同时，增加"我要办事 / 我要查政策 / 我要找工具"这类任务入口（我 Q1 详述），直接服务 80% 的任务型用户。

**② 分类与频道页是"两套组织"，必须明确分工。**
现状：首页 10 个分类（快捷筛选）与 directory 16 个频道页（垂类导航）并存，用户分不清"频道导航"和"分类筛选"的区别（我人设里也没有区分）。**分工建议**：首页分类 = 浏览模式的快捷筛选（保留现状）；频道页 = 垂类深度页（承载前位专家的"导语内容化"，成为 SEO/内容资产）——两者脱钩，频道页从"分类的副本"进化为"垂类的内容入口"。

**③ 多层级一致性：README 的骨架契约是稀缺资产，但要升级成"页面契约"。**
这个站最被低估的架构资产是 **README 里的 S1–S6 骨架契约**（导航页/中枢页/说明页/合规页/功能页/内容页六类骨架，各自的结构/资源引用/SEO 规范）——大多数站点没有这种文档。我的升级建议：① 把它从"README 手册"正式化为"页面契约文档"（每类页面的检查清单，新页面先查契约）；② **S6（内容页）契约要预定义**——blog/news/journal 一旦启动就是新骨架，现在定义好避免届时拍脑袋（README 已有雏形，落成正式契约）。

**④ 整体收敛：九份答卷的共识与路线图。**
九位专家的共识高度一致：定位 = 可信政务/机构垂类（弃通用导航）、技术债要清（bug/CLS/可维护性）、内容化是搜索出路、先验证再动手。我作为收口者，把全部建议按"能动手的顺序"排成路线图（见 4.3），并推荐下一位产品管理专家做最终拍板。

## 三、专业深挖：我的 3 个问题及答案

> 注：这 3 个问题已同步追加到主问卷第 6 节「历届追加问题池」。

- Q1. **导航站的 IA 应该按"分类"组织还是按"任务"组织？现有 10 分类结构的根问题在哪？**
  A1. **两者都要，但要有主次**：分类 = 浏览模式（适合"不知道找什么/随便看看"），任务 = 搜索模式（适合"我知道我要什么"——占大多数）。现有 IA 的根问题：① 10 个分类是"站方视角"（机构/政协/资讯媒体…），不是"用户任务"（办事/查政策/找工具）；② 任务型用户被迫先猜分类；③ 分类与频道页两套组织并存，心智负担。**方案：双模式 IA**——首页保留分类（浏览），增加一行任务入口（"我要办事/我要查政策/我要找工具/我要看资讯"），任务入口直接映射到对应分类/频道页（如"我要办事"→ 政务服务平台 + 机构频道）。低成本、不动现有结构，直接服务任务型用户。

- Q2. **找站任务的最短路径是什么？站内搜索、分类、频道页三者怎么分工？**
  A2. **最短路径 = 搜索直达**（用户心智默认，尤其政务人群习惯了百度）。三者的分工：**站内搜索 = 主路径**（负责"找"，必须永远可见——sticky 已满足；搜索词要匹配"用户语言"，呼应收口搜索词分析师的对照表）；**分类 = 浏览路径**（负责"逛"，保留现状）；**频道页 = 深度路径**（负责"垂类深耕"，导语内容化后成为内容资产，不再只是分类的副本）。关键设计动作：搜索结果与分类结果合并展示（已有）、扑空出口（"没找到"反馈，产品专家方案）、搜索词打点（搜索词分析师方案）——三者串成"找-反馈-修正"闭环。

- Q3. **多层级站点（首页/频道页/子页/文章）的一致性由什么保证？现在的风险在哪？**
  A3. 一致性 = **骨架契约（README S1–S6）+ 设计 token（CSS 变量）+ 导航/页脚模板**三层保证。现在的风险：① 频道页与首页复用同一 S1 骨架，随着频道页内容化（导语/文章）会逐步漂移出骨架；② S6 内容页（blog/news/journal）契约只存在于 README 一句话，未落地，启动时会拍脑袋；③ 子页（pages/）与频道页的页脚导航/面包屑一致性未做全站核查。**建议**：① 骨架契约升级为"页面契约文档"（每类页面：结构/资源引用/SEO/导航/新增检查清单）；② 预定义 S6 内容页契约（文章布局/资源/SEO/上一篇下一篇）；③ 做一次全站一致性核查（面包屑位置、页脚导航、sticky 行为）。

## 四、点评 / 修改方案 / 发展方向

### 4.1 点评（现状：好在哪、问题在哪）

**做得好（架构层）**：
- **README 骨架契约（S1–S6）是稀缺资产**：大多数站点没有"每类页面怎么搭"的成文规范，这是这个站的架构底子；
- **CSS 变量体系 = 设计 token 雏形**：色彩/字体/间距/圆角/阴影全变量化，为"视觉宪法"打好了地基（UI 专家方案可直接落地）；
- **URL 结构清晰**：`/directory/xx/` 频道、`/pages/xx/` 子页、根 assets 单一真源，层级规范；
- **资源引用与 SEO 契约完整**：子页 `../../assets`、canonical/面包屑/JSON-LD 全站统一。

**有问题（架构层）**：
- 🔴 **IA 是"分类中心"而非"任务中心"**：80% 任务型用户被迫走浏览路径；
- 🟡 **分类与频道页两套组织并存**：分工不明，心智负担（我人设也无法区分）；
- 🟡 **S6 内容页契约未落地**：blog/news/journal 启动即拍脑袋；
- 🟡 **骨架契约停在 README 手册**：没有可执行的"页面契约/检查清单"；
- 💭 全站导航模板（页脚/面包屑/sticky）一致性未核查。

### 4.2 修改方案（改哪里 → 改成什么样 → 为什么，标优先级）

- [高] **双模式 IA（任务入口）**：首页分类行上方加一行任务入口（"我要办事 / 我要查政策 / 我要找工具 / 我要看资讯"），映射到对应分类/频道页。为什么：直接服务 80% 任务型用户（我的 Q1），低成本不动现有结构。
- [高] **分类与频道页分工明确化**：首页分类 = 快捷筛选（现状不动）；频道页 = 垂类内容页（导语内容化后与分类脱钩）。为什么：消除"两套组织"的心智负担（我的 Q2）。
- [中] **页面契约文档化**：把 README 骨架契约升级为独立"页面契约文档"（S1–S6 每类：结构/资源引用/SEO/导航/新增检查清单），新页面先查契约。为什么：架构资产从"手册"变"可执行规范"（我的 Q3）。
- [中] **预定义 S6 内容页契约**：blog/news/journal 启动前，定义文章页骨架（布局/资源引用/SEO/上一篇下一篇/列表页）。为什么：避免内容区启动时拍脑袋（我的 Q3）。
- [中] **设计 token 文档化**：CSS 变量整理为正式 token 体系（色板/字体阶/间距/圆角/阴影 + 亮暗对照），作为"视觉宪法"（呼应 UI 专家）。为什么：新增页面不跑偏。
- [低] **全站导航一致性核查**：页脚导航/面包屑/sticky 行为全站核对统一。为什么：多层级一致性是"可信感"的结构支撑。

### 4.3 发展方向（整体改造路线图 · 收口整合九份答卷）

**第一优先 · 立即（1–2 周，零/低风险）**：
① 代码审查专家的 2 个 🔴 bug（搜索高亮破损、favToggle 判空）+ 🟡 项（大小写/focus 对比度/background-clip 回退）；② UI 专家的 7 项 CSS 修复；③ 站内搜索打点（GA4 事件，搜索词分析师的免费数据源）。

**第二优先 · 3–4 周**：
① 用户体验研究员的 3 周最小验证（5 访谈 + 10 任务测试 + 打点数据）——**先验证再动手**；② 定位对齐文案（meta/hero/分类顺序，产品管理专家 + SEO 专家方案）；③ 频道页导语内容化起步（SEO/搜索词/独立站三位的共识项）。

**第三优先 · 1–2 月**：
① 双模式 IA（任务入口，本答卷方案）；② 收藏导出（开发专家方案）；③ "没找到"反馈入口（产品/搜索词方案）；④ 广告信任分级（独立站方案）。

**第四优先 · 2–3 月+**：
① 备案评估（独立站方案）；② blog 办事指南文章 + FAQPage（SEO/搜索词方案）；③ "官方认证"标记（独立站方案）；④ 页面契约 + 设计 token 文档化（本答卷 + UI 方案）。

**总原则**：先清技术债 → 跑验证拿数据 → 用数据校准定位与 IA → 再上内容化与商业化。
