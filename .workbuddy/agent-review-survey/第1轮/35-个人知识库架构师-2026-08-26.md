### ③ 我补充的（PKM 专属，别人没说的——本棒核心）

1. **"书签 ≠ 知识，布尔星标更不是"——这是 PKM 的第一性原理**。本站的 `zx_favs={url:true}` 和用户的 200+ 乱书签，本质是同一病：**只存"在哪"，不存"为什么、和我什么关系、下一步干嘛、和别的什么连"**。PKM 把每张收藏变成原子笔记（只装"一个入口 + 我为什么存 + 我打算用它干嘛"），让"找到"变"知识"。
2. **Zettelkasten 原子化**：每张收藏卡 = 一个原子笔记（唯一 ID + 只讲一件事）——"政协官网"是一张、"我的考公资源"是另一张，互不塞；避免 #25"标签大杂烩"退化为又一堆死标签。
3. **PARA 分类（比扁平标签更懂用户）**：用户收藏按 **项目（如"办居住证"）/ 领域（如"政务办事"）/ 资源（如"常用工具"）/ 归档（如"已办完"）** 组织——这是 Obsidian/Notion 验证过的"有截止日期=项目、持续负责=领域、感兴趣=资源、不活跃=归档"四层，比 #25 的扁平标签更贴近"用户真实心智"，也直接喂 #29 画像（PARA 即最天然的画像信号）。
4. **LYT 双向链接 + MOC（让收藏长成网络，而非堆）**：收藏间建双向链接（"政协官网"↔"民主党派官网"↔"我的办事指南"），用 MOC（内容地图 / Map of Content）索引过大的收藏夹——#25 没做"连接"，#34 做了组织侧交叉引用但用户侧空白；我补用户侧"链接你的思考"。
5. **导出为可复用格式（接 #20 分享楔子 + #25 导出）**：当前 `zx_favs={url:true}` 连导出都只是 URL 列表；PKM 应导出**带语义的 Markdown**（每张卡 = 一行笔记，含来源/标签/备注/双向链接），可一键进 Obsidian/Notion 真正变成用户第二大脑——把 #20"收藏即分享"从"分享页"升级为"分享我的知识网络"。
6. **"第二大脑" vs "死书签"的本质区别**：书签只存"在哪"，PKM 存"为什么、和我什么关系、我下一步干嘛"——这恰好接 #29 `why_relevant`/`next_step` 和 #21 per-card，让"收藏"与"可信/可行动"对齐。
7. **零后端 MVP 即可起步**：localStorage 结构从 `{url:true}` 升级为 `{url, title, note, why, next, tags[], para, links[], savedAt, sourceSnapshot}`（复用 #21 四字段 + #34 实体页），导出生成 Markdown——纯前端、零后端、零 PIPL（呼应 #3/#17/#23），不破纯静态架构（#3）。

## 三、专业深挖：我的 3 个问题及答案

> 注：这 3 个问题已同步追加到主问卷第 6 节「历届追加问题池」。

- **Q1. 用户用这个站"找到"的官方入口，当前只被存成 `zx_favs={url:true}`（main.js:244 实测）的布尔星标——怎么用 Zettelkasten（原子笔记）+ PARA（项目/领域/资源/归档）+ LYT（双向链接 + MOC）方法论，把"一次性收藏"升级为"会连接、可复用、越用越懂我的个人第二大脑"，而不只是 #25 说的"标签+导出+同步"容器？**
  - A1. **PKM 方法论落地，而非功能堆叠**：① **原子化**——每张收藏 = 唯一 ID 原子笔记 `{id, url, title, note, why, next, savedAt, sourceSnapshot}`，`why/next` 接 #29、`sourceSnapshot` 复用 #21 四字段（来源类型/核验渠道/核验日期/失效周期）；② **PARA**——用户收藏归入"项目(如办居住证)/领域(如政务办事)/资源(如常用工具)/归档(已办完)"，PARA 即最天然画像信号（喂 #29）；③ **LYT 双向链接 + MOC**——收藏间建 `[[政协官网]]↔[[民主党派官网]]` 链接，用 MOC 页索引过大收藏夹（补 #25 缺的"连接"层）；④ **导出**——生成带语义 Markdown（每张卡=一行笔记含链接/标签/备注/双向链接），一键进 Obsidian/Notion（接 #20 分享 + #25 导出）。这样收藏从"布尔值"变"第二大脑"——**这是 #25 没做的"连接与复用"层，本棒核心补刀**。

- **Q2. #34 建了"站点运营侧 LLM Wiki"（每卡实体页带来源/责任人/核验日期/status），但用户侧"个人 PKM"怎么和它结构同源、形成"组织维护可信 ↔ 用户沉淀知识"双螺旋，又不踩 #15/#17/#18/#21 指路不代办与 PIPL？**
  - A2. **双螺旋同源架构**：① **同源字段**——用户每张原子笔记的 `sourceSnapshot` 直接引用 #34 运营库每卡实体页（URL+来源+核验日期+status），**用户存的"可信"= 运营真在维护的可信**（#34 同源，从设计上排除 #19 伪数据舆情）；② **单向引用不越界**——个人笔记只"引用"运营库 URL，绝不"代办/代解读"（锁死 #21 指路不代办、#15/#18 不冒充）；③ **隐私最小化**——个人 PKM 全在 localStorage / 用户自有 Obsidian，**不含任何个人信息出境**（弃 GA4、用境内或本地，接 #17），导出 Markdown 不含运营库责任人姓名（#34 已脱敏）；④ **保鲜联动**——#34 运营库 `status=失效` 时，用户个人笔记里引用该卡的自动标"来源可能失效，请于官方核实"（接 #28 失效提醒飞轮）。这样组织库与个人库结构同源、可信闭环、合规不越界。

- **Q3. 个人 PKM 怎么既驱动 #2/#20 回访飞轮（让"收藏"从一次性变"持续积累"）、又用 #26 埋点验证"用户真在沉淀知识而非点了一下星标"、且不踩 #17/#24 合规？**
  - A3. **飞轮 + 度量 + 合规三件套**：① **飞轮**——原子笔记(why/next) + 双向链接 + PARA 让收藏"越用越懂我"，回访从"找入口"变"看我的知识网络"（接 #2/#20 回访率、#25 save-rate/re-find-rate）；② **度量（扩展 #26 事件）**——从 `fav_add`(布尔) 升级为 `note_add`(原子笔记数)/`link_add`(双向链接数)/`para_move`(PARA 分类迁移)/`note_tag`(打标签)/`pkm_export`(导出第二大脑)/`moc_open`(MOC 地图访问)/`refind_note`(回访某笔记)；指标 `pkm_active_rate`(有≥3 原子笔记用户占比)/`link_density`(平均每张卡链接数)/`para_adopt_rate`(PARA 使用率)/`export_rate`(导出率)/`note_reuse_rate`(笔记被回访复用率)——**测量"用户在真沉淀知识"而非"点了一下星标"**（呼应 #26"无 30 天分母不拍板"）；③ **合规**——PKM 数据全本地/用户自有，零 PIPL 出境（接 #17）；导出文案/原子笔记模板经 #24 公文审稿；"指路不代办"锁死（#21/#15/#18）。这样"个人第二大脑"既驱动回访、又可被测量、且不越界。

## 四、点评 / 修改方案 / 发展方向

### 4.1 点评（现状：好在哪、问题在哪）

**做得好（PKM 视角）**：
- 卡片已是极佳"原子笔记素材"：每张卡有 `title`/`desc`/`tags`/`data-key=URL`/`card__fav`（main.js:139），且 #21/#34 已设计 per-card 可信字段——**知识原材料齐备，只差"用户侧 PKM 组装层"**；
- 纯静态 + 前端 localStorage 技术取向（#3/#30）与 PKM"本地优先"天然契合，零后端即可起步。

**有问题（PKM 视角）**：
- 🔴 **用户收藏 = `{url:true}` 死数据（main.js:244 实测）**：零语义、零结构、零连接、零复用；
- 🔴 **站点零 PKM 基础设施**：grep 个人知识库/双向链接/MOC/Obsidian 零匹配，C 侧无"我的知识库"入口；
- 🟡 **圆桌口径分歧**：#32"localStorage 仅 zx_theme"错（有 zx_favs），本棒以源码纠正；
- 🟡 **#25 只到功能层**：个人知识库缺"原子化+双向链接+PARA+MOC"方法论，会退化为死标签。

### 4.2 修改方案（改哪里 → 改成什么样 → 为什么，标优先级）

- **[高] 收藏结构升级（破 `{url:true}` 死数据）**：`main.js` 的 `favs[key]=true` → `favs[key]={url,title,note,why,next,tags[],para,links[],savedAt,sourceSnapshot}`，还原逻辑同步（668–673 行）。为什么：把布尔星标变原子笔记，是 PKM 第一性原理（本棒核心）。
- **[高] 加 PARA 分类 + 双向链接 + MOC**：收藏面板支持"项目/领域/资源/归档"四区 + 笔记间 `[[链接]]` + "我的地图"MOC 页。为什么：让收藏长成网络而非堆（补 #25 连接层）。
- **[高] 导出带语义 Markdown（接 #20/#25）**：一键导出 Obsidian/Notion 可用笔记（含来源/标签/备注/链接）。为什么：收藏→第二大脑，把 #20 分享楔子从"分享页"升级为"分享知识网络"。
- **[中] 复用 #21/#34 可信字段作 sourceSnapshot**：个人笔记引用运营库每卡实体页（URL+来源+核验日期+status）。为什么：组织库↔个人库双螺旋、可信同源（#19 伪数据从设计排除）。
- **[中] 扩展 #26 PKM 埋点**：`note_add/link_add/para_move/pkm_export/moc_open/refind_note` + 指标 `pkm_active_rate/link_density/para_adopt_rate/export_rate/note_reuse_rate`。为什么：测量"真沉淀"而非"点星标"。
- **[低] 纠正圆桌口径**：#32"localStorage 仅 zx_theme"→ 实为 `zx_favs`+`zx_theme`（本棒已证）。

### 4.3 发展方向（中短期 1–3 个月 / 长期半年以上）

- **中短期**：收藏结构升级（原子笔记字段）→ PARA 四区 + 双向链接 + MOC 页 → 导出 Markdown（Obsidian/Notion）→ #26 PKM 埋点上线。目标：pkm_active_rate（有≥3 原子笔记用户占比）≥ 20%、link_density（平均每张卡链接数）≥ 0.5、export_rate ≥ 5%、note_reuse_rate（笔记被回访复用率）≥ 30%（待 #26 30 天分母校准）。
- **长期**："找到→沉淀→连接→复用→回访"成站点 C 端护城河——把 #25 收藏命题、#29 画像、#21 可信、#34 运营库在"用户侧会连接、可复用的第二大脑"织成双螺旋；用户看到的可信=运营真在维护的可信（#19 伪数据舆情从设计排除）、用户沉淀的知识=越用越懂自己的第二大脑（#2/#20 飞轮 C 端闭环）；全程纯前端、零后端、零 PIPL 个人信息风险。
