## 二、五道裁决题（选边 → 理由 → 给反方最有说服力的挑战）

### 裁决 1｜定位：共识还是确认偏误？

**选边：C（方向可留，但"给谁用"必须先用最小成本验证）**

- **理由（数据视角）**：站点的"自称"与"内容"已经对齐（事实 1：meta/OG/JSON-LD/分类 100% 一致），第 1 轮的一致性争议**已闭环**。但"自洽"只证明站点内部逻辑成立，**不证明外部需求成立**——337 张卡片的收录依据是"我们觉得该收"，不是"用户找过"。而当前**全部观测通道都是零**（#26 实测：业务埋点为零；事实 3：扑空不回流），意味着"垂类定位成立"这个判断**没有任何可证伪的数据支撑**。11 位专家一致，恰恰说明这是需要外部基准来证伪的判断——这正是 #12 的担忧，我作为测试分析师从"可测量性"角度给出同样的结论：**没有基线的共识，本质是未验证的假设**。
- **给反方的挑战**：**如果 C 的验证窗口期内证明垂类不行，站点等于全站重构**——337 张卡片、11 个分类、SEO 结构全部按垂类重新设计，成本远高于"现在先验证"。反方（A 直接执行）最有力的反驳是：垂类已经是既成事实（第 1 轮后已落地），验证的边际价值可能低于直接跑起来从真实搜索词里学；但正因为"已压上全部筹码"，才更该先花一周验证筹码押对了没有。

### 裁决 2｜改名：改 / 留名 / 先测误认率？

**选边：C（先测误认率再决）**

- **理由（统计视角）**：改名是**不可逆高成本动作**（域名、外链、SEO 权重、收录全部重来），不能基于"觉得像官方"这种主观感受拍板。误认率是**可测量的指标**：给目标用户看站点在真实搜索场景下的呈现（标题 + 域名 + 摘要组合，而非孤立截图），问"这是官方站吗"。测量设计要点：① 呈现方式必须模拟真实搜索上下文（孤立截图会高估误认）；② 用 #22 的 Kill Conditions 预注册判定阈值——**建议 ≥30% 触发改名评估、<15% 可留名、15–30% 走留名重塑**；③ 样本 30 份即可出方向性结论（比例估计的 95% 置信区间 ±18% 内），够决策、不浪费。
- **给反方的挑战**：反方（B 留名重塑）最有力的反驳：**合规风险不等人**——#15 已判定存在"冒充官方"风险，法律意见可能要求立即动作，测量窗口（1–2 周）里若真有投诉/函件，就是 #22 说的"官方函件触发即更名"，测了也白测。但我的回应是：测量和合规动作不冲突——**先按 B 做留名重塑的最低合规动作（角标 + 免责声明，成本几乎为零），同时并行测误认率**，测出 ≥30% 再上改名，两边都不耽误。

### 裁决 3｜可信最小版：1 周能上线的最小可验证版本？

**选边：B（全量卡片挂"来源类型 + 核验日期"标签，数据已在 32 列 schema，只差渲染）**

- **理由（实验设计视角）**：A（1 张卡 demo）**只能验证"渲染技术通不通"，不能验证"可信标签是否提升信任"这个商业假设**——1 张卡做不了对照实验，样本和曝光都不够。C（免责声明/角标）是合规基线，**应该做、且成本最低**，但它产生不了"用户可感知的信任差异"，无法被测量，也就回答不了裁决 1/4 的问题。**B 是唯一能同时支撑"上线"和"测量"的选项**：数据已在 32 列（事实 2 实锤只差渲染），A/B 对照天然可行（有标签 vs 无标签两组卡片），且与裁决 4 的验证方案直接复用同一套实验。
- **给反方的挑战**：反方最有力的反驳：**数据质量可能是 B 的致命伤**——#38 实测过 desc 空 83%、media 空 89%，如果 `verify_date` / `source_type` 同样大面积空值，全量渲染等于把"数据没准备好"暴露给用户，**反而伤信任**（"核验日期：空"比没有标签更糟）。我的回应：B 的前提是**先跑数据完整度检查，缺字段的卡片不渲染标签**（#38 的 SLA 闸门正是为此设计）——这是执行顺序问题，不改变 B 是唯一可测选项的结论。

### 裁决 4｜验证顺序：最值得先验证的一条？

**选边：B（"带来源的卡片真能提升信任、驱动回访"）+ 附一条补充：B 和 C 可合并为一个实验**

- **理由（可测性视角）**：三条候选假设里，**B 是唯一有"操作变量"和"观测指标"都明确的**——操作变量：渲染/不渲染可信标签；观测指标：任务成功率、信任评分、回访意愿。A（客户关口"有人真的需要"）更基础但**最难测**（要访谈 30 个目标用户，成本高、周期长，且访谈本身有自我报告偏差）；C（扑空即流失）**缺观测通道**（事实 3：扑空不回流，先要补埋点，那是开发活不是验证活）。所以顺序是：**先 B（1 周，A/B 实验）→ 顺手补 C 的扑空埋点（1 个事件，成本极低）→ 再 A（B 的结果本身就是 A 的试金石：如果可信标签无效，说明用户要的不是"信任标记"，客户关口大概率也过不了）**。
- **给反方的挑战**：反方最有力的反驳：**B 的 A/B 在 10–15 人样本下统计功效极低**——两组各 7–8 人，任何差异都达不到统计显著（n=8 时连 1 分的均值差都测不出 0.8 功效）。我的回应：**这正是为什么要预注册阈值 + 同时测行为和态度**——"信任评分提高 ≥1.0 分"这种阈值在 n=15 时虽不显著，但作为**方向性信号**足够触发 go/no-go；而且任务成功率是行为数据，比态度问卷更抗偏差。测试的目的不是发论文，是**在最低成本下拿到足够决策的方向信号**——这就是"够决策、不浪费"的标准。

### 裁决 5｜广告与内容边界：边界画哪？内容区第一个做什么？

**选边：A（政务类页面全禁广告 + 内容区先做"办事指南/入口核验"类长尾）**

- **理由（可测量视角）**：政务页禁广告是 #6/#15/#17 的既有共识，执行成本低、无争议，且**可验证**——禁了之后监控站点信任相关信号（误认投诉、跳出率）即可。内容区先做"办事指南"类，因为它有**明确的搜索意图映射**（用户搜"XX 省政协提案查询""XX 政协官网"），可以被 SEO 测试直接测量（收录、排名、点击），而 B（入口变更情报）依赖 #30 的聚合流水线（**未建的工程**），在验证窗口内根本无法上线测量。**先做能测的，再做要等的**。
- **给反方的挑战**：反方最有力的反驳：**禁广告 = 放弃 AdSense 现金流**，对一个纯静态个人站是实打实的收入损失；且"政务页"边界本身模糊（首页算不算政务页？频道页算不算？），定义不清会执行扯皮。我的回应：边界问题恰恰可以用**测试来定义**——广告只在"用户做可信判断的页面"禁（涉及官方入口跳转的卡片区），在纯工具/资讯区保留，先按这个粗略规则跑一周看有没有踩雷信号，再收紧。**用数据定边界，比开会定边界快**。

## 三、问题池回收（认领 1 题作答）

**认领：第 1 位（用户调研专家）Q1 ——「用户来导航站的'真实任务'是什么？怎么验证'任务完成'而不是'页面停留'？」**

**我的作答（测试分析师版）**：真实任务 = **"带着具体找站需求进来，带着可核验的成果离开"**——用户不是来"逛"的，是来完成一个找站动作的。验证"任务完成"不能看停留时长（停留长可能是迷路），要看**行为证据链**，我给出可落地的三件套：

1. **任务定义**：把"找站"拆成可判定的原子动作——搜索/筛选 → 点开卡片链接 → 到达目标站 → （可选）返回收藏。**"完成"= 点开目标链接且不立刻返回**（返回 = 找错站）。
2. **观测指标**（事件级埋点，#26 的 find-rate 落成可算定义）：
   - **任务成功率** = 完成动作数 ÷ 发起搜索/筛选次数（这是"完成"的替身，行为而非态度）；
   - **任务耗时** = 从输入到点开链接的秒数（>60s 视为卡住）；
   - **一次找到率** = 首次点开即不再返回的比例（这是"找对"的最强信号）。
3. **验证方法**：10–15 个真实用户 × 5–8 个真实找站任务（如"找到你所在省政协官网"），观测这三项，**预注册阈值：任务成功率 ≥70%、一次找到率 ≥50%** 才算"任务完成"成立；不达标即"扑空/迷路"占主导，定位要回炉。

核心观点：**"页面停留"是虚荣指标，"任务完成"是行为证据——只要埋点没补，两者都测不了，这就是为什么事实 3 的扑空回流必须和验证一起做。**

## 七、用户评价与裁决 3 修正（2026-08-29 补记）

> 用户在 #40 棒作答后给出**决策 + 设计原则**，要求录入答卷底部。此评价**直接推翻了我原裁决 3 的选边 B（全量挂标签）**，故先录原话要点，再给修正。

### 7.1 用户对「可信档案列」的决定（已决，非投票项）
- `verification_*` / `source_type` / `verify_date` 等列：**决定删除，或仅作为 xlsx 内部数据使用**；
- py **不加工这些列进 html**；
- **不渲染给客户**——板上钉钉。

### 7.2 用户对「可信」的定位（已决，非投票项）
- 可信的建立应定位在**用户对「整个网站」的信任**，不是单独某个页面、卡片、链接。

### 7.3 用户的逻辑（标记悖论，原话要点，须录入）
1. 若可信定位在「某页面 / 卡片 / 链接」级 → 那是不是**每个**页面、卡片、链接都该标记？
2. 若都标记 → 等同**无差别标记**，属于**重复类噪音**。
3. 若不是每个都标记 → 未标记的会不会**降低用户信任**，且用户会质疑「不可信的为什么出现在这里」，进而**质疑整站可信度**。

> 推论：逐卡 / 逐链接标记在逻辑上不成立（要么全标成噪音，要么漏标反噬整站），所以可信只能落在整站级。

### 7.4 对我答卷的修正（作废 + 新立场）
- **原裁决 3 选边 B（全量挂标签）作废**：其前提「把可信落在卡片级」被 7.2 用户决策推翻；原 §五 的「卡片级标签 A/B 实验」同步作废。
- **新立场：可信 = 整站级信号**，由以下构成且都**可观测**：
  - 页脚免责 + 「独立第三方」定位（事实 2 已落地，属合规基线）；
  - about 页讲清「是什么、不是什么、怎么用」；
  - 分类 / 收录的**一致策展**（事实 1 已自洽）；
  - 来源透明（链接露真域名，事实 2 已落地）。
- **验证焦点转移**：从「逐卡信任评分差」转为「整站信任评分」——单题量表测「整站声明文案 vs 无声明」的 A/B；并与裁决 2 的「误认率」共用同一批样本（误认率低 + 整站信任高 = 垂类定位成立的可测证据）。
- 与我原「先跑数据完整度闸门」的担心**一致**，但闸门对象从「逐卡字段」转为「整站可信信号的完整与一致」；`verification_*` 列是否保留为内部 xlsx（7.1）不影响这一原则——**内部数据可留，渲染给客户不可有**。

### 7.5 对活母本 §8 裁决 3 的影响（建议，待用户 / 文档管家拍板）
- 原 §8 裁决 3 三选项（A 1 张卡 demo / B 全量挂标签 / C 仅免责）均建立在「卡片级」前提上；用户决策使这三个选项**全部 moot**。
- 建议将 §8 裁决 3 改写为：「可信的最小可验证版本 = 整站级信号（页脚声明 + about + 一致策展 + 来源透明），验证『整站信任评分』，不渲染逐卡标记」，并标注「**用户已决：verification_* 列不渲染、可信 = 整站级**」。
