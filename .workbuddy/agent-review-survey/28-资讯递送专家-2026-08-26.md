## 二、圆桌总结（综合之前所有答卷 + 自己的思考）

我通读了第 1–27 位。圆桌把"可信/非官方/合规/定位/增长/战略/顺序/用户侧沉淀/测量/内容"说到极深，但**整张圆桌漏了"时效（timeliness）"这一根柱子**——而它恰恰是导航站"帮人找对官方入口"的核心价值载体。我实地核验了站点，结论比想象更硬：

### ① 核心核验结论（实地，资讯递送视角的铁证）

我查了 `index.html` 首页渲染、`pages/changelog/`、`sitemap.xml`、`directory/<cat>/assets/json/self_meta.json`：

- **首页无用户侧资讯流**：`index.html` 仅 231 行 footer 有"更新日志"链接，首页**零**"最新资讯/动态/本周新增/刚核验"呈现。用户打开站，看不到"最近收录了什么、哪些入口刚核验、哪些热线刚变更"——导航站对"官方入口时效性"价值最大，却完全不呈现。
- **更新日志只记"站点自身迭代"**：`pages/changelog/index.html:7` 描述为"记录站点分类、功能、页面与合规相关的迭代历史"——这是站内自我表扬，**不记录外链资源的新鲜度/失效/变更**，不是用户要的资讯。
- **sitemap.xml 缺 `<lastmod>`**：26 个 URL 有 `changefreq`（weekly/monthly）但**无 `<lastmod>` 时间戳**（实地逐行核验 sitemap.xml 全文 1–133 行）——搜索引擎侧也缺新鲜度信号，抓取频次与"内容是否更新"解耦（SEO 新鲜度漏洞，接 #6/#7 长尾 + #26 数据资产盘点）。
- **卡片数据无新鲜度字段**：频道 `self_meta.json` 仅 `title/description/keywords`（实地读取 `directory/ai/assets/json/self_meta.json`）；收录条目（xlsx，15 个）字段（README 第五节）仅 `站序/分类/type/title/desc/media/tags/links`——"新鲜度/复核状态"在数据结构层**无落点**，与 #21 per-card 可信档案缺失、#26 数据底座缺字段、#27 字段表缺项**三方互证**。
- **无 RSS/订阅/回推**：站点无 feed、无订阅机制、无"收藏入口变更提醒"——用户无法"订阅某分类更新"，更无法被通知"你存的入口变了"，**直接断 #25 用户侧知识库的"失效提醒"飞轮**。

### ② 我认同的（接住前位）

- **#21 per-card 可信档案（来源/核验/失效）**：这是"新鲜度"的数据底座；我补：**"核验日期"必须会流动**——加 `review_cycle`（复核周期）+ `status`（有效/待复核/疑似失效），否则"可信"是静态快照、会过期失真（呼应 #26 禁硬编码）。
- **#25 用户侧知识库 + 失效提醒飞轮**：收藏存的是 URL，存的那一刻就"定格"；我补：**缺失的是"递送管道"**——站点须有机制把 per-card `status` 变化回推给用户本地收藏（零后端可做）。
- **#26 真实行为聚合反伪数据**：把"已被 N 人标记失效"真实呈现，比口号可信；我补：`expiry_flag` 类聚合是新鲜度的最强证据（群众雪亮）。
- **#27 journal/ 内容区天然载体**：README 规划了 `journal/`（日记/动态）却没建；我补：**journal/ 最该承载"官方入口变更情报"**，比一次性 blog 更适合"常更 + 订阅"。
- **#2/#20 回访飞轮缺"回来理由"**：我补：**"你关注的入口有更新"是非侵入、合规的回访钩子**（不碰 #20 增长雷区：非官方、不代办、不冒充）。

### ③ 我补充的（资讯递送专属，别人没说的）

1. **"可信"缺时效会塌房**：圆桌把"可信"当成静态属性（来源类型 + 核验日期），但**信任 = 来源可信 × 时效新鲜**。一条 2023 年核验的"市政务入口"今天可能已改版/合并/关停——不递送新鲜度，"可信"迟早反噬（正是 #19 担心的"伪数据/伪官方"舆情温床）。
2. **资讯递送 = 把"可信 + 新鲜"变成可订阅、可提醒、可验证的流**：三层——① 站点侧"更新情报/动态"页（接 #27 journal/，定位为"官方入口变更情报"而非普通博客）；② 用户侧"我的收录更新提醒"（接 #25 localStorage 收藏 → 失效/变更回推）；③ 场景内"本入口最近核验 2026-08 · 3 人标记疑似失效"的真实数据呈现（接 #26 真实聚合 + #21 角标真实化）。
3. **新鲜度流 = 回访飞轮的真实触发器**：#2/#20 反复找"用户为什么回来"，答案之一就是"你存的入口变了，我提醒你"——比任何推送都合规（非官方、不代办、仅提示"请于官方核实"），完美避开 #20 增长雷区与 #21 指路不代办边界。
4. **新鲜度流 = 长尾 SEO 的"常更内容"引擎**：#6/#7/#27 苦于"只有卡片没有文章、抓取频次低"；持续更新的"XX 热线 2026 最新 / XX 官网入口变更"情报页，既是天然长尾 query（接 #8 搜索意图），又给 sitemap 加 `lastmod` 让 Google 重抓，**一举补 SEO 新鲜度 + 抓取频次两个洞**。
5. **"数据新鲜度健康度"应进 #26 指标树第 0 层**：收录条目 30/60/90 天未复核占比、疑似失效占比、用户 `expiry_alert_click` 率——这是"可信"能否持续的先行指标，比 pageview 更早预警（呼应 #26"无分母不拍板"）。

### ④ 我反对的

- **反对把"更新"只做成站内自我 changelog（现状）**：`pages/changelog/` 只记站点迭代，对用户零价值；应改为"外链资源新鲜度情报"对外版（用户要的是"入口变没变"，不是"你站加了几个分类"）。
- **反对"可信 = 静态核验日期"忽略时效衰减（轻反对 #21 表述）**：#21 的四要素要补 `review_cycle` + `status` 使其"会流动"，否则"可信"是会说谎的快照。
- **反对"内容运营只写办事指南、不碰动态情报"（轻提醒 #27）**：journal/ 的"变更情报"比 blog 办事指南更高频、更驱动回访，应并列内容支柱，而非等定位稳了再建。

### ⑤ 往哪推一步

把"时效"立为"可信"的第四根柱子，落成三件可勾选的改造：**① per-card 字段补 `review_cycle`+`status`（接 #21/#27 字段表）**；**② 建 `journal/`（更新情报页）+ 首页"本周更新"信息流 + sitemap 加 `lastmod`**；**③ 零后端"我的收录更新提醒"（localStorage 收藏 × per-card status 比对 + 失效回推，接 #25）**；并**扩展 #26 埋点加 `update_seen`/`expiry_alert_click`/`subscribe`**，把"新鲜度是否真驱动回访"变成可量化指标。这是把 #21 可信、#25 沉淀、#26 测量、#27 内容**四棒在"时效"维度一次性织进可订阅、可提醒、可验证的真实产品**。

## 三、专业深挖：我的 3 个问题及答案

> 注：这 3 个问题已同步追加到主问卷第 6 节「历届追加问题池」。

- **Q1. 导航站核心价值是"帮人找对官方入口"，但官方入口/热线/政策随时会变——站点当前"新鲜度"怎么呈现给用户？怎么把 #21 per-card 可信档案从"静态核验日期"升级为"会流动的新鲜度 + 可订阅的更新流"？**
  - A1. 实地结论：当前**零**用户侧新鲜度呈现（首页无信息流、changelog 只记站点迭代、sitemap 无 lastmod、卡片字段无复核状态）。升级路径三步走，全落在既有契约内：① **字段流动化**：在 README 字段表（接 #27）给 per-card 加 `review_cycle`（如季度）+ `status`（有效/待复核/疑似失效），前端角标从"核验于 2026-08"升级为"最近核验 2026-08 · 状态：有效"（文案经 #24 公文审稿定调）；② **站点侧更新流**：建 `journal/`（接 #27 规划的 journal/ 目录）承载"官方入口变更情报"，首页加"本周更新"信息流卡片（JS 读 `status` 变化生成）；③ **搜索引擎新鲜度**：sitemap 每个 URL 补 `<lastmod>`，changefreq 据 `status` 动态调（疑似失效 → daily）。这样"可信"从静态快照变"会流动的信任"。

- **Q2. 用户把入口存进收藏（#25 localStorage）后，站点能否在该入口"疑似失效/已变更"时回推提醒？零后端怎么做"我的收录更新情报"，且不与 #21"指路不代办"、#20 增长雷区冲突？**
  - A2. **能，零后端**。机制：① 站点把每张卡的 `status` + `last_verified` 作为轻量 JSON（如 `directory/<cat>/assets/json/freshness.json`，接 #26 数据底座）随页面下发；② 用户 localStorage 收藏存的是 `card_key` 列表（非裸 URL，接 #25）；③ 前端在用户打开站/点击"我的收藏"时，比对本地收藏 `card_key` 与最新 `freshness.json`，对 `status=疑似失效` 的卡弹"你收藏的『XX 入口』已于 2026-08 标记疑似变更，请于官方渠道核实"——**只提示、不代办、不给新链接、不代通知官方**（严守 #21 Q2 指路不代办边界，也不碰 #20 增长雷区：非官方、不冒充、不诱导分享）；④ 提醒文案经 #24 公文审稿定调。这是 #25"失效提醒飞轮"真正可落地的零后端实现。

- **Q3. 资讯递送怎么既喂饱 #6/#7 长尾 SEO（持续更新的"XX 最新入口/热线"页 = 常更内容 + 抓取频次）、又用 #26 埋点验证"新鲜度真驱动回访"，且不踩 #17/#24 合规？**
  - A3. 内容侧：journal/ 的"变更情报"天然命中长尾 query（"XX 热线 2026 最新""XX 官网入口变更"），且高频更新 + sitemap lastmod 拉高抓取频次（解 #6/#7 长尾 + #26 SEO 数据质量）；验证侧：扩展 #26 事件 schema 加 `update_seen`（看了更新流）/ `expiry_alert_click`（点了失效提醒）/ `subscribe`（订阅某分类），看板监控"更新流 → 回访率""失效提醒 → re-find 率"，无 30 天分母不判成败（#26 治理红线）。合规侧：情报文案"仅提示、附官方核实路径、不构成代办"（#21/#24），搜索词/订阅数据走境内管道（接 #17 GA4 出境风险、#26 合规红线）。这样"新鲜度"既喂 SEO、又闭环测量、还不越界。

### 4.1 点评（现状：好在哪、问题在哪）

**有问题（资讯递送视角）**：
- 🔴 **首页零用户侧资讯流**：打开站看不到"最近更新/刚核验/本周新增"，无从判断站点"活不活、新不新"；

- 🟡 **无 RSS/订阅**：用户无法"订阅某分类更新"，回访钩子缺位（#2/#20 飞轮缺触发器）。

### 4.2 修改方案（改哪里 → 改成什么样 → 为什么，标优先级）

- **[高] per-card 字段补 `review_cycle` + `status`（接 #21/#27 字段表）**：README 字段表加 `review_cycle`（复核周期）+ `status`（有效/待复核/疑似失效），前端角标升级为"最近核验 2026-08 · 状态：有效"。为什么：解"可信静态失真"（#21 落地 + 本棒核心），是新鲜度的数据底座。
- **[高] 零后端"我的收录更新提醒"（localStorage × freshness.json 比对回推，接 #25）**：随页面下发 `freshness.json`，前端比对用户收藏 `card_key`，对 `疑似失效` 弹"请于官方核实"提示（只提示不代办）。为什么：补 #25 失效提醒飞轮的真实管道，本棒核心落点。
- **[高] 建 `journal/`（更新情报页）+ 首页"本周更新"信息流（接 #27 规划的 journal/）**：定位"官方入口变更情报"，JS 读 `status` 变化生成，文案经 #24 定调。为什么：解首页零资讯流 + 给用户"回来理由"（#2/#20 飞轮触发器）。
- **[中] sitemap 补 `<lastmod>` + changefreq 据 `status` 动态调**：每个 URL 加最后修改时间。为什么：补 SEO 新鲜度信号、拉高抓取频次（#6/#7 长尾 + #26 数据资产盘点）。
- **[中] 扩展 #26 埋点加 `update_seen`/`expiry_alert_click`/`subscribe`**：接 #26 看板，验证"新鲜度真驱动回访/re-find"。为什么：本棒价值可量化。
- **[中] "数据新鲜度健康度"进 #26 指标树第 0 层**：收录条目 30/60/90 天未复核占比 + 疑似失效占比 + `expiry_alert_click` 率。为什么："可信"能否持续的先行指标（呼应 #26"无分母不拍板"）。
- **[低] changelog 页重构为"对外情报 + 站内迭代"双栏**：把外链资源新鲜度从 journal/ 同步摘要到 changelog 顶部。为什么：让既有页不浪费、用户一眼见价值。
- **[低] RSS/订阅（轻量，定位稳后）**：`/feed.xml` 输出 journal/ 更新，供高级用户订阅。为什么：回访钩子增强（呼应 #2/#20）。

### 4.3 发展方向（中短期 1–3 个月 / 长期半年以上）

- **中短期**：per-card `status` 字段 + `freshness.json` 下发 → 首页"本周更新"流 + journal/ 情报页上线 → 零后端收藏失效提醒跑通 → #26 埋点 `update_seen`/`expiry_alert_click` 上线。目标：30 日内"更新流浏览率"≥ 活跃用户 15%、收藏用户 `expiry_alert_click` 率 ≥ 疑似失效卡曝光 20%（待 #26 30 天分母校准）；收录条目 90 天未复核占比压到 < 10%。
- **长期**：新鲜度流成"可信"标志性符号（"最近核验 2026-08 · 已被 3 人标记最新"），把 #21 可信 + #25 沉淀 + #26 数据 + #27 内容在"时效"维度织成可订阅、可提醒、可验证的产品；用户因"入口变了有人告诉我"而稳定回访，闭合 #2/#20 飞轮；sitemap lastmod 常态化让 SEO 抓取与内容更新同频，"常更情报"成 SEO 护城河（#6/#7）。
