## 第 1 节 · 五道裁决题（选边 → 理由 → 反方挑战）

### 裁决 1｜定位 — 选边 C（先验证）
数据补刀：第 1 轮 39 棒全程**零真实用户观测数据**（#26 埋点为零），所以"垂类"至今是未验证假设。C 不是"不投入"，而是"先用最低成本拿方向信号再投入"——与 #41 一致。我的增量：把"验证"落成**可观测指标**（见第 3 节 OSM 树），而不是再开一轮分析。
**反方挑战**：垂类已上线且 SEO 化，"验证"边际价值可能低于直接跑。回应：正因为已压上全部筹码，先花 3 天确认"真有人用这个站找政协入口"比上线后发现没人来便宜一个数量级（#23 正是卡在这）。

### 裁决 2｜改名 — 选边 C（先测误认率）
数据支撑 #43 的 SERP 测量协议：取真实 SERP 快照给 N 人判"是否官方"，阈值接 #40/#42（≥30% 触发改名、<15% 留名）。**数据提醒**：误认率测量要预注册样本量与随机性；且 #44 点名的"正协↔政协拼音同形 zhèngxié"属语音维度，必须纳入（视觉快照测不出），否则测量有系统偏差。
**反方挑战**：零容忍触发项（官方函件/商标异议）已让改名不只靠数字。回应：两机制并行不悖——数字用于"灰区留名重塑 vs 改名"决策，红线用于"无条件触发"，互不替代。

### 裁决 3｜可信最小版（整站级 · 已决）— 选边 A（about 补位 + Organization）
整站级路径正确（逐卡标记=虚假宣传风险，#44 已证）。**我的数据增量**：about 页「来源透明 / 链接露真域名」的承诺，必须用数据兜底——`cards.unified.xlsx` 实测 `link_1_url`（主官方入口）**缺失 58.5%**、`card_desc` 缺失 58.7%（见第 0 节附 / 附表 B）。即"来源透明"目前只覆盖约 **41%** 的卡。建议：① 建**发布前数据完整度闸门**（缺 link_1/desc 的卡不准发布），与用户"不渲染逐卡"决策不冲突；② about「内容怎么来的」声明以"有主链接卡占比"为可验证前提，避免说过头。
**反方挑战**：完整度闸门会拖慢发布。回应：只对**新增卡**强制、存量卡仅计入质量分，不阻塞已上线页。

### 裁决 4｜验证顺序 — 支持 #42「A 闸门 / B 并行」，且用功效分析约束 B 的设计
**本棒最关键定量结论**：#40 的 B 方案（组间 A/B，n=20=10/arm）在效应量 d≥0.5 时**功效仅 20–53%**，几乎必然漏检；#41 的组内 n=24 达 69–99%（附表 A）。实测指标"信任评分差 ≥1.0（1–5 李克特，SD≈1.2）"下，#40 功效 **46%**、#41 **98%**。→ **若做 B，必须采用 #41 的组内 n≈24 设计，否则整笔验证经费打水漂**。A（客户关口）用 5 人方向性访谈即可拍板，与 B 并行不冲突。
**反方挑战**：#40 主张"先看可信价值 B"。回应：B 的设计必须先过功效关——我已给出最小可行样本（组内 24），这不是否决 B，是让 B 真能出结论。

### 裁决 5｜广告与内容边界 — 选边 A（政务区禁广告），且本棒已落成可重复门闸
**数据实证**：严格「政务区零广告」闸门下，首页当前 **FAIL（11 标记）**（事实 4）。选项：① 严格 A——从首页/民主党派/机构 cat 页 + about/disclaimer **移除广告**，仅在未来非政务内容页展示；② 采纳 #44 §5.3「band 在网格外即合规」放宽闸门（只禁卡旁、不禁页级带）。我交付门闸脚本，决策权交用户。
内容区第一个做什么 = **办事指南**（接 #43 五件套），且须过我的数据完整度闸门（每篇有真实官方出处 link_1，不编造）。

## 第 3 节 · 我的验证方案（一页 · 裁决 4「看什么数」）

```
验证假设：能用一套对齐的 OSM 指标树 + 可埋点事件， measurable 地回答
          "用户是否真能找到、是否真信、是否真回来"（裁决 1/3/4 共用）。

验证对象：真实访问用户（埋点，非抽样）；政务工作者 + 普通网民混合。

验证动作（零后端补业务事件，GitHub Pages 静态站）：
  ① 轻量 beacon：隐私友好统计（Umami/Plausible 自托管 或 Cloudflare Web Analytics，
     支持自定义事件、数据可不出境）；或 fetch beacon → serverless 函数写日志。
  ② PIPL 红线：搜索词属敏感个人信息，只上报「是否 0 结果 + cat 维度 + 聚合计数」，
     不传原始 query、不出境（#17/#26 红线）。

看什么数（OSM 指标树 + 预注册阈值）：
  北极星：find_rate 一次找到率 = 首次点击即命中目标卡 / 发起检索次数 ≥ 50%
  漏斗：访问(UV) → search/filter 触发 → first_click_hit → task_done(成功率≥70%) → return(回访≥4分占比≥60%)
  事件：search_query(0-result标记) / card_click(目标url) / fav_add / refind / share
        / about_view + about_read(滚动≥80%) / ad_impression / ad_click / ad_block
  可信主指标（接 #41）：整站信任评分(1–5) + 行为信任(敢点官方链接/点完不返回) 双轨，
        先定行为指标为主，避免态度漂。
  误认率（接 #43/#2）：SERP 快照 N=20，阈值 ≥30% 触发改名评估。

不达标怎么回滚：find_rate<50% 或 任务成功率<70% → 移除新增埋点/B 实验，
  结论转向"先验证客户关口(A)"，不扩大投入；门闸脚本(ad audit)不达标 → 移除政务区 slot。
```

> 注：本方案与 #44 门闸互补——广告 placement 用抓取审计（已落成），用户行为用埋点（本方案）；两者都进构建期 CI。
