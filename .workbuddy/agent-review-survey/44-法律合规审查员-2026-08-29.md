## 第 1 节 · 五道裁决题（选边 → 理由 → 反方挑战）

### 裁决 1｜定位 — 选边 C（先验证）
合规补刀：定位"政协/民主党派垂类"本身**合法**，无合规障碍；但策展必须保持"第三方索引"中立表述，不得出现"官方授权/指定/合作"等暗示词。验证（#41 的 5 人游击访谈）可并行确认"定位表述是否引人误认官方"——这是定位与改名两条线的合规交集。
**反方挑战**：若 C 一直"先验证"而不投入，站点在无 ICP 备案状态下持续投放广告，违法时长只增不减——所以 C 的"验证"不应阻塞 P0 合规整改（备案/广告边界可立即做）。

### 裁决 2｜改名 — 选边 C（先测误认率）+ 合规红线升级
- **合规法理**：《反不正当竞争法》第六条（混淆行为：擅自使用与他人有一定影响的名称等近似标识，引人误认）、《广告法》第四条（不得含虚假或引人误解的内容）。"正协 / 政协"**拼音完全相同（zhèngxié）**——这是混淆风险的最高形态：视觉误认率测不出语音搜索、口头传播、口播视频里的混淆。
- **升级建议**：除 #40/#42 阈值（误认率 ≥30% 触发改名评估）外，增加**零容忍触发项**（将 #22 Kill Conditions 合规化）：一旦收到**官方函件 / 商标异议 / 任何"足以引人误认为有官方授权或关联"的证据**，无论误认率数字多少，**立即改名**。改名不应只靠误认率数字决，应有法律红线兜底。
**反方挑战**：误认率测量（#43 SERP 协议）若只测"视觉误认"，会漏掉拼音同形这个最危险维度；合规要求测量必须含"听到/读到 zhengxie 是否联想到政协"的语音场景。

### 裁决 3｜可信最小版（整站级 · 已决）— 选边 A（about 补位 + 补 Organization）
- **合规强力背书整站级路径**：about 六段 + 页脚声明 + 来源透明（链接露真域名）是**合规正确路径**。理由：若走"逐卡已核验"标记而实际未真核验，等于**虚假宣传**（《广告法》第四条），比不标更危险——用户决策（#40 §7）推翻逐卡在合规上也是对的选择。
- **补 `Organization` 结构化数据（接 #43 选 B）——给出合规模板**：
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "正协导航",
  "url": "https://zhengxie.com.cn",
  "description": "独立第三方导航站点，汇集人民政协与民主党派的公开官方入口；与任何官方机构、政党无隶属、无授权、无合作关系。",
  "logo": "https://zhengxie.com.cn/assets/images/logo.png"
}
</script>
```
  **合规硬约束**：① 绝对不写 `sameAs` 指向任何官方站；② description 必须明示"无隶属/无授权/无合作"；③ 不出现"官方/政府/授权/指定/合作"等暗示背书词；④ `logo` 须为本站自有标识，**不得用任何党政徽标**；⑤ 本模板经我合规初审通过，落地前仍建议 #24 公文审稿做最终签字（与 #43 备注一致）。
- **🔴 备案号缺口是整站级可信的"硬通货"缺失**：当前 footer 自认无 ICP 备案——这既违法，也让"整站可信"失去最基础的第三方背书。裁决 3 的"整站级可信"若不含有效 ICP 备案号公示，是半成品。
**反方挑战**：补 Organization 若 description 写得像"专注政协"又没把"无合作"说足，反而放大混淆——所以措辞必须经 #24 公文审稿，不能只靠 SEO 直觉。

### 裁决 4｜验证顺序 — 支持 #42「A 闸门 / B 并行」
无分歧。合规提醒：A（客户关口）真人访谈若收集受访者个人信息（如职业/联系方式），须走 **PIPL 最小必要 + 告知**（隐私页已声明"不收集账号类个人信息"，访谈需单独告知同意）。验证本身不引入新合规风险。
**反方挑战**：无。

### 裁决 5｜广告与内容边界 — 选边 A，并升级为**合规硬要求（非可选）**
- **合规法理**：《广告法》第十四条（广告应当具有可识别性，能够使消费者辨明其为广告）；政务/民主党派官方入口卡若旁渲染商业广告，等于把广告与官方服务**捆绑呈现**，易被认定为暗示关联或商业化官方服务，且触碰 #15/#17/#18 红线。
- **🔴 实站证据**：`ads.txt` 实证 AdSense 已上线（pub-id 在册）——所以"政务页禁广告"不是假设风险，是**当前已存在**的暴露。必须审计广告位 placement。
- **强制边界**：① 政务/民主党派类入口卡区（首页 `?cat=政协/民主党派/机构`、directory 对应频道页）+ about/disclaimer/免责等可信声明区 **绝对不渲染广告**；② 广告仅限非政务内容区（影音娱乐/效率工具/设计创意等分类），且保持"广告"标识；③ 内容"办事指南"必须带**真实官方出处**，不得编造，否则构成误导用户 + 信息不实责任（#17/#21 雷）。
**反方挑战**：若 AdSense 是全站自动注入，技术上去"政务区广告"需要定向排除逻辑——这恰是验证方案要解决的（见下）。不能因为"技术难"就放任政务卡旁投广告。

### 5.2 静默上线 / GitHub Pages / 备案路线（用户说明）
- 当前=静默上线、GitHub Pages 境外托管、无 ICP（GitHub Pages 无法备案）；满足条件后迁移境内服务器 → 办 ICP。
- 合规结论：在"无 ICP + 有广告"状态上线属用户自担风险。本棒定位是**把可降风险压到最低**，而非消除（消除需迁移+备案）。

### 5.3 广告位置与数量建议（基于实站核验 · 已合规，仅加固）
实站核验：2 个固定位 `ad--top`（hero 内、网格前）/ `ad--bottom`（网格后、footer 前），均带「广告」标识（广告法14条可识别性达标），且**都在政务卡区之外** → 已满足"政务区禁广告"。
加固建议：
1. **视觉区隔**：`ad--top` 当前嵌在 `<header class="hero">` 内，易与品牌/搜索混同。建议移为 hero **之后**的独立全宽带，强化可识别性、避免"像站点推荐"误读。
2. **数量**：维持 **2 个**（顶部带 + 底部带），均为非政务中性区。**上限 3 个**，禁止在卡片网格内 / 分类级插入（既违政务区禁广告、又侵蚀整站级可信）。
3. **标识**：`ad__label`「广告」移动端必须常显，不得隐藏。

### 5.4 运营经费替代来源（用户备选）
若广告收益不及预期或想降合规风险，按合规友好度排序：
1. **捐赠 / 打赏（赞助入口）**：footer 加"请喝咖啡/赞助"入口，零广告法风险，最适合静默测试期。✅ 推荐与主广告并行。
2. **赞助友链（须明示"赞助"）**：仅限非政务区、明确标注，不混入第三方中立性叙事。
3. **联盟 / affiliate**：政协/政务主题难匹配、易误导，迁移境内+备案前不建议。
4. **B2B 数据/API、会员付费**：边际价值低或违背信息免费原则，暂缓。
→ 结论：**广告（合规 2 位）+ 捐赠入口**双轨，是静默期最低合规风险组合。
