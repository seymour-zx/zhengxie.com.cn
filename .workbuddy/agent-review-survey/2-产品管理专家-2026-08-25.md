## 二、圆桌总结（综合之前所有答卷 + 自己的思考）

我读了第 1 位（用户调研专家·闻真）的答卷。**整体高度认同，特别是"定位漂移"和"扑空即流失"两个判断**——我自己以政务相关用户身份作答时，也撞上了同样的困惑（C2 说不清这站给谁用）。以下是产品视角的补充与推进：

**① 认同 + 补充：定位漂移不只是表达问题，是产品战略问题。**
闻真指出 meta 说"政协政务垂类"、首页却是全量通用——我要往前推一步：**这不是文案没对齐，而是"主战场"没选定**。导航类产品的本质是"在一个细分场景里做到比搜索引擎更好"，全量通用没有护城河（浏览器主页、hao123、搜索都比你强），而"政务/机构官网入口 + 可信甄别"是搜索引擎给不了的（搜出来全是广告和钓鱼风险）。**产品判断：主定位应明确选垂类"可信政务/机构入口"，全量分类保留但退居二线**——理由见我的 Q1。

**② 认同 + 补充：扑空不是终点，是需求入口。**
闻真说"扑空即流失"，产品视角补充：扑空恰恰是**最便宜的需求收集器**——搜了但没找到，说明用户真有这个需求而你没收录。所以不是简单"加个提示"，而是把"没找到？告诉我们"做成一个正式的产品功能，让扑空变成内容规划的输入。

**③ 回应闻真的 Q3（第一批用户从哪来）：**
我同意"被收藏夹和搜索结果逼疯的人"这个判断，并具体化为**"政务/体制相关人群"优先**——他们有高频办事需求（公积金、社保、政务平台）、怕钓鱼、且人群集中好触达（单位内部、行业群），和站点调性天然匹配。第一批可以从"本地政务服务群/行业交流群"切入。

**④ 我的推进：产品层缺三样东西——明确的北极星、留存钩子、指标体系。**
闻真抛了"怎么验证用起来了"（Q1），我接这个球给出产品层答案：**北极星 = 周回访用户数**，驱动 = 搜索/筛选使用率、任务成功率、收藏使用率；同时"本周上新"做留存钩子——详见我的 Q2、Q3 和修改方案。

## 三、专业深挖：我的 3 个问题及答案

> 注：这 3 个问题已同步追加到主问卷第 6 节「历届追加问题池」。

- Q1. **定位二选一：垂类（政协/政务）还是全量通用？如果只能选一个主定位，选哪个、放弃哪个？**
  A1. **选垂类"可信政务/机构入口"作为主定位，全量通用分类保留但降为辅助层**。理由：① 通用导航没有护城河——hao123、浏览器自带主页、搜索引擎在"找任何网站"上都比你强，正面打必输；② "政务/机构官网 + 可信甄别"是搜索给不了的：搜政务办事全是广告和钓鱼风险，一个"官方入口精选"的站对体制内/办事人群是刚需；③ 垂类才可能"全量"——全国的政协/政务/机构官网是有限可枚举的，而"全量通用"是填不满的坑；④ 红金白视觉 + 正式调性天然适配政务人群的信任诉求。**放弃的代价**：流失纯通用流量（学生、自由职业找工具的人群），可接受——他们本来就不是你的核心用户。

- Q2. **正协导航的北极星指标应该是什么？怎么衡量"真的用起来了"？**
  A2. **北极星 = 周回访用户数（每周回访率）**。导航站的本质是"高频回来的工具"，不是一次性访问，拉新不重要、回来才重要。配套指标：**驱动** = 站内搜索/筛选使用率（证明用户在"找"）、单次任务成功率（回应闻真 Q1，找到率）、收藏使用率（收藏=有长期价值预期）；**健康** = 扑空率（搜了没结果的比例，必须低）、加载速度。落地：先跑 4 周统计回访率基线，目标定在"周回访率 ≥ 20%"再谈增长。

- Q3. **增长飞轮在哪？导航站怎么让用户"有理由回来"？**
  A3. 导航站的飞轮不是拉新，是 **"收录增量 → 新鲜感 → 回访 → 反馈需求 → 收录增量"** 的循环：① **"本周上新"栏目**（每周 3–5 条精选新增，配"更新了什么"）给回访理由；② **"没找到"反馈入口**积累真实需求，反哺收录优先级——用户报一个、你收一个，他会回来；③ **政务垂类自带时效钩子**：政策发布、办事入口变更、公积金新规出台时"入口已更新"——这是搜索引擎给不了的、天然的回访理由；④ 收藏可导出/云同步降低流失成本。飞轮的启动点：先跑通"反馈→收录→上新→回访"最小闭环。

## 四、点评 / 修改方案 / 发展方向

### 4.1 点评（现状：好在哪、问题在哪）

**做得对**：
- 视觉与调性是差异化资产（"可信感"是导航站里稀缺的）；
- 功能克制不堆砌，多重筛选 + 集合搜索逻辑自洽；
- 静态渲染 + SEO 扎实，底层工程健康；
- 内容已有垂类雏形（directory 有政务/人大/政协/银行/保险等频道页），不是从零开始。

**有问题**（产品层）：
- **主战场没选定**：垂类 vs 通用两套人设，导致"这站是干嘛的"说不清（我 C2 的真实困惑）；
- **没有北极星和指标体系**：不知道"用起来了"长什么样，优化全凭感觉；
- **缺留存机制**：无新鲜感钩子、无"更新了什么"、收藏不跨设备；
- **无需求收集出口**：扑空即流失，需求全部浪费掉。

### 4.2 修改方案（改哪里 → 改成什么样 → 为什么，标优先级）

- [高] **定位对齐（Now）**：首页 Hero 副标题 + meta 描述/OG/JSON-LD 统一到主定位"可信政务与机构入口精选"，首页分类顺序把政务/机构类提前；同时保留通用分类。为什么：先解决"这站是干嘛的"，其余优化才有准星。
- [高] **上线"没找到"反馈入口（Now）**：站内搜索 0 结果时显示"没找到？告诉我们你想找什么"，提交落到公开需求池（可用表单 + 邮件）。为什么：最便宜的需求收集器，扑空变输入。
- [中] **"本周上新"栏目（Next，1–2 月）**：每周 3–5 条精选新增 + "更新了什么"小日志（已有 changelog 页可复用）。为什么：给回访理由，跑通"收录→上新→回访"最小飞轮。
- [中] **收藏可导出（Next）**：一键复制收藏列表文本 / 导出书签 HTML。为什么：缓解"换设备就丢"的信任硬伤，成本低感知强。
- [低] **建立周报基线（Later，2–3 月）**：统计周回访率、搜索使用率、扑空率 4 周基线。为什么：北极星落地，后续决策有数可依。

### 4.3 发展方向（中短期 1–3 个月 / 长期半年以上）

- **中短期**：把"可信垂类"做实——政务/机构/办事入口做到**全量 + 可信甄别 + 时效更新**（政策/入口变更及时标"已更新"），这是搜索引擎替代不了的护城河；同步上线反馈入口和"本周上新"，跑通最小闭环；开始统计回访基线。
- **长期**：成为"政务/体制相关人群的浏览器主页"——从"导航"进化为"办事入口 + 政策动态 + 工具"的垂类门户；若回访数据验证成立，再考虑云端收藏/账号体系（需要评估静态站改造，抛给下一位开发专家）；变现从 AdSense 走向"可信入口增值服务"。
