## 附 · sitemap `<lastmod>` 正确取值机制（② 已决方案，待授权实现）

**前置事实（实测）**：当前 `sitemap.xml` 是**静态手写文件**（13 URL、0 lastmod）；活脚本 `build_homeplus.py` 第 166 行明确「不自动维护 sitemap.xml（待用户授权）」，`build.py` 编排器只跑 `build_homeplus.py` + `collect_meta.py`，不含 sitemap；且 `render_and_write` 每次运行都无条件 `f.write(page)` 重写所有 html。→ 若"自动生成 + lastmod = 构建时刻 / 文件 mtime"，每次构建会给全部 URL 盖上今天，制造**伪新鲜度**，搜索引擎会学会忽略 lastmod、浪费抓取预算——这就是"错"的根因。

**正确机制 = 内容哈希 + 持久化缓存（与构建时刻彻底解耦）**：
1. 维护状态文件 `assets/.build/.sitemap_lastmod.json`：`{ "<url>": {"hash": "<sha256>", "lastmod": "YYYY-MM-DD"} }`（建议提交进 Git，跨设备克隆也能记住历史 lastmod，避免缓存丢失导致全量刷新）。
2. 每次构建，对每个待收录 URL：
   - 取**当前渲染内容**：py 生成页取 `render_and_write` 写入前的 `page` 字符串（需让该函数 return 页面内容）；手写页（`pages/*`）读磁盘 html。
   - 算稳定指纹：本站点 html 不嵌构建时间戳，直接 `sha256(内容字节)`；若将来模板注入构建时间，须先剥离再哈希。
   - 比对缓存：`hash 相同 → 沿用原 lastmod（不更新）`；`hash 不同 → lastmod = 今天、更新 hash`；`URL 不在缓存（新页）→ lastmod = 今天、入库`；`缓存有但已删除 → 移出 sitemap 与缓存`。
3. 用缓存里的 per-URL lastmod 写出 `sitemap.xml`。

→ 效果：只有**内容真变**的页拿新 lastmod，其余保留历史值；搜索引擎获得真实新鲜度信号。裁决 5 新内容页（办事指南）随生成自动进 sitemap 并获当天 lastmod。

**为何不用别的**：构建时刻 / 文件 mtime（py 全量重写 → 全错）；git 提交时间（生成 html 每次提交也 = 今天，且抓不到 about 文案变更）；xlsx 手填 lastmod 列（人维护、易漏、违背自动化）。内容哈希最稳、与源解耦。

**实现落点**：在 `build_homeplus.py` 新增 `build_sitemap()`（或在 `build.py` 加一步 `gen_sitemap.py`）。URL 清单 = 根页 + `meta_dir_paths()` 频道页 + 手写页白名单（about/submit/privacy/contact/disclaimer/guide/sitemap/changelog/overview）+ 裁决 5 新内容页；py 生成页在 `render_and_write` return html 供哈希，手写页读盘哈希。
