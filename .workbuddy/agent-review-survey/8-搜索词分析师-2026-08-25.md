## 二、圆桌总结（综合之前所有答卷 + 自己的思考）

我通读了第 1–7 位答卷。前七位已经从用户、产品、工程、代码、视觉、独立站、SEO 七个面把站看透了，我作为**搜索词分析师**，贡献的是别人都没有的视角——**用户到底会输入什么词**。我的核心判断：

**① 站点的分类名是"站方语言"，不是"用户语言"——这是站内搜索扑空的根因，也是内容化的起点。**
我以理赔内勤人设作答时，"机构"分类对我意味着"政府单位官网"，但我搜的是"医保局""卫健委""下载"——**用户的词和站点的分类名、卡片描述对不上**。举例：用户会说"医保局官网/社保查询入口/办事大厅"，而站点叫"机构/政务服务平台"。这个 gap 是搜索词分析最该解决的问题：建一张**"用户语言 ↔ 站点语言"对照表**（我 Q2 详述），它同时服务三个地方——卡片描述怎么写、频道页导语覆盖哪些词、站内搜索怎么匹配。

**② 站内搜索是这座站最便宜的"真实用户语言"数据源，但现在完全浪费了。**
用户站内搜的词 = 真实需求的直接证据，比问卷真实、比访谈量大。但现状是**站内搜索没有打点**（GA4 只埋了页面级，没记录搜索词），用户搜了什么、扑空了多少，一无所知。我强烈建议：**站内搜索词打点 + "扑空词"报表**（详见我的 Q2）——这是整个圆桌所有方案里唯一"白送数据"的动作。

**③ 认同前位的"可信政务垂类"，搜索词层面它意味着什么？**
意味着站点的搜索词战略应该围绕**导航型 query（找官方入口）+ 信息型 query（怎么办/在哪）**展开，同时**坚决不碰负面词生态**（代办/代开/加急/包过——这些词既是骗局高发区，也与"可信"定位冲突）。我以人设作答时最反感的正是代办广告，搜索词层面要主动"负向隔离"（Q3）。

**④ 数据纪律声明**：我没有任何真实搜索数据，下面的**词库是假设库**，落地后必须用 Search Console / 百度站长平台 / 站内打点数据验证——分析师的职责是提出可验证的假设，不是编造数字。

## 三、专业深挖：我的 3 个问题及答案

> 注：这 3 个问题已同步追加到主问卷第 6 节「历届追加问题池」。

- Q1. **用户想找"官方入口"时会怎么搜？这些 query 应该映射到站点的哪个页面？**
  A1. 假设库（待数据验证），按意图分两类：
  - **导航型**（一步直达）：`{机构/事项名}+官网/入口/平台`，如"国家医保局 官网""政务服务平台 入口""XX市公积金中心 官网"。→ 映射：**卡片直达**（收录即承接），这类 query 是站点的"外链价值"，不是自己的排名机会。
  - **信息型**（怎么办/在哪）：`{事项}+网上办理/入口在哪/网上怎么办`，如"医保目录 官方下载""公积金提取 网上办理入口""食品经营许可证 网上年检"。→ 映射：**频道页导语 + 未来办事指南文章**（这正是 SEO 专家说的内容化承接点）。**结论：频道页导语必须按"入口在哪/怎么找/常见坑"来写，而不是现在的"本频道收录了什么"**——现有导语（如 zhengxie 频道"收录全国政协及各省市…"）是站方视角，用户视角应该回答"你要找的政协官网在这，别搜到假的"。

- Q2. **站内搜索的"高频词"和"扑空词"分别说明什么？怎么把站内搜索变成免费的需求数据源？**
  A2. 站内搜索词 = 用户真实语言的免费样本：**高频词** → 收录优先级与卡片描述对齐（用户搜什么，卡片就该被搜到）；**扑空词** → 需求缺口（"没找到"反馈入口的天然输入，呼应产品专家的方案）。落地三步：① GA4 埋自定义事件（搜索词 + 结果数 + 是否扑空），百度统计同埋；② 每周出一份"站内 query 报表"（高频 Top50 + 扑空 Top20）；③ 用扑空词驱动收录优先级（高频扑空 = 下一个该收录的站）。**这是整个圆桌里成本最低、数据最真的动作，建议排进前三周。**

- Q3. **政务向导航站最该"负向隔离"的搜索词是什么？（付费搜索叫 negative keyword，内容站同样适用）**
  A3. 三组负面词模式，**内容与广告双线隔离**：
  - **代办黄牛类**：`{事项}+代办/代开/加急/包过/收费办理`——骗局高发区，与"可信"定位直接冲突，**不优化、不承接、不写进任何内容**；
  - **金融骚扰类**：`贷款/理财/刷单/兼职`——与政务场景无关且拉低信任，内容不碰；
  - **下载器类**：`破解/免费下载/绿色版`——易关联盗版与低质生态，不碰。
  广告侧：AdSense 屏蔽上述类目（呼应独立站专家的"三类广告不接"）；内容侧：频道页导语、指南文章一律不优化这些词——**导航站的目标是"官方入口的灯塔"，不是"灰色生态的中转站"。**

## 四、点评 / 修改方案 / 发展方向

### 4.1 点评（现状：好在哪、问题在哪）

**做得好（搜索词视角）**：
- 分类名 + 卡片标签已经是"半套搜索词库"（10 分类、卡片标签即词），有基础但缺"用户语言"；
- 站内搜索支持全文匹配（textContent）且带 hash 分享（`#q=`），词可传播；
- 频道页导语块（channel-intro）是内容化现成载体（虽然现在是站方视角的一两句）。

**有问题（搜索词视角）**：
- 🔴 **站内搜索无打点**：用户搜了什么词完全不知道——最便宜最真实的 query 数据源被浪费；
- 🔴 **"用户语言"缺失**：分类名/卡片描述是站方语言，与用户真实说法（"医保局""下载""网上办理"）对不上，站内扑空和内容无效的根因；
- 🟡 **频道页导语是站方视角**（"本频道收录了什么"），不是用户视角（"你要找的入口在这，别被假站骗"）；
- 🟡 **无负面词隔离**：内容与广告都没主动规避代办/贷款类词生态；
- 🟡 卡片描述是"介绍体"（长段功能说明），不是"搜索体"（用户会搜的关键词组织方式）。

### 4.2 修改方案（改哪里 → 改成什么样 → 为什么，标优先级）

- [高] **站内搜索词打点**：GA4 自定义事件（搜索词 + 结果数 + 扑空标志），百度统计同埋；每周出"站内 query 报表"。为什么：免费、真实、全圆桌最该先做的数据动作（我的 Q2）。
- [高] **建"用户语言 ↔ 站点语言"对照表**：10 个分类 × 用户真实说法映射（"机构"→"政府单位/官网/部委"；"效率工具"→"办公软件/免费工具/在线工具"；"政务服务平台"→"办事/查询/年检"），用对照表重写卡片描述关键词、频道页导语、站内搜索别名。为什么：解决"用户搜的词和站点的词对不上"这个根因（我的 Q1/Q2）。
- [中] **频道页导语改用户视角**：16 个频道页导语按"你要找的官方入口在这 + 怎么找 + 常见坑 + 收录标准"重写，覆盖对应 query 集群。为什么：内容化的承接点（我的 Q1，呼应 SEO 专家）。
- [中] **站内搜索别名增强**：如搜"办理"匹配"政务服务"、搜"医院"匹配"卫健委"、英文大小写不敏感。为什么：词不匹配是扑空主因之一。
- [低] **负面词隔离清单**：内容不优化代办/贷款/下载器类词；AdSense 屏蔽对应类目。为什么：保护"可信"定位（我的 Q3）。

### 4.3 发展方向（中短期 1–3 个月 / 长期半年以上）

- **中短期**：① 站内搜索打点 + 首份 query 报表（2 周内）；② "用户语言对照表"落地（配合频道页导语重写，1 个月）；③ 用首月站内数据校准上述假设库（高频词/扑空词验证，数据说话）。
- **长期**：① **站内 query 数据驱动收录**——高频扑空词 = 下一个收录对象，形成"需求-收录"闭环（呼应产品专家的增长飞轮）；② 季度性 query 复盘：看用户的词怎么演化（政策热点变化会带来新词，如"个税汇算入口"）；③ 把"用户怎么找官方入口"的研究沉淀成内容库，成为频道页和指南文章的选题来源。
