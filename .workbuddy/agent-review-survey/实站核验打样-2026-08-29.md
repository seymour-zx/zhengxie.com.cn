## 事实 1｜定位一致性：meta / OG / JSON-LD 自称什么？分类里政务类占几个？

- meta description / OG / twitter / JSON-LD **四处全文统一**：「正协导航是专注人民政协与民主党派的第三方导航站……本站为独立第三方，与任何官方机构无隶属关系」。
- 首页分类共 **11 个**：政协、民革、民盟、民建、民进、农工党、致公党、九三学社、台盟、工商联、机构 → **政务类 11/11（100%）**。
- 首页卡片 **337 张**。
- **观察**：第 1 轮 #36 实锤的「meta 写垂类 / 关于页写全量 / 实际卡片聚焦」三处打架**已修复**——站点已实际执行垂类定位，自称口径一致。→ **裁决 1 的讨论前提变了**：焦点不再是"表述打架"，而是"垂类定位本身有没有经过真实用户验证"。

## 事实 2｜一张政协卡片上，用户肉眼能看到哪些"可信"信息？

- 链接格式：`访问官网 - www.cppcc.gov.cn` → **链接旁露真实域名**（#21 建议、SOP §5 已落地）。
- 页脚 footer 存在；页面正文含「免责声明」「无隶属关系」（4 处）「第三方导航」（5 处）。
- **未渲染**：认证徽章 / 核验日期 / 来源类型标签（备案号为占位注释：「项目托管于 GitHub Pages，无 ICP 备案，故不渲染备案」）。
- **观察**：32 列 schema 的 `verification_*` / `source_type` / `verify_date` 字段**尚未上卡片**——可信档案目前只存在于数据层，用户层只看得到"域名 + 声明"。→ **裁决 3 的实际起点是 B 选项**（数据已备、只差渲染），不是从零做起。

## 事实 3｜站内搜索扑空时，0 结果给了什么？

- 站内搜索存在（`site-search` + `#site-search-input`，main.js 绑定 input/keydown）。
- 0 结果时：结果计数变「当前显示 0 / 337 张卡片」（is-empty 样式）+ empty-state 显示「**没有找到匹配的结果，换个关键词或分类试试**」。
- **没有**「没找到？告诉我们，我们帮你收录」的反馈入口（#1 的高优先级建议未落地）。
- **观察**：兜底文案有了，但**扑空数据不回流**——"扑空即流失"仍无法被观测。→ **裁决 4 C 选项（扑空即流失）要成立，必须先补"扑空记录"这一环**。
