## 0. 圆桌规则（每位 agent 必读）

这不是一次性的问答接力，而是一场**圆桌讨论**——每份答卷都是圆桌上的一次发言：**接住前面所有人的观点，再往前推一步**。

可参与的专家不限：产品专家、网站开发专家、代码审查专家、UI 设计专家、独立站专家、SEO 搜索专家、搜索词分析师、用户体验研究员、用户体验架构师……以及你认为该补位的任何角色。

### 接力流程（以 agentB 为例）

1. **作答问卷**：先以「普通网站用户」身份完成第 3 节通用问卷（题目格式对应保留，逐题作答）；
2. **看之前所有答卷**：阅读**之前所有** agent 的答卷 md（第 1 份、第 2 份……直到最新一份，如 `1-XXX-日期.md`、`2-XXX-日期.md`……）；
3. **圆桌总结**：综合**之前所有作答**与你自己的作答，写下你的想法——**认同什么、补充什么、反对什么、往哪个方向再推一步**；
4. **自拟 3 题**：以你的专业身份给出 3 个问题，自己作答，**并把 3 个问题追加到主问卷第 6 节「历届追加问题池」**（问题在接力中不断累积，问卷越滚越厚、维度越滚越广）；
5. **点名下一位**：点名推荐下一位作答的 agent（C），给一句推荐理由；
6. **产出答卷**：把你的完整作答合并生成一个独立 md，**命名格式：`{第几个作答}-{agent名称}-{YYYY-MM-DD}.md`**（如 `2-网站开发专家-2026-08-26.md`），内容必须包含：① 通用问卷的作答（带对应题目格式）；② 圆桌总结；③ 你的 3 个问题及答案；④ 下一位 agent 的名称。产出后按第 5 节模板填写，并在主问卷第 7 节「答卷索引」登记。

### 规则

- 只评方案，不评人；
- 修改方案必须具体到能落地（说"怎么改"，不说"应该更好"）；
- 不设维度限制，鼓励用你的专业优势视角；
- 允许自行打开 zhengxie.com.cn 实站验证，再下结论；
- **第一位作答的 agent（A）没有前序答卷可看，跳过第 2、3 步的综合环节**，直接作答 + 自拟 3 题 + 点名下一位即可。

## 1. 评审对象：项目背景

**正协导航**（zhengxie.com.cn）是一个**全量收录的精选站点导航站**，slogan：**「让每一次寻找，都不止于找到」**。纯静态手写 HTML/CSS/JS，无构建工具，已上线，托管于 GitHub Pages + 自有域名，接入 Google AdSense 广告。

- **收录分类**：常用入口、AI 智能、资讯媒体、设计创意、开发技术、学习教育、效率工具、影音娱乐等；
- **视觉语言**：奢华尊贵风——红为主色、金为点缀、白为底；暗色模式复用同一套语言（漆面黑 / 暖炭灰 / 亮金 / 象牙白），手动切换、不跟随系统；
- **核心功能**：分类 × 关键词 × 本地收藏的多重筛选（AND 叠加）、集合搜索（百度 / Google / 必应为主引擎 + 多引擎滑道）、结果计数、统一滑动交互、本地收藏（localStorage，不跨设备）；
- **站点结构**：首页（导航产品页）+ `directory/` 频道页（政务 / 人大 / 政协 / 银行 / 保险 / 股票 / 媒体 / AI 等）+ `pages/` 说明与合规页（关于 / 收录申请 / 隐私 / 指南 / 网站全景等）+ 内容区（blog / news / journal）+ 404 + robots + sitemap + ads.txt；
- **SEO 现状**：卡片与链接全部静态渲染（禁用 JS 仍可读可点）、JSON-LD（WebSite + SearchAction）、canonical / OG / 标题层级齐备。

## 2. 本次评审想解决什么

**主问题**：作为"全量收录精选导航"，用户（包括你）**看得懂吗？哪部分吸引、哪部分劝退？**

**延伸问题**：怎么改，能让它**更好用、更可信、更能留人、更有增长空间**？

**期望产出**：每位 agent 的 **点评 + 修改方案 + 发展方向**，以圆桌接力方式互相补充与挑刺，最终形成一份可以照着执行的改造清单。
