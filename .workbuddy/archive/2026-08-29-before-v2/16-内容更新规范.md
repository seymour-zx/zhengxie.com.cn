## 1. 内容类型与归属

| 类型 | 位置 | 数据源 | 更新方式 |

**分流列 `dir_path`**：根页 `/`；频道 `directory/gov`、`directory/engine`。

## 2. 收录标准（能不能收）

### 2.1 必须全部满足（任一不满足即驳回）

| 项 | 核验方法 |
|---|---|
| ICP 备案可查 | beian.miit.gov.cn |
| 域名归属主体与站点名一致 | whois / 备案主体比对 |
| 无诈骗预警/黑名单记录 | 12321 / 12377 |
| HTTPS 可达且证书有效 | 浏览器访问 |
| 是**官网**而非商业代理/仿站 | 人工判断 |

### 2.2 定位判定（收进来放哪）

| 判定 | 去向 |
|---|---|
| 政协/民主党派核心入口 | 根页 + 对应频道 |
| 政务办事机构 | gov 频道 |
| 搜索引擎/工具类 | engine 频道 |
| 与垂类无关的通用站点 | 根页通用类目（LOCKED：垂类为主、通用为辅，**不得删除通用类目**） |

### 2.3 卡片 type 判定

| type | 适用 |
|---|---|
| `1`（4 行 3 列 logo 卡） | 有清晰方形 logo 的官网（**默认选择**） |
| `2`（5 行 2 列，横向 1.618:1 封面） | 有横向素材的站点 |
| `3`（5 行 2 列，纵向 1:1.618 封面） | 有纵向素材的站点 |

> 不确定用 `1`。三种 type **按 type 分组分行**，不同类型绝不同行（04-组件库规则 §3）。

## 3. 字段录入细则

### 3.1 卡片（`cards.unified.xlsx`，31 列英文 snake_case）

详细 schema 见 [05-开发规范](./05-开发规范.md) §3.2。此处只列**录入时的质量要求**：

| 字段 | 录入要求 |
|---|---|
| `row_seq` | 数字。排序先按 `card_layout`（1→2→3）分组，再按 `row_seq` 升序 |
| `dir_path` | `/` 或 `directory/<name>`，**必须准确**（决定生成到哪个页面） |
| `cat_name` | 分类名。**新增分类 = 改分类导航**（影响全站导航结构，需谨慎并报告用户） |
| `card_layout` | `1` / `2` / `3` |
| `card_title` | 站点**官方全称**，不简写、不加营销词 |
| `card_desc` | **强烈建议必填**（防薄内容）。一句话，客观描述，不含负面词 |
| `card_media` | WebP + 透明通道。语法见 05 §3.3。纯色/文字占位也可 |
| `card_tags` | 英文逗号分隔。分类名会自动成为第 1 个标签，此处**不必重复填分类名** |
| `link_N_name` / `link_N_url` | 组序即展示顺序；`url` 为空的组自动跳过。链接名称用"访问官网""网上办事"等**动作词 + 目标** |

### 3.2 页面元信息（`pages.unified.xlsx`）

| 字段 | 要求 |
|---|---|
| `title` | ≤ 30 字，含站点名与页面核心词 |
| `description` | 60–120 字，**每页唯一**，不得复制其他页 |
| `keywords` | 5–10 个，逗号分隔，与页面内容相关 |
| `channel_intro` | 频道导语，**300–500 字独特内容**（D1 目标），禁止模板化重复 |

> ⚠️ `canonical` 由 build 按 `dir_path` 自动生成，**不得手写**（CONVENTIONS §5.5 🔴-10）。

## 4. 文案规范

### 4.1 通用

- 客观陈述，不用夸张修辞、不用感叹号堆砌。
- 不使用负面词：代办 / 代开 / 加急 / 包过 / 贷款 / 下载器（D4）。
- 不使用"最权威""第一""官方指定"等可能构成不当宣传的表述。
- 涉及政务信息须**标注来源与核验日期**。

### 4.2 非官方声明（必带）

任何可能被误认为官方的位置，须有"独立第三方"表述。**不得**：暗示政府隶属、使用政协官方标识、自称官方。

### 4.3 公文审稿闸门

内容类文案发布前必过（CONVENTIONS §5.3.2 第 8 步）：

- [ ] **措辞**：无夸大、无误导、无负面词
- [ ] **角标**：引用处有来源标注
- [ ] **来源留痕**：可追溯到官方出处
- [ ] **非官方声明**：位置得当
- [ ] 涉法律效力 → **转法律专家**，AI 不定稿（12-合规 §0）

## 5. 更新与下线规则

### 5.1 卡片更新

| 情形 | 动作 |
|---|---|
| 官网改版/换域名 | 核验新域名 → 更新 `link_N_url` → 台账登记 `verify_date` |
| 站点关闭 | **先标记** `status=失效` 观察 1 个周期 → 确认后下线（不立即删） |
| 信息变动（电话/地址） | 立即更新 + 台账登记 |
| 季度外链核验不通过 | 按 12-合规 §3 处置 |

### 5.2 下线（删除卡片）

1. 确认该站点确已不可达或违规（**存疑即下架，不等核实完**）。
2. 先从 xlsx 标记待下线（不直接删行），跑 build 观察。
3. 确认无异议后删除行，重跑 build。
4. 更新 changelog + 台账 + sitemap（若该卡片有独立页面）。
5. 记时间日志。

> 删除前必须有备份锚点（02-迭代规则 §3.1）。

每次收录/改动后更新 `pages/changelog/index.html`：

```markdown

- 新增：<站点名>（分类 / 频道）
- 更新：<站点名> —— <改了什么>
- 修复：<描述>
```

> 「本周上新」（C3 建成后）复用 changelog 数据源，不重复维护。

## 8. 内容红线（复述，一票否决）

- ❌ AI 自动生成/自动发布政务或民生资讯
- ❌ 冒充官方（暗示隶属、用官方标识、自称官方）
- ❌ 收录未核验链接
- ❌ 优化负面词（代办/代开/加急/包过/贷款/下载器）
- ❌ 未授权转载正文
- ❌ 删除首页通用类目 / 剥离流量词（LOCKED）
