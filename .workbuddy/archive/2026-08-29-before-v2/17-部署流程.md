## 1. 部署模型

```
本地改动 → 构建 → 校验 → 闸门检查 → 【用户 git commit + push】→ GitHub Pages 自动发布 → 线上验证
```

- 托管：GitHub Pages，分支发布（`main` / `/ (root)`），自动 HTTPS。
- 产物**进仓库**（ADR-012），因此 push 即发布。
- 无 CI、无预览环境；**本地验证就是上线前的最后一道关**。

## 2. 标准部署步骤

### 步骤 1 · 备份锚点

```bash
mkdir -p .workbuddy/backups/YYYY-MM-DD-<用途>/
# 复制将要改动的文件，并写 MANIFEST.txt
```

`MANIFEST.txt` 必含：功能 / 时间 / 来源清单 / 回档说明 / 对应迭代卡。
**缺 MANIFEST 的备份视为无效。**

### 步骤 2 · 构建

```bash
python assets/.build/build.py
echo "exit=$?"     # 必须为 0
```

- 涉及 build 模板/数据源的改动**必须重跑**，且生成范围是**根页 + 全部频道页**（不接受只生成一部分）。
- 不得手改生成产物（改数据源重跑）。

### 步骤 3 · 自动化校验

```bash
# 3.1 断链扫描（相对资源路径）
#     见 08-测试流程 §3.1 脚本片段 → 必须零输出

# 3.2 死链检查（当前仅覆盖根页数据）
python assets/.build/check_links.py

# 3.3 head 覆盖与外链属性扫描
#     见 08-测试流程 §3 第 2/3/5/6/7 项
```

> ⚠️ 标准校验脚本 `verify_site.py` **不存在**（05-开发规范 §4.3 / M-1）。在补齐前，以上 3 项为替代方案，须手工执行并留记录。

### 步骤 4 · 本地预览验证

```bash
# 起本地静态服务（任选其一）
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

逐项过 [08-测试流程](./08-测试流程.md) §6（功能 / 视觉 / 无障碍 / 禁用 JS 降级）。
**`python -m http.server` 不提供 gzip**，故本地只验证功能，**不验证传输体积**（体积用 §2 的 gzip 脚本度量）。

### 步骤 5 · 闸门检查

- [ ] [10-质量标准](./10-质量标准.md) §3 判定：🔴 红线项全过
- [ ] SEO：新增页已手动补 `sitemap.xml`
- [ ] 页脚导航、changelog、README（结构变化时）已同步
- [ ] 内容文案已过公文审稿闸门
- [ ] 合规清单已勾（12-合规 §2）

### 步骤 6 · 写迭代卡与时间日志

- `.workbuddy/memory/YYYY-MM-DD.md`，须**注明 agent 名称**（未注明=无效）。
- 模板见 [02-迭代规则](./02-迭代规则.md) §5。

### 步骤 7 · 收口

- 清理临时脚本（`_` 前缀）、超期备份。
- **提醒**用户未提交文件清单 → **由用户本地 git 提交**（Agent 不执行）。

### 步骤 8 · 发布（👤 用户执行）

```bash
git add .
git commit -m "<说明>"
git push origin main
```

### 步骤 9 · 线上验证（发布后 10 分钟内）

- [ ] 访问 `https://zhengxie.com.cn` 返回 200
- [ ] 首页样式正常（CSS 已加载 —— **本项目曾在此翻车**）
- [ ] 改动的目标页面内容已更新
- [ ] 浏览器控制台无 4xx/5xx
- [ ] 抽查 1–2 个频道页
- [ ] 暗色模式正常

## 3. 回滚

| 层级 | 方法 | 适用 |
|---|---|---|
| **本地未推送** | 从 `.workbuddy/backups/YYYY-MM-DD-<用途>/` 覆盖回来 | 改动尚未 push |
| **已推送，需回滚** | 👤 用户执行 `git revert <commit>` 或 `git reset --hard <commit>` 后 push | 线上出问题 |
| **单文件误改** | 从备份目录取单文件覆盖，重跑 build，走部署步骤 | 局部错误 |

**回滚纪律**：

1. 回滚前先确认备份锚点存在且含 MANIFEST。
2. 回滚后**必须重跑校验 + 线上验证**，不能回滚完就不管。
3. 回滚事件记入当日时间日志，并复盘根因。

## 4. 故障处置

| 现象 | 排查顺序 | 处置 |
|---|---|---|
| **站点 404 / 打不开** | ① GitHub Pages 设置页（Custom domain / Enforce HTTPS）② CNAME 文件 ③ DNS 解析 | 按 15-运营SOP §4 |
| **样式丢失（页面裸奔）** | ① F12 → Network 看 CSS 是否 404 ② 检查相对路径 `../` 深度 | 修路径 → 重跑 build → 重新部署 |
| **改动没生效** | ① 是否 push 成功 ② GitHub Pages 构建状态 ③ 浏览器缓存（强刷） | 等 Pages 构建完成（通常 < 2 min） |
| **HTTPS 证书异常** | Pages 设置页 Enforce HTTPS / 证书签发状态 | 等待自动签发或重签 |
| **内容错乱** | 是否手改了生成产物 | 改数据源重跑 build |

## 5. 部署禁忌

- ❌ Agent 执行任何 git 命令（Git 全停令，凌驾一切）。
- ❌ 只生成部分频道页就部署。
- ❌ 手改 build 生成的 HTML。
- ❌ 跳过备份锚点做任何删除/替换。
- ❌ 跳过校验直接 push。
- ❌ 未补 `sitemap.xml` 就上线新页面。
- ❌ 在 CI/预览环境不存在的情况下，"先上线再修"。
