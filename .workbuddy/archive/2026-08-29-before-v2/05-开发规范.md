## 1. 目录分层（实操视角）

```
zhengxie.com.cn/
├── index.html 404.html robots.txt sitemap.xml CNAME ads.txt favicon.ico   # L1 发布层
├── pages/<name>/index.html                    # L3 手写子页（英文小写 URL）
├── directory/<name>/index.html                # L3 频道页（build 生成）
├── assets/
│   ├── css/style.css                          # 全站唯一样式（设计 token 真值源）
│   ├── js/main.js                             # 全站唯一交互脚本
│   ├── images/                                # logo.svg + *.webp（WebP 且保留透明通道）
│   ├── json/manifest.json                     # PWA manifest
│   ├── data/                                  # all_cppcc.csv / pca.json（静态参考数据）
│   ├── xlsx/                                  # ★ 数据真值源（见 §3）
│   └── .build/                                # 构建脚本 + reports/
└── .workbuddy/                                # L4 治理层（随仓库同步，不进站点发布）
```

**铁律复述（CONVENTIONS §4.1）**：

1. 备份永不进发布层与资源层（`*.bak` 一律进 `.workbuddy/backups/`）。
2. 临时脚本用后即删（`_` 前缀只表示本次会话临时，不表示可长期滞留）。
3. 真值源唯一（同一数据只允许一个权威位置）。

## 3. 数据 Schema（真实，2026-08-29 核验）

### 3.1 两张统一真值源

| 文件 | 内容 | 分流列 |
|---|---|---|
| `assets/xlsx/cards.unified.xlsx` | 卡片数据 | `dir_path`（根页 `/`；频道 `directory/gov`、`directory/engine`） |
| `assets/xlsx/pages.unified.xlsx` | 页面元信息：`title` / `description` / `keywords` / `channel_intro` | 同上 `dir_path` |

> 输出位置、canonical、资源前缀**全部由 `dir_path` 推导**，不得手写。

### 3.2 `cards.unified.xlsx` 列定义（31 列）

```
row_seq | dir_path | cat_id | cat_name | card_layout | card_title | card_desc |
card_media | card_tags | card_id | card_order |
link_1_name | link_1_url | … | link_10_name | link_10_url
```

| 列 | 必填 | 说明 |
|---|---|---|
| `row_seq` | ✅ | 站序（数字）。排序：**先按 `card_layout`（1→2→3）分组，再按站序从小到大**；不同 layout 强制分行 |
| `dir_path` | ✅ | `/` 或 `directory/<name>` |
| `cat_id` / `cat_name` | ✅ | 分类 ID / 分类名。分类按钮按出现顺序生成；`cat_name` 自动作为标签行第 1 个标签 |
| `card_layout` | ✅ | 卡片结构：`1`=4 行 3 列 logo 卡，`2`=5 行 2 列横向封面卡（1.618:1），`3`=5 行 2 列纵向封面卡（1:1.618） |
| `card_title` | ✅ | 站点名 |
| `card_desc` | 否 | 一句话描述（**建议必填**：D1 内容化与去重都依赖它） |
| `card_media` | 否 | 见 §3.3 |
| `card_tags` | 否 | 英文逗号 `,` 分隔 |
| `card_id` | 否 | 当前不参与渲染，留待徽章接入 |
| `card_order` | 否 | 当前不参与渲染，可作手动排序键 |
| `link_N_name` / `link_N_url` | 否 | 共 10 组（20 列）。**组序即展示顺序，`url` 为空的组自动跳过** |

### 3.3 `card_media` 语法

| 写法 | 效果 |
|---|---|
| `URL` | 仅图片（红底容器，失败移除露红底） |
| `URL,颜色` | 图片容器内铺该背景色（给矢量/透明 logo 衬底） |
| `颜色值` | 纯色块占位 |
| `字符,颜色` | 文字占位 + 底色 |

- 颜色支持 `#rgb` / `rgb()` / `rgba()` / `hsl()` / `transparent` / 颜色名。
- 图片**必须 WebP 且保留透明通道（RGBA）**，否则透明 logo 被填黑。
- 分隔符一律英文半角逗号 `,` 与分号 `;`。

### 3.4 表头纪律

- **仅接受英文表头**。含中文旧键（`站序`/`分类`/`link1_name`…）→ build **直接报错拒绝**，不透传兼容。
- 改列名 = 只改 `build_homeplus.py` 的 `HEADER_NORMALIZE` 常量一处，其余逻辑不动。
- 已移除列（2026-08-27）：链接富化列 `link_N_id/desc/media/enabled`、来源列 `source_*` —— 不得再加回。

## 4. 构建链路（真实）

### 4.1 统一入口

```bash
python assets/.build/build.py
```

执行顺序（任一步失败即中断并保留非零退出码）：

1. `build_homeplus.py` —— 生成根页 `index.html` + 各 `directory/<name>/index.html`
2. `collect_meta.py` —— 采集全站 `index.html` 的 title/keywords/description，导出 SEO 报告 xlsx

### 4.2 单跑与工具

| 脚本 | 用途 | 备注 |
|---|---|---|
| `build_homeplus.py` | 只重新生成导航产品页（跳过 SEO 报告） | 生成器核心 |
| `collect_meta.py` | 只出 SEO meta 报告 | 产出 `reports/` |
| `check_links.py` | 外链死链检查 | **当前仅扫根页数据**，覆盖频道页待办（CONVENTIONS §5.3.5） |
| `sync_star_sprite.py` | 收藏星形 SVG sprite 同步 | 已补记（M-8，2026-08-29） |
| `link-policy.json` | 外链属性策略（域名优先级，ADR-008） | 改外链规则改这里 |

### 4.3 ⚠️ 已知缺口：`verify_site.py` 不存在

CONVENTIONS §5.1（迭代四阶段 2.4）、§5.3.2（部署闸门第 4 步）、§5.5（必做第 3 条）三处均要求「跑标准校验脚本 `assets/.build/verify_site.py`」，但**该文件在全仓不存在**。

**后果**：迭代流程的强制校验步骤目前**挂空挡**——每次部署的"跑校验"实际无法执行，质量保障退化为人工清单。

**处置（待用户拍板，见 §8 漂移清单 M-1）**：

- 方案甲（推荐）：新建 `verify_site.py`，覆盖 08-测试流程 §3 的自动化项（相对路径断链、head 标签齐备、外链属性、JSON-LD、schema 合法性）。
- 方案乙：把 CONVENTIONS 三处引用改为实际存在的脚本组合（`build.py` + `check_links.py` + 手工清单）。

## 5. 编码规范

### 5.1 HTML

| 规则 | 说明 |
|---|---|
| 静态优先 | 所有卡片/链接/分类按钮**静态渲染在 HTML**，禁用 JS 时内容完整可读可点（SEO 生命线） |
| 资源路径 | 根页 `assets/...`；子页按**实际目录深度**相对回引（`../` / `../../`）——**不可照抄**，见 ADR-005 |
| 内链 | 绝对 URL（`https://zhengxie.com.cn/...`）+ `target="_self"` |
| `<head>` 齐备 | `title` / `description` / `keywords` / `canonical` / OG 全套 / `twitter:card` / `theme-color` / JSON-LD |
| 标题层级 | `h1`=站点名（每页唯一）；`h2`=分类/区块；`h3`=卡片名 |
| 图片 | 必带 `alt`；`loading="lazy" decoding="async"`；外链图片 `referrerpolicy="no-referrer"` |
| referrer | **不设**全局 `<meta name="referrer">`（ADR-008） |
| 内联事件 | **新代码不得新增** `on*` 内联属性（现有 `onerror="this.remove()"` 为历史遗留，阻碍 CSP） |

### 5.2 CSS

- 颜色一律用 03-设计规范 §2 的 token 变量，**禁止硬编码色值**（例外：token 定义处本身）。
- 新增 token → 先改 03-设计规范，再改 CSS。
- 媒体查询：移动优先 or 桌面降级二选一，**同一文件内不得混用**。
- 选择器深度 ≤ 3 层。

### 5.3 JavaScript（`assets/js/main.js`）

- 无框架、无构建；ES6+ 浏览器原生语法。
- **事件委托优先**，避免给每个卡片绑监听（337+ 卡片）。
- 禁止 `eval`、禁止 `innerHTML` 拼接用户输入（当前实测均为 0，保持）。
- 状态持久化走 `localStorage`（ADR-007），键名前缀 `zx_`。
- 主题 FOUC 防护：读取 `localStorage('zx_theme')` 的内联脚本必须在**首屏渲染前**执行。

### 5.4 Python（构建脚本）

- 文件头 `# -*- coding: utf-8 -*-` + docstring 说明用途/用法/输出。
- 路径一律基于 `os.path.dirname(os.path.abspath(__file__))` 定位仓库根，**不依赖 cwd**。
- 失败即非零退出码，不静默吞异常。
- 脚本内既有中文注释保持原样，不改写。

## 7. 临时文件与清理

| 类型 | 位置 | 处置 |
|---|---|---|
| 临时校验脚本 | 仓库根或任意处，`_` 前缀 | **用后即删**，不得留仓库根或同步区 |
| 备份 | `.workbuddy/backups/YYYY-MM-DD-<用途>/` | 保留最近 3 个，超出 MANIFEST 标 `superseded` |
| 待删物 | `.workbuddy/trash/` | 30 天后确认删除 |
| 草稿 | `.workbuddy/staging/` | 批准即移权威位或删除，每轮收尾清理 |
| Python 缓存 | `__pycache__/` `*.pyc` | 不得进 Git（`.gitignore` 已涵盖） |
