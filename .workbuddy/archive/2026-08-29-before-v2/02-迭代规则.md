> 前置铁律（凌驾本文）：CONVENTIONS 的 Git 全停令、文件改动铁律、backup 铁律、公开暴露铁律。

## 1. 四阶段总表（每次改动必走）

| 阶段 | 必做动作 | 产出物 | 跳过条件 |
|---|---|---|---|
| **1 立项 Plan** | 1.1 一句话目标<br>1.2 改动清单（文件 + 行号/区段 + 改前→改后）<br>1.3 验收标准（可观测通过条件）<br>1.4 **首次改/删 → 等用户确认** | 迭代卡 Plan 段 | 无 |
| **2 执行 Build** | 2.1 全量备份 + MANIFEST<br>2.2 按清单改（不扩大范围）<br>2.3 涉及 build 模板/数据源 → 重跑生成<br>2.4 跑标准校验 | 备份锚点、校验输出 | 无 |
| **3 同步 Sync** | 3.1 引出新规则 → 落权威源<br>3.2 写当日时间日志（迭代卡）<br>3.3 确认新规则在同步区 | 时间日志 | 无 |
| **4 收口 Close** | 4.1 补完迭代卡（目标/范围/清单/验收/回档锚点）<br>4.2 清理临时脚本/超期备份<br>4.3 **提醒**未提交文件（只提醒不询问，不执行 git） | 完整迭代卡 | 无 |

> **轻量版**（单文件文案微调）：Plan 清单 + Build 备份 + Close 记录，可合并进一张迭代卡，不必单独开卡。
> **禁止**：跳过 Build 备份做任何删除/替换；跳过 Sync 日志做任何文件增删改（backup 铁律）。

## 2. 立项（Plan）细则

### 2.1 改动清单格式（必须精确到区段）

```
文件：<相对路径>
区段：<行号 或 唯一可识别锚点，如 class="card card--t1" 第 3 处>
改前：<原文摘录>
改后：<新内容>
理由：<一句话>
```

- 无行号/锚点的清单 = 不合格，退回重写。
- 清单外的文件**不许动**（范围蠕变是本项目历史上多次事故的来源）。

### 2.2 验收标准写法

必须是**可观测**的通过条件，禁止"页面正常""功能可用"这类不可判定表述。

| ❌ 不合格 | ✅ 合格 |
|---|---|
| 页面显示正常 | 浏览器 Network 无 4xx/5xx；CSS 已加载（`.category-nav` 计算样式 `display:flex`） |
| 筛选能用 | 输入"政协"后结果计数显示 `当前显示 X / N 张卡片`，X < N 且 X > 0 |
| 性能变好 | 根页 HTML 体积 ≤ 200 KB（当前 345 KB） |

### 2.3 首次确认制

- **触发**：本会话 agent 首次改/删空间内任何文件（含对话内切换 agent 后重新计数）。
- **动作**：列出将要改动的文件清单 → 等用户明确同意 → 才执行。
- 已获授权后的同会话后续改动不再重复确认。

## 3. 执行（Build）细则

### 3.1 备份锚点

```
.workbuddy/backups/YYYY-MM-DD-<用途>/
  ├── MANIFEST.txt   # 功能 / 时间 / 来源清单 / 回档说明 / 对应迭代卡
  └── ...            # 备份内容
```

- **每个回档点必须带 MANIFEST**，缺 MANIFEST 的备份视为无效。
- 保留策略：**仅保留最近 3 个有效备份**，超出的清理前 MANIFEST 标 `superseded`。
- 备份**永不进发布层与资源层**（CONVENTIONS §4.1 铁律 1）。

### 3.2 重跑构建

触发条件（满足任一即重跑，不可只改生成产物）：

- 改了 `assets/.build/build_homeplus.py` 模板逻辑
- 改了 `assets/xlsx/cards.unified.xlsx` 数据
- 改了 `assets/.build/link-policy.json` 外链策略

重跑范围：**根页 + 全部频道页**（不接受只生成一部分）。

### 3.3 标准校验

改动涉及页面/数据/链接时，跑：

```
assets/.build/verify_site.py        # 格式 / 死链 / 字段完整性
```

配合本文 §6 的自查项。

## 4. 同步（Sync）细则

1. **引出新规则 → 落权威源**（选其一，禁止新建裸 md）：
   - 站点结构/手工写站 → `README.md`（注意公开暴露铁律：不得提及 `.workbuddy/`）
   - 治理约定/运营节奏 → `.workbuddy/docs/CONVENTIONS.md`
   - 工程标准/基线 → `.workbuddy/docs/NN-*.md` 本编号体系（先登记进 00-索引）
   - 可复用操作步骤 → `.workbuddy/skills/*/SKILL.md`
2. **写当日时间日志**：`.workbuddy/memory/YYYY-MM-DD.md`，格式见 §5 迭代卡模板。须**注明 agent 名称**（未注明=无效，backup 铁律）。
3. 确认新增规则落在**随仓库同步**的位置（跨设备可读，ADR-011）。

## 5. 迭代卡模板（直接复制使用）

```markdown
## 迭代卡 · YYYY-MM-DD · <一句话目标>

**Agent**：<agent 名称>
**关联**：PRD §<需求编号> / ADR-<编号> / 圆桌 Todo <编号>

### Plan
- 目标：<一句话>
- 范围：<涉及页面/模块>
- 改动清单：
  - 文件 A（行 12–20）：改前 `xxx` → 改后 `yyy`，理由 `zzz`
  - 文件 B（`.card--t1` 第 3 处）：…
- 验收标准：
  1. <可观测条件 1>
  2. <可观测条件 2>
- 用户确认：<已确认 / 待确认>

### Build
- 回档锚点：`.workbuddy/backups/YYYY-MM-DD-<用途>/`（含 MANIFEST）
- 重跑构建：<是/否>｜生成日志：<摘要>
- 校验输出：`verify_site.py` → <通过 / 失败项>

### Sync
- 新规则落点：<权威源路径 + 小节>
- 时间日志：`.workbuddy/memory/YYYY-MM-DD.md` ✅

### Close
- 验收结果：<逐条对照 Plan 验收标准>
- 清理：<删除的临时脚本 / 超期备份>
- 未提交文件提醒：<列出，由用户本地处理；agent 不执行 git>
```

## 6. 分场景自查（Build 后逐项勾）

| 场景 | 自查项 |
|---|---|
| **改了页面结构** | 骨架判定正确（S1–S6）｜相对资源路径零 404｜JSON-LD 类型符合映射表｜面包屑层级真实 |
| **改了样式** | 亮/暗两色都看过｜token 未越界（03-设计规范 §2）｜未删字体三件套｜焦点环可见 |
| **改了数据** | 英文表头｜`scope` 列正确｜重跑 build 全量｜字段完整（16-内容更新规范） |
| **改了链接** | `target`/`rel` 符合域名优先级（ADR-008）｜`_blank` 必带 `noopener`｜无裸 IP 外链 |
| **新增页面** | 手动补 `sitemap.xml`｜页脚导航已挂｜OG/Twitter 全套｜canonical 正确 |
| **引入第三方脚本** | 见 11-安全审计 §5 引入前检查（当前无 CSP，新增需更审慎） |

## 7. 范围蠕变拦截

执行中若发现"顺手该改"的额外问题：

1. **不改**，记进迭代卡「发现但本次未做」。
2. 若属 P0 缺陷（阻断/安全风险）→ 停下报告用户，等指令。
3. 清单外的改动**一律视为越界**，即使改动本身正确。
