## ADR-001 纯静态站 + GitHub Pages + 自定义域名

- **状态**：✅ 生效 ｜ **确立**：建站期 ｜ **风险等级**：🔴 高（待复议）

**背景**：导航站内容更新频率低、无需用户交互后端；预算为零；要求 HTTPS 与自定义域名。

**决策**：全站静态 HTML，无服务端渲染、无数据库。托管 GitHub Pages，域名 `zhengxie.com.cn` 经 CNAME 绑定。

**理由**：零成本、零运维、自动 HTTPS、与 Git 仓库一体（天然可回档）；静态渲染对 SEO 最友好（禁用 JS 仍可读可点）。

**后果**：
- ➕ 部署即 push；任意历史版本可 git 回档；无服务端攻击面。
- ➖ **境外托管导致百度收录降权**（SEO Backlog P0，生命线级）；国内访问不稳定。
- ➖ 无后端 → 收藏不跨设备、无用户反馈通道、无服务端日志。

**复盘触发**：备案完成（A5/F1）或百度索引量连续 2 个月不增长 → 复议迁国内托管。迁移时必须 301 + 更新 sitemap（见 [13-SEO审计](./13-SEO审计.md) §6）。

## ADR-002 数据源 = 单一 xlsx 真值源 + Python build 生成页面

- **状态**：✅ 生效 ｜ **确立**：2026-08-28（三份 scope 表合并为统一表）

**背景**：早期渠道页各自携带独立卡片 xlsx，出现多真值源漂移；手写 HTML 维护 300+ 卡片不可行。

**决策**：`assets/xlsx/cards.unified.xlsx` 为**唯一真值源**（含 `dir_path` 列区分 '/' / 'directory/gov' / 'directory/engine'）；`assets/.build/build_homeplus.py` 读取后生成根页与频道页。**仅接受英文表头**，含中文旧键直接报错拒绝。

**理由**：卡片量级（337+67+59）决定必须数据驱动；单一真值源消除"改了这边忘了那边"；英文表头杜绝编码/命名歧义。

**后果**：
- ➕ 新增卡片 = 加一行 + 重跑 build；schema 变更有明确落点。
- ➖ 引入构建步骤，README 的"手工写站"叙事与真实链路分离（属既定的公开层/内部层分离，见 CONVENTIONS §1.11）。
- ➖ 生成的 HTML 体积偏大（根页 345 KB），见 ADR-012 与 14-性能基线。

**复盘触发**：卡片总量 > 800 或 build 耗时 > 30s，或需要多人并发编辑数据 → 复议换数据源形态。

## ADR-003 页面按骨架分类（S1–S6）+ JSON-LD 类型映射

- **状态**：✅ 生效 ｜ **确立**：README §三 / CONVENTIONS §3.1

**背景**：新增页面时"照哪个页抄"没有判据，容易出现结构漂移。

**决策**：按**布局范式 × 资源引用 × SEO 角色**划分六骨架（S1 导航产品页 / S2 全景中枢 / S3 说明页 / S4 合规页 / S5 功能入口 / S6 内容页），新增页先判归属再套模板；无法覆盖且对长远有利才新增 S7+。JSON-LD `@type` 按 CONVENTIONS §3.1 映射表取，所有页 `isPartOf` 统一回链站点根 `WebSite`。

**理由**：按骨架而非主题分类，才能复用模板与卡片组件；`isPartOf` 统一回根避免层级嵌套混乱。

**后果**：
- ➕ 新增页面成本可预测，结构一致性由模板保证。
- ➖ 骨架判定失误会传导到 SEO 类型与面包屑，需在 [08-测试流程](./08-测试流程.md) 中列为必检项。

**实测覆盖（2026-08-29）**：13/14 页有 JSON-LD（404 无，符合预期）；BreadcrumbList 已覆盖 12 页；`Organization` 仅 about 页有 —— **B14 待办：按映射表补齐**。

**复盘触发**：新增第 7 类骨架，或某骨架页面数 > 20（说明该抽象仍不够细）。

## ADR-004 站点层级 = 建筑隐喻（overview 与 directory 是兄弟，非父子）

- **状态**：✅ 生效 ｜ **确立**：CONVENTIONS §3.2

**背景**：面包屑曾出现"首页 › 网站全景 › 频道导航 › 频道名"，虚构了层级。

**决策**：根页=大楼正门；`pages/overview/`=入门后的**总指示牌**（全站分发中枢）；`directory/`=**楼层指示牌**（频道集合）；`directory/<name>/`=房间（具体频道）。**overview 与 directory 平列，都直接从根页到达。**

**理由**：面包屑每级必须真实存在、可点击、与可见导航一致；虚构层级会被搜索引擎判不实甚至忽略。

**后果**：
- ➕ 面包屑与信息架构自洽，符合 SEO 规范。
- ➖ 想在 overview 内引导到频道，只能加**可见链接/卡片**，不能靠面包屑伪造 —— 这是特性不是缺陷。

**复盘触发**：站点新增"全站分发中枢"级别的板块（如博客、榜单）→ 按 CONVENTIONS §3.2.3 判定归属。

## ADR-005 assets 单一真源，子页用相对路径回引

- **状态**：✅ 生效 ｜ **确立**：README §三

**背景**：早期子页自包含并复制 assets，导致多份 CSS/JS 漂移。

**决策**：`assets/` 是唯一真源。根页用 `assets/...`，子页（`pages/*/`、`directory/*/`）用相对路径回引（`../../assets/...` 或 `../assets/...`，**按实际目录深度取，不可照抄**）。内链一律绝对 URL 且 `target="_self"`。

**理由**：单一真源 = 改一处生效全站；相对路径保证本地与线上、子目录与根域都能解析。

**后果**：
- ➕ 无资源重复，缓存命中率高。
- ➖ **路径深度写错是本项目已发生的真实缺陷**：`directory/index.html` 位于二级目录，却写成 `../../assets/...`（应为 `../assets/...`），导致 CSS 与 Logo 全 404。
- ➖ 新增目录层级时必须重算相对深度。

**强制动作**：任何新页面/新目录 → 必须跑 [08-测试流程](./08-测试流程.md) 的「相对路径断链扫描」，零 404 才算过。

**复盘触发**：目录结构层级调整，或断链扫描再次命中同类问题。

## ADR-006 无前端框架，原生 CSS + 原生 JS

- **状态**：✅ 生效

**背景**：站点交互有限（筛选/搜索/收藏/滑道/主题切换），引入框架的收益远小于成本。

**决策**：不使用 React/Vue/Tailwind 等。CSS 变量管理设计 token，原生 JS 处理交互，无构建打包步骤（build 只生成 HTML，不转换前端资源）。

**理由**：零依赖 = 零供应链风险、零版本升级负担；静态站追求首屏快；交互复杂度不需要框架。

**后果**：
- ➕ 首屏无框架运行时开销；无 npm 生态安全面。
- ➖ 组件复用靠 HTML 模板复制，无类型检查 → 必须靠 [04-组件库规则](./04-组件库规则.md) 契约 + 测试兜底。
- ➖ CSS/JS 未压缩（40.9 KB / 49.9 KB），见 14-性能基线预算。

**复盘触发**：交互复杂度显著上升（如需要状态管理），或团队规模 > 1 人协作前端。

## ADR-007 收藏与主题存 localStorage，不做后端同步

- **状态**：✅ 生效

**背景**：ADR-001 决定无后端，但收藏与暗色主题需要持久化。

**决策**：收藏与主题偏好存浏览器 `localStorage`（键 `zx_theme` 等），**不跨设备/浏览器同步**；主题**仅跟随用户手动切换**，不跟随系统偏好；加载前内联脚本读取以防 FOUC。

**理由**：静态站无后端的必然结果；不跟随系统是为保证用户显式选择被尊重、避免系统切换导致观感突变。

**后果**：
- ➕ 零成本、零隐私外传（数据不出浏览器）。
- ➖ 换设备/清站点数据即丢失 → **必须在 UI 与文档明示此限制**（README FAQ Q6 已写）。
- ➖ 导出/导入（C2）成为弥补手段，P2 待做。

**复盘触发**：C2 收藏导出上线后重估；或用户强烈反馈多设备同步需求。

## ADR-008 外链属性按域名优先级自动匹配，不设全局 no-referrer

- **状态**：✅ 生效

**背景**：外链既要防权重流失与安全风险，又不能让统计后台收不到来源。

**决策**：按 `同域 > 同族 > 营销 > 评论 > 暴露 > 默认` 六级优先级匹配（规则表见 README §七）。**禁止**设全局 `<meta name="referrer" content="no-referrer">`；仅卡片图片单独 `referrerpolicy="no-referrer"` 防盗链。

**理由**：全局 no-referrer 会让百度统计收不到来源；分级策略才能在"传权重/防作弊/保统计"之间取平衡。

**后果**：
- ➕ 政务 `.gov.cn` 走"暴露"档 = dofollow，对 SEO 有利；营销/UGC 走 nofollow 防作弊。
- ➖ 规则复杂，新增外链域名需判档 → 已由 `assets/.build/link-policy.json` 集中管理。

**实测（2026-08-29）**：`target="_blank"` 207 处，**缺 `noopener` 0 处**（无 tabnabbing 风险）；`nofollow` 92 处，其余为政务/同域 dofollow，与策略一致。

**复盘触发**：引入新外链类型（如付费合作）或 link-policy 命中不了的新域名族。

## ADR-009 国际频道采用"轻量法"（不建独立门户）

- **状态**：✅ 生效 ｜ **确立**：2026-08-24

**背景**：国际频道（`world-*`）数量少，是否值得独立楼层？

**决策**：不新建独立"外国频道中心"门户；`world-*` 置于 `directory/world-*/`，作为频道导航内的"国际"分区；面包屑统一 `首页 › 频道导航 › 国际XX导航`。

**理由**：当前数量撑不起独立楼层；改动成本（301 + sitemap + 内链全改）远超收益。

**后果**：
- ➕ 架构简单，无需重定向。
- ➖ 未来国际频道壮大后需迁移，届时必须 301 + 更新 sitemap（"完整法"预案见 CONVENTIONS §3.2.3）。

**复盘触发**：国际频道数 > 5 个，或国际流量占比 > 15%。

## ADR-010 统计与广告：百度统计 + GA4 + AdSense 三者并存

- **状态**：⚠️ **生效但待复议**（D-4 未拍板）

**背景**：国内主战场需百度统计；GA4/AdSense 提供补充数据与变现。

**决策（现状）**：三套并存。百度统计（3 处）、GTM/GA4（11 处）、AdSense（6 处，发布商 ID 已写入 `ads.txt`）。

**待决问题**：GA4 与 AdSense 域名在国内被 GFW 屏蔽 → 拖慢首屏（第三方脚本阻塞）、数据大量缺失。SEO Backlog P0 建议**删除 GA4/AdSense，仅留百度统计**。

**后果（现状）**：
- ➖ 首屏额外 3 个第三方域；阻塞渲染的脚本拖慢 LCP（见 14-性能基线）。
- ➖ 隐私政策需同时披露三方的 cookie/追踪行为（见 12-合规检查清单）。

**复盘触发**：**D-4 拍板即触发**。拍板后本 ADR 改为终态并同步 11/12/14/18 四份文档。

## ADR-011 治理层（`.workbuddy/`）随仓库同步

- **状态**：✅ 生效

**背景**：跨设备工作时，AI 必须遵守的项目规范若只存在本机，换设备即失效。

**决策**：治理文档、记忆、技能、备份锚点全部置于 `.workbuddy/` 并**随 Git 仓库同步**（仓库 public，内容公开已由用户接受）。禁止把"AI 必须遵循的规范"唯一出处放在非同步位置。

**理由**：权威源唯一 + 跨设备可读 = 换机器不丢约束。

**后果**：
- ➕ 换设备 5 分钟恢复全部上下文。
- ➖ 仓库 public → 治理内容对外可见（已明示接受）；**页面层仍严禁暴露 `.workbuddy/` 存在**（CONVENTIONS §1.11）。

**复盘触发**：仓库改为 private，或治理层体积影响克隆速度。

## ADR-012 构建产物直接进仓库（方案甲）

- **状态**：✅ 生效 ｜ **确立**：CONVENTIONS §5.2

**背景**：build 生成的 HTML 是否提交？

**决策**：**提交**。生成的页面属强制同步文件，随仓库一起走。

**理由**：GitHub Pages 从分支直接发布，产物不进仓库则站点不更新；产物在仓库也便于 diff 与回档。

**后果**：
- ➕ 部署 = push，无 CI 复杂度。
- ➖ 仓库体积随页面增长（当前 14 页 HTML 合计 664 KB，根页单页 345 KB）；需靠 14-性能基线的体积预算约束。

**复盘触发**：仓库体积 > 50 MB，或引入 CI 后改为构建时生成。

## ADR-013 文档体系 = `.workbuddy/docs/` 编号体系（00–19）

- **状态**：✅ 生效 ｜ **确立**：2026-08-29（本轮重建）

**背景**：规范散在 README / CONVENTIONS / SKILL 三处，缺产品定义、设计 token、组件契约、测试与质量标准、安全/性能/合规基线、部署与监控闭环。

**决策**：在 `.workbuddy/docs/` 建 `NN-<主题>.md` 编号体系（20 份），由 `00-索引.md` 统一登记，并纳入权威源清单。体系**不复制** CONVENTIONS 治理铁律、README 手工教程、SKILL 操作步骤，只写指针。

**理由**：补齐"必须满足什么"的标准层，使换人接手有据可依；编号化便于引用与检索。

**后果**：
- ➕ 19 类工程约束有了唯一落点；新 md 有登记出口，不再裸放。
- ➖ 多一层文档需维护 → 每季度一致性抽查（见 15-运营 SOP）。

**复盘触发**：季度抽查发现体系与站点漂移 > 5 处，或编号扩容到 30+。
